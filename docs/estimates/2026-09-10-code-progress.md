## Оценка результата

Проверенный игровой конвейер продвинулся от записи результата до полного
возврата игрового вызова, последовательных вызовов с сохранением состояния,
паузы и активного ввода. Приложение пока использует старую тренировочную
реализацию. Законченный матч с уроном и результатом раунда ещё не подтверждён.

Существенная новая зависимость: настоящая точка входа EXE загружает комплектную
`lib.dll` до CRT startup. Она меняет62 байта в13 местах EXE. Предшествующие
цепочки исполнялись без этих изменений и остаются контролями этого режима.
Их нельзя выдавать за сравнение полного приложения из дистрибутива.
Это расширение известного объёма работ, а не повод переписывать старые эталоны.

4. Расширить проверку взаимодействий до всех персонажей, AI, техник и режимов,

## Исправления измерителя и срок

Первый запуск измерителя завершился делением на ноль: за последнее окно
6,60 часа выбранные диапазоны EXE не выросли. Теперь для неположительной
скорости прогноз имеет JSON-значение `null`; это отсутствие конечной
экстраполяции, не нулевой остаток и не утверждение об остановке работы.

Дополнительно старый парсер пропускал24 реальные аннотации вроде
`Whole421cdc..422218`, `EXE43d157..43d1ef` и `and41ae60..41b12d`.
Новый допускает буквенный префикс с хотя бы одной не-шестнадцатеричной буквой,
сохраняя запрет на извлечение диапазона из более длинного hex-значения.
Источники доказательств и границы `.text` не расширены.

По прежним правилам текущий срез даёт117349 байт/41,41%. Исправление парсера
добавляет20926 уже существующих байт до138275/48,79%. Это исправление учёта,
не новая работа сегодняшнего агента. Вечерняя база пересчитана тем же парсером
до136041/48,00%; только разность2234 отражает прирост этой метрики за ночь.
Сохранён [отчёт до исправления парсера](2026-09-10-code-progress-before-parser-fix.json).

Механическая экстраполяция по всей60,48-часовой истории даёт67,5 часа по байтам,
75,4 по инструкциям и79,7 по условным инструкциям. Прежний произвольный запас
50% превращает это в101–120 часов. Эти значения не являются прогнозом срока
готовности игры: DLL, функции без диапазонов, приложение и Windows-зависимость
не измеряются полноценно. Последнее шестичасовое окно не даёт конечного ETA,
а двенадцатичасовое даёт790 часов — дополнительный признак непригодности этой
метрики для текущей экстраполяции всей работы. Честной новой даты завершения нет.
