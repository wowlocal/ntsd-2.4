# Цикл перекрёстной проверки игры с оригиналом

Задание для `/loop`. Каждая итерация читает этот файл, берёт следующую строку
[матрицы](research/CROSSPLAY_MATRIX.md), проверяет её на настоящем рантайме
оригинала под CrossOver и записывает результат. Найденное расхождение
разбирается и исправляется в порте. Цель — проверить всю игру, а не отдельные
функции. Общие правила проекта ([CONTINUE_GOAL](CONTINUE_GOAL.md), AGENTS.md,
[GOAL_100](GOAL_100.md)) остаются в силе.

## Безопасность

- **Ввод.** Только в окна приложения `NTSD 2.4.exe`.
  - Окна NTSDNative параллельного агента называются так же («Little Fighter
    2»); их не трогать.
  - Терминалы и другие приложения не трогать.
  - Сетевую игру оригинала (ONLINE GAME, Waiting/Connect) не запускать.
- **Экран.** Перед GUI-прогоном — `caffeinate -d -i -m -s -t <сек>`, после —
  снять. Если экран заблокирован (`CGSSessionScreenIsLocked`), GUI не
  использовать: только `winedbg`, Mac-приложение и анализ.
- **Процессы.** Экземпляры оригинала закрывать по PID: в командной строке Wine
  путь вида `Z:\…`.
- **Место.** X5 (UUID 3A4F5FA6-DC86-4C6E-87E2-EAC2C2D72548): держать не меньше
  40 ГБ свободными; старые кадры и сборки удалять.
- **Открытые ограничения.** Отказы safety и прежние ограничения из
  CONTINUE_GOAL остаются; затронутые операции не повторять.

## Итерация

1. Прочитать матрицу и выбрать строку с наивысшим приоритетом в статусе
   «не проверено».
2. Получить запись:
   - Mac → оригинал: сценарий для Mac-приложения с нужным режимом, персонажами
     и ареной;
   - оригинал → Mac: матч в оригинале, лучше только компьютерные игроки (ввод
     нужен лишь в меню), с включённой записью.
3. Проиграть запись в другой программе и сравнить:
   - все строки Summary;
   - время;
   - для War — итоги команд с учётом накопления в сессии;
   - когда есть инструмент — значения из памяти (оригинал через `winedbg`,
     Mac через дамп состояния) и, по возможности, состояние на выбранных тиках.
4. Если есть расхождение:
   - локализовать: тик → функция → инструкция (`winedbg`-трасса, оракул
     Unicorn);
   - исправить порт с тестом;
   - прогнать затронутые наборы и e2e;
   - влить в main;
   - записать карточку в `docs/research/`.
5. Обновить матрицу (статус, ссылка на evidence) и закоммитить.
6. В конце итерации кратко по-русски сообщить, что проверено, что найдено и
   что дальше.

## Задел для первых итераций

- **Чтение Summary из памяти.** Найти поля Kill/Attack/HP Lost/MP Usage/Picking/
  Status и время: `OriginalResultLayout` их читает. Читать их в оригинале через
  `winedbg`, а в Mac-приложении — опцией дампа, без сверки снимков на глаз.
- **Пакетный прогон.** Список записей проигрывается в оригинале (Cua),
  значения собираются автоматически.
- **Оригинал → Mac без участия человека.** Матчи «компьютер против
  компьютера» в оригинале: VS, турниры, War, Demo.
- **Потиковое сравнение.** Точка останова в оригинале на конце тела тика с
  условием по счётчику; в Mac-приложении — тот же тик через существующие
  трассы.

## Когда остановиться

Цикл останавливается, когда все строки матрицы проверены или явно объявлены
непроверяемыми с причиной. Ещё одна причина остановиться — следующая итерация
требует решения пользователя. Тогда вопрос задаётся один раз, ясно, с
рекомендацией.
