## Запуск и управление

```sh
cd /Users/michael/Developer/ntsd-2.4-l2df-prototype
./prototypes/l2df/launch.command
```

Готовое приложение: `build/l2df-prototype/NTSD L2DF Prototype.app`.
Папку `.app` можно перенести целиком: внутри находятся LÖVE, L2DF и ресурсы.
Самодостаточность проверена по ZIP-байтам, библиотекам и внутренним symlink;
перенос на другую/чистую macOS не проверялся. В установленном LÖVE, Python,
Windows EXE, Wine, CrossOver, эмуляторе и браузере runtime не нуждается.

- Naruto: WASD, F — атака, G — прыжок, H — защита.
- Sasuke: стрелки, J — атака, K — прыжок, L — защита.
- Иглы Sasuke: **одновременно J + L + направление взгляда**, из стойки.
  Последовательный ввод оригинального NTSD здесь не реализован.
- R — новая практика, Esc — пауза, M — звук, Q — выход.
  Уход фокуса ставит интерактивную сцену на паузу. Это управление оболочки.

Инструкции сборки и запуска проверок: [README](../../prototypes/l2df/README.md).

## Реализация

L2DF закреплён на `a20a16f2e8c9e889e33b3d762c94dc49498d0f83` (`wip-test`).
Все850 файлов полного архива сверены по Git blob SHA с ранее сохранённым GitHub
деревом. В runtime139 файлов upstream скопированы без изменения байтов.
Свои файлы находятся в `prototypes/l2df/`; реализация NTSDCore не затронута.

Сцена вызывает настоящий `l2df:init` и `l2df.gameloop`. В ней действуют
Factory/Object, Frames, States, Physix/Collision, World, Controller/Input,
LF2 Attributes, Sound и Opoint из выбранного движка. HP изменяет кандидатный
collision/hurt pipeline; оболочка не назначает урон или after-state. Снаряд440
создаёт `object.processOpoint` по исходному DAT, а не отдельная демонстрационная
анимация. Оболочка наблюдает audio API и missing Opoint, не подменяя их результат.

District читается из исходного зашифрованного DAT: фиксированный вид всей арены,
15 слоёв и два цикла NPC. Рендер слоёв и HUD написан в LÖVE вокруг движка;
бойцы, их кадры и столкновения принадлежат L2DF. Точного camera/raster сравнения
с Windows нет. Точный чёрный цвет BMP превращается в alpha только в собственных
image buffers там, где требуется прозрачность; исходные BMP не редактируются.

Конечный каталог содержит2/11/203/224/440. Скопированы111 исходных ресурсов,
19 532 782 байта; оригинальные DAT, BMP и WAV сохранены побайтно. L2DF Lua
converter и LFFS2 разбирают819 определений/818 уникальных ID:
Naruto318/317, Sasuke268/268, charge109/109, snake47/47, Chidori77/77.
Это полнота маркеров выбранных файлов, не проверка raw Frame/storage семантики.
Все пути и SHA находятся в `resource-manifest.json`.

LÖVE11.5, runtime API11.5.0, macOS bundle11.5a; universal Mach-O arm64/x86_64.
Фактическая среда: macOS26.6.2 (25G83), arm64. Приложение содержит259 ZIP-файлов,
20 453 293 распакованных байта игры. Все ZIP members сравнены с подготовленными
файлами, внешних symlink нет. Взятый официальный runtime не подписан; прототип
не notarized. Защиты ОС и глобальные настройки не менялись. Сеть не регистрируется
и не подключается: entrypoint исходного LF2 preset не используется.

## Найденные несовпадения и продолжение

- Повтор Naruto123 по-прежнему заменяется новым L2DF Frame; исходный NTSD
  сохраняет пропущенные численные поля. Не исправлено и не принято как NTSD.
- Kunai120 не включён: известное несовпадение незакрытого itr48 остаётся открытым.
- Иглы порождают **один** объект при `facing:50`; сохранённый NTSD-контракт
  создаёт пять. В этом кандидате **не списывается100MP** кадра261.
- NTSD D→direction→A не срабатывает; L2DF использует одновременные кнопки.
- 60Hz/data30, gravity24.9, friction0.96, seed12564, позиции410/475 и500HP —
  настройки кандидата/контролируемого прототипа, не восстановленная подготовка NTSD.
  Timing, double-tap, guard damage, HP/MP regeneration и RNG не сравнены с оригиналом.
- Большинство Naruto-техник ссылаются на отсутствующие здесь Opoint ID;
  это ограничение каталога, не исходное правило. AI, исходные меню/режимы,
  весь контент, сохранения, повторы, сеть и полный жизненный цикл матча открыты.
- Физическая клавиатура, услышанный звук, Windows pixel/timing и чистый/Intel Mac
  остаются отдельными непрошедшими проверками. Reset/pause UI есть в коде;
  отдельного автоматического ввода этих host-controls пока нет.

Следующий обоснованный эксперимент: адаптация импортного/Frame контракта и
конечного Chidori-пути (five-way spawn, MP, исходный combo) по существующим
доказательствам, с отдельным дифференциальным сравнением. Успешное native окно
не разрешает переносить непроверенные правила L2DF в NTSDCore и не закрывает
первый полный оригинальный матч или цель полной игры.
