input, runs the shared19-stage body and returns the same pending Bootstrap
ticket. The existing outer commit publishes the result. World/Actor aliases,
mutable DAT frames, backgrounds, replay storage, graphics and RNG remain owned

Installed-library control, contacts, hit processing and interleaved transform
prefixes now run through the shared body. The text replacement is forwarded
through diagnostics, notices, result layout and output. Its DC, hit storage
and transform destinations are retained in application state across calls.
The accepted process-attach input establishes20000 known-zero hit bytes once;
this is declared loader provenance, not a claim about an actual Windows heap.
Unrecovered transform destinations remain empty and reject required extended
writes. Pristine entry points retain their existing default behavior.

Catalog bitmap records belong to the current match model, while UI and arena
wrappers belong to general allocation memory. Retained ordinal/wrapper/surface
maps join them to the current graphics inventory. New arena surfaces are taken
from actual controlled CreateSurface replies. Release state and surface presence
are checked at use; historical constructor bytes do not replace current records.

Effects are buffered in the supplied value-owned environment and operation
journal. Result-file allocation, processor input, open/write/close and music
resume require explicit providers; their defaults throw at the actual call.
Codec allocations are checked against retained logical allocation ranges.
Queued WAV output validates a loaded buffer owner and stages each method once.
This API does not itself perform host file or device IO.
