# R03.1 — загрузка целых файлов каталога

**Статус:** в работе. Непрерывное чтение Naruto/Sasuke/kunai и контрольного
потока, всех 17 BG и исходного stage.dat перенесено и сравнено; весь набор
объектов исполнен в оригинале с MSVCR80 .6195; его полное нативное сравнение,
перекрытия Frame/десятый лист и соединение каталога открыты.
**Родитель:** R03 в [карте](../RESEARCH_MAP.md).
**Основания:** объявленная часть R02.1 — размеры Object/Frame, конструкторы,
разреженные маски и родительский реестр. Полная R02.1 не закрыта; этот участок
не зависит от ещё не восстановленного выбранного матча.

## Вопрос

Как EXE получает из целого исходного DAT заголовок, кадры, bitmap, оружейные
параметры, звуковой кэш и checksum, сохраняя исходный порядок и побочные эффекты?
Отдельный `<frame>` не является границей файлового потока оригинала.

## Принятый результат

[OBJECT_LOADER.md](OBJECT_LOADER.md) описывает адреса, данные и точную границу D.
`40ef70`, `4148a0`, `40bbf0`, `43ee50`, `40bd90` исполняются настоящими
инструкциями. Native Core содержит decoder, общий Object loader и прежний
Frame parser с непрерывным входом. Ошибка не публикует частичную сессию загрузки.

Сравнены шесть загрузок в четырёх корпусах: три исходных файла с явными stdio/
device-вариантами и один synthetic control. 308 688 байт/масок заголовков и bitmap,
1233 frame occurrences и 2400 конечных записей кадров, shared sound/checksum.
Kunai frame 49 действительно поглощается незакрытым itr кадра 48. Исходник сохранён.
Исключения старого изолированного корпуса не скрыты и не пересчитаны задним числом.
Регрессия: 20 Swift-тестов без ошибок и повторное сравнение всех 15 056
определений из прежнего изолированного корпуса; его хеш не изменился.

[BACKGROUND_LOADER.md](BACKGROUND_LOADER.md) добавляет целые исходные арены,
загрузку/освобождение/повторную загрузку слоёв и контрольные EOF/полей/ресурсов.
149 вызовов, 39 разборов, 673 wrapper и 608 освобождений совпали по полным
5 759 520 байтам/маскам, порядку ресурсов, decoded bytes и checksum. Общий
scanner исправлен для EOF без присваивания числа; реальный MSVCR80 остаётся
границей. Новый BG loader ещё не связан с parent/игровой практикой.

[STAGE_LOADER.md](STAGE_LOADER.md): полный `40c910/414a30`, 25 исходных стадий,
138 фаз, 818 записей и отдельные контроли. Сравниваются полные записи до EOF,
после каждой стадии/фазы и при повторных загрузках; все 60 слотов, включая
неиспользованные, сохраняют байты/маски. Stage не изменяет checksum.
Всего 6 загрузок / 436 checkpoints / 796 records; 24 Swift-теста прошли.
Это ещё не игровой режим Stage и не полный каталог.

[CRT_SCANNER.md](CRT_SCANNER.md): настоящий `fscanf` из хешированного пакета VC80
подтвердил wrap32 для `%d/%ld`, потребление знака при matching failure и EOF.
С Swift совпали 5364 случая с тремя размерами буфера, включая все 39 больших
целочисленных литералов исходников. Pein/Naruto/Sasuke и числовой контроль
совпали через целый Object и настоящий scanf: 817 определений, 216480 байт/масок.
26 Swift-тестов прошли. Общее `%lf`, Windows file I/O/startup остаются открыты.

Все 137 Object исполнены в исходном порядке с общим кэшем/суммой: 15388
определений, 54800 конечных Frame, 808 bitmap, 400 звуков, checksum 30847120.
Это [исследовательский корпус](../evidence/object-registry-research.json),
не нативное соответствие. Следующие препятствия конкретны: 38 Frame с указателями,
перезаписанными именами, включая изменение sound index; `4TK_ball` с 10 листами.

- [x] Проверить одно продолжение незакрытого блока через границу кадра, общий
  sound cache, таблицы спрайтов и mirror fallback с явной границей устройства.
- [x] Перенести все исходные BG и отдельные функции загрузки/освобождения
  слоёв с полными записями, масками и явными CRT/device-границами.
- [x] Перенести исходный stage.dat через полный Stage loader, включая sparse
  инициализацию всех 60 слотов, повторные стадии и порядок параметров.
- [ ] Проверить зависимые объекты Naruto/Sasuke и остальной реестр в исходном
  порядке; исходная последовательность загрузки отличается от пары этого стенда.
- [x] Выполнить все 137 исходных Object в исходном порядке, сохранив сырой
  результат и не интерпретируя повреждённые указатели как пути звука.
- [x] Выполнить настоящий MSVCR80 .6195 для `%d/%ld`, переполнения, позиции и EOF;
  сопоставить нативный сканер и отдельный полный Object корпус.
- [ ] Восстановить общее `%lf` rounding/lexing, точное stdio, Windows startup
  и фактическую привязку CRT. Переданный в `_read` поток этого не доказывает.
- [ ] Расширить домен имён/буферов/чисел на все исходные DAT; не править данные
  ради снятия ошибки парсера. Непроверенные случаи отклоняются явно.
- [ ] Сопоставить сырой Frame storage, его padding/указатели, полное владение
  аллокациями; нынешнее нативное сравнение кадров сохраняет числовое представление.
- [ ] Соединить загрузчик с родителем и BG/Stage, затем с обоснованным состоянием
  R01.2 и игровым циклом. Текущая практика использует прежний импорт.
- [ ] Добавить Windows W для соответствующего полного пути и устройств.

Закрытие требует целого объявленного набора зависимостей и числовых/файловых
границ; совпадение этих трёх объектов не закрывает весь R03 или полный матч R18.
Ближайшая задача R02.1 — полный Object-реестр и соединение загрузчиков в исходном порядке.
