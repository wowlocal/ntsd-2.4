# R02.1/R15 — ранняя загрузка ресурсов меню

Эталон — исходный EXE SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Исполнены конструктор World `419e40`, вход и диспетчер `4246b0`, затем ветвь
`424755..427089` при World selector, отличном от 1 и 2. Нативный
`OriginalFrontMenuResources` использует общий `OriginalBitmapConstructor`.

Это самостоятельное исследование раннего startup, необходимого для последующих
настоящих menu draws. Оно ещё не соединяет ранний экран с прежней цепочкой
World1→2/loading/round/menu. Старые корпуса сохраняют свои исходные границы
и нулевые ранние указатели; подстановка успешных ресурсов в них не производится.

## Порядок и состояние

Каждый вход сначала записывает `4511f8 = 1 - old` с UInt32 wrap. Если `44d068`
равен нулю, управление сразу доходит до `42709b`. Любое ненулевое значение
флага запускает загрузку. World constructor задаёт selector=0 и очищает только
400 байт активности; остальные байты World сохраняют заданный allocator backing.

Все 24 запроса выделяют wrapper размером `1f50`, передают flags=`40`, optional=0
в настоящий `43ee50` и сохраняют возвращённый wrapper pointer в global slot.
Null allocation пропускает конструктор и записывает нулевой pointer.

Сразу после первого global store записываются восемь имён `1\0`…`8\0`:
**UInt16** по `44fcc0 + 11*seat`. Остальные девять байт каждого поля не очищаются.

После первых 11 конструкторов задаются 151 буквальный прямоугольник на девяти
листах: SLOGAN 4, ENDING 6, MENU_CLIP 25, CLIP2 4, CLIP3 52, CLIP4 25,
CLIP5 12, CLIP6 8, CLIP7 15. Для каждого кадра порядок x/y/width/height,
смещения `10/7e0/fb0/1780 + 4*frame`; count в `+0c` пишется последним для листа.
Всего 613 записей. Координаты — константы EXE, а не сетка по размерам картинки.

`tools/extract_front_menu_rectangles.py` воспроизводит эти константы из
`424a72..426b98`: проверяет SHA EXE, каждый байт дизассемблирования, непрерывность
инструкций, разрешённые операции и порядок полей. Результат — обычные Swift
массивы с адресами инструкций, без runtime EXE/интерпретатора. Снимки ожидаемого
состояния не служат входом генератора.

После оставшихся 13 конструкторов сначала записываются все шесть font counts=256.
Затем внешний цикл идёт по glyph 0…255, внутренний — по шести шрифтам, затем
по x/y/width/height: `((glyph & 15)*16, (glyph >> 4)*16+1, 8, 16)`.
Таким образом сохраняются все 6 144 записи и их чередование между шрифтами.
Полная успешная загрузка содержит 6 796 записей родителя.

Старые wrappers заменяются в globals **без release** и остаются в реестре
выделений. Все нетронутые байты/маски сохраняются, в том числе count у cursor,
MENU_WAIT, CS и FRAME. Общий конструктор задаёт только surface/dimensions;
ошибки ресурса и SetColorKey сохраняют его уже исследованное поведение.

## Границы и независимое сравнение

Успешная ветвь останавливается **перед call `423480` в `427089`**. Флаг `44d068`
ещё не очищен: исходная запись находится в `427092`, после возврата настроек.
Результат `.settings` не означает завершённый startup. `.ready` означает
достигнутый `42709b` только при входном нулевом флаге.

Для 15 ресурсов, разыменовываемых этим участком, null wrapper останавливает
источник до первой metadata write. Native возвращает `.nullBitmap` с тем же
slot и частичным состоянием. Успешного пропуска нет. Остальные null wrappers
могут пройти этот участок, но это не доказывает допустимость их позднего рисунка.
Нулевая страница стенда нужна для SEH, а не для допустимой записи через NULL.

Выполнены два свежих прохода: A5/прямое размещение и ramp/обратное размещение
выделений. В каждом 145 случаев: первый вход из настоящего World constructor,
skip при разных phase/selector, ненулевые flags, одиночные и сочетанные null,
missing surface, signed HRESULT и последовательные повторные входы.
Между случаями сохраняются собственные World/globals и все старые wrappers.
Outer caller frame, allocator backing/addresses и OS/COM responses заданы явно;
это не весь исходный WinMain/CRT lifecycle. В повторных skip-пробах нулевой флаг
также задан явно, а не выдан за следствие ещё не выполненного `423480`.

На проход: 23 исходных PE DIB целиком с SHA, 2 151 allocation / 106 null,
2 045 настоящих конструкторов с ret12/EAX/nonvolatile проверкой, 506 213 событий
/ 497 585 упорядоченных записей; 72 settings, 44 skip и 29 null boundaries.
Независимый Swift получает исходные входы и выполняет собственную загрузку;
ожидаемые after-снимки не используются как начальное состояние.
Сравниваются все World/globals и все сохранённые bitmap bytes/masks после
каждого случая: 122 263 записи / 984 711 600 байт и масок на проход.
Нормализуется только известное surface word `+0` в 1/0 с проверкой привязки;
wrapper pointers и другие непрозрачные слова сохраняются буквально.

Оба release-сравнения прошли до принятия [основного](../evidence/front-menu-resources.json)
и [контрольного](../evidence/front-menu-resources-control.json) fixtures.
Оба XCTest прошли за 4.207 s; release NTSDNative — за 2.33 s.
SHA всех 19 прежних fixtures неизменны. SHA обоих новых raw/packed корпусов
и полное обратное распаковывание проверены; статический генератор воспроизведён.

```sh
python3 tools/extract_front_menu_rectangles.py --check
uv run tools/oracle_front_menu_resources.py
uv run tools/oracle_front_menu_resources.py --control
uv run tools/oracle_front_menu_resources.py --accept
swift test --package-path native --filter OriginalFrontMenuResourcesTests
swift build --package-path native -c release --product NTSDNative
```

SwiftPM команды выполняются последовательно. Следующий участок — настоящий
`423480` (чтение `data\control.txt` через CRT), возврат и очистка `44d068`,
затем ранний экран и соединение с проверенной цепочкой меню/загрузки.
Полный UI, реальный вывод пикселей/шрифтов, Practice, законченный матч,
Windows и чистая macOS остаются открытыми.

Продолжение: [SETTINGS_LOADING.md](SETTINGS_LOADING.md) теперь выполняет423480
и его CRT readers после свежего раннего parent, затем427092/42709b. Старые
resource fixtures остаются до settings boundary. Уточнение:427092 пишет caller
EBX, равный0 на естественном пути; это не непосредственный нулевой литерал.

[Собственная загрузка поверхностей](BITMAP_SURFACE_LOADING.md) теперь продолжает
реальный WinMain/loop/dispatcher через все43ed10/4013d0 и177 собственных
конструкторов. Семь ветвей доходят до427089, одна — до первой NULL metadata
границы. Все прежние корпуса этого документа и их границы неизменны;
новый путь ещё не исполнил settings и не вернул World/диспетчер.
