# R02.1 / R03.1 / R14 — непрерывная первая загрузка

Эталон: оригинальный NTSD2.4 EXE, SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
[oracle_initial_loading.py](../../tools/oracle_initial_loading.py) выполняет
**41bc90..41c581 в одном CPU, с настоящим прологом и без замены стека или
загруженного состояния между компонентами**. Это новый корпус; прежние
изолированные и составные корпуса не переписаны.

Теперь первая загрузка действительно соединяет18 общих WAV, полный исходный
каталог с включённым звуком,400 Actor и10 UI bitmap. Сброс44d05c получен из
настоящей инструкции41c577. Следующий41c581 ещё не выполняется.
Это не полный запуск игры, игровой такт или проверка вывода под Windows.

## Порядок исполнения

| Участок | Действие и проверяемое состояние |
| --- | --- |
| 419e40 | Настоящий World constructor; затем явно supplied selector2 |
| 41bc90..41be98 | Выравнивание стека, изменение фазы, очередь паузы, два локальных10-byte буфера |
| 41be98..41bfeb | Общая отрисовка/очистка областей,18 настоящих4014e0, count18,43e940 |
| 41bfeb..41c052 | Malloc4d823a8 и настоящий4122f0 со всеми Object/BG/Stage/WAV/bitmap children; реальный ret8 |
| 41c052..41c0d8 | Связь World с загруженным каталогом,400 аллокаций и конструкторов Actor |
| 41c0d8..41c2f5 | Повторные конструкторы и активация0..7 по настоящему catalog[0] |
| 41c2f5..41c581 |10 настоящих43ee50/ret12, последовательные global stores, восстановление паузы в EDI,44d05c=0 |

Входной ESP=1000f004; после выравнивания и пролога bodyESP=1000e9fc.
Общие звуки возвращают стек к bodyESP; после presentation остаётся ещё один
аргумент.41bff5 снимает его вместе с аргументом malloc. Возврат каталога в
41c018 сразу переходит на41c052. Не проходить линейно через41c01a..41c04b:
этот участок принадлежит playback/camera ветви пролога.
После UI ESP снова bodyESP, EDI равен локальному результату проверки паузы.
Функция41bc90 ещё не вернулась; её полный ret4/SEH здесь не заявлен.

## Фаза и пауза

41bcda..41bcf3 вычисляет `(Int32(old) + 1) % 2` с32-bit wrap и остатком
со знаком делимого. При результате0 копирует44fb60→450bfc и44fcb0→44fb60.
Пауза локального вызова — точное450bfc==1. Два локальных буфера+434 и+440
получают по10 нулевых байт; промежуточные padding bytes не становятся
игровыми командами.

Первый полный проход проверяет phase0→1 и отсутствие паузы. Второй:
phase1→0, pause0→1 и queued1→3, EDI после UI=1. Формула для иных Int32
восстановлена статически; эти два корпуса не являются перебором её границ.
450b84=0 явно задан: replay/camera/43dc50 до загрузки остаются вне этого
нативного пути. Native begin отвергает playback вместо пропуска его действий.

## Существующие globals внутри звукового кэша

В прежнем отдельном каталоге11776-byte cache455638..458438 был нулевым.
В первом входе в этом диапазоне уже находятся graphics device457578,
presentation mode458348 и очищаемая общими звуками область457588.

Native OriginalSoundRegistry теперь принимает исходные bytes этого диапазона.
OriginalLoadedCatalog получает их из **собственного состояния после общих
звуков**. При регистрации сохраняется исходный stride20, полный path+NUL,
lookup и его перекрытия. Не обнулять хвост диапазона и не заменять его
словарём. Проверены ненулевой457578=10203040 и режимы вывода1/3; оба значения
сохраняются после400 исходных регистраций и достигают UI/presentation.

Зарегистрированные400 буферов остаются отдельными от18 общих. Их PCM,
временная память, format/descriptor, маски, SetVolume и real caller ABI
сравниваются прежним [CatalogSoundsReference](../../native/Sources/NTSDReferenceChecks/CatalogSoundsReference.swift)
при новом полном построении каталога. Файлов365; дедупликация по имени
по-прежнему неверна из-за перекрывающихся строк реестра.

## Таймер загрузочного экрана

При соединении найдено пропущенное поведение без изменения данных каталога:

- 412549 делает один timeGetTime перед fopen и отбрасывает результат.
- Родитель вызывает4242e0 перед каждым Object.
- 40f1d8..40f1e9 вызывает его **перед каждым чтением поля BMP-заголовка**,
  включая чтение первого поля и завершающего `<bmp_end>`.40fd23 возвращает
  цикл на40f1d8; это не только один вызов на весь `<bmp_begin>`.
- 40f314/40fdde — после normal bitmap и записи ссылки;
  40f3d5/40fe9b — после optional mirror и до проверки поверхности;
  40f500/40ffc3 — после fallback/mirror blit, также при уже имеющемся mirror.

Общий Object parser теперь имеет callback в этих местах; правило не зависит
от имени персонажа. OriginalCatalogRegistry.beforeRead сохраняет первый
таймерный вызов в правильной позиции относительно четырёх embedded bitmap.
Старые data-only callbacks по умолчанию пустые, поэтому прежние области
проверки не выдают себя за исполнение загрузочного экрана.

Здесь timeGetTime всегда возвращает100, PeekMessageA=0. Каждый полный проход
выполняет4231 вызов4242e0,8464 запроса timeGetTime и4231 Sleep(5).
Первый вызов helper задаёт4511c0=100. Нативная OriginalLoadingProgress
воспроизводит этот порядок; список timer/Sleep событий сравнивается целиком.
Ветка с elapsed>33, рисующая анимированный экран загрузки, остаётся открытой
и явно отвергается native. Это ограничение существенно для подключения
к настоящему приложению с движущимися часами.

## Нативная композиция и сравнение

[OriginalInitialLoading](../../native/Sources/NTSDCore/OriginalInitialLoading.swift)
владеет итоговыми globals, каталогом, общими/зарегистрированными звуками,
bootstrap и интерфейсными bitmap. Использует существующие механизмы;
провайдер каталога в сравнении запускает реальный OriginalLoadedCatalog,
не возвращает ожидаемый снимок. Checksum/cache/buffer slots после каталога
получены из native parser/WAV results. Отдельные callback checkpoints
проверяют результаты и не подставляют expected globals.

OriginalWorldBootstrap теперь также принимает уже построенный World,
сохраняя прежние bytes/masks. Word90 для первых восьми берётся из native
catalog.objects[0], а не из supplied заглушки. В исходном реестре это Pein,
но код использует ordinal0. Выбор игроков и match spawn остаются отдельным
ранее восстановленным механизмом.

[InitialLoadingReference](../../native/Sources/NTSDReferenceChecks/InitialLoadingReference.swift)
сравнивает полные globals после пролога, каждого общего WAV, каталога и
каждого UI store; оба снимка всего пула, все UI wrappers и маски, исходные
DIB/dimensions и события. Связанные сравнения повторно строят и проверяют
все137 Objects/15388 Frames,17 BG,25 Stage/138 phases,829 catalog bitmap,
14586 Frame allocations и400 зарегистрированных WAV.
Преобразуются только установленные указатели: World/catalog/Actor ordinals,
bitmap surface1/0; произвольные pointer-like bytes не нормализуются.

Контрольный проход использует ramp backing World/Actor, обратный физический
порядок400 адресов, phase0/pause и presentation3. Каталог обоих проходов
остаётся исходным text/a5. Нативный результат не зависит от физического
порядка адресов. После UI исходный oracle проверяет неизменность всего пула.

| На один полный проход | Результат |
| --- | ---: |
| Общие / зарегистрированные WAV |18 /400|
| Actor / UI constructors |408 /10|
| Loading records / bytes+masks |929 /3106120|
| Audio / catalog bytes+masks |66210142 /112063739|
| Loading / registry-audio events |13027 /6426|
| Checksum |31475378|

Два прохода вместе:362760002 сравниваемых bytes/masks. Это объём сравнения,
а не показатель готовности игры. Полные raw captures и шесть lossless
fixtures закреплены SHA в [основном отчёте](../evidence/initial-loading.json)
и [контроле](../evidence/initial-loading-control.json). Packed release comparison
обоих проходов прошёл до записи fixtures. Исторический interleaved catalog
после извлечения snapshot method заново воспроизведён **точно со всеми blobs**.

Десять выбранных XCTest прошли за314.981s без ошибок: новые два сквозных
прохода158.857s, старые catalog sounds98.056s, четыре Object/raw-Frame проверки
56.300s и два bootstrap теста1.768s. Release-сборка NTSDNative прошла за2.47s.
Прежние fixtures не изменены. Эти проверки относятся к описанному загрузочному
домену, не к полному матчу или запуску на чистой macOS.

```sh
uv run tools/oracle_initial_loading.py

uv run tools/oracle_initial_loading.py --accept
```

## Оставшиеся границы

World selector2, исходные PE/BSS globals с явными device/mode/pause inputs,
allocator backing/адреса, frozen clock, file/MMIO/COM и pinned VC80 contract
остаются входами стенда. Предшествующая World1→2 ветвь проверена отдельно;
она ещё не вызвана в этой же непрерывной цепочке. World constructor выполнен,
но полный размер и lifetime World ещё не закрыты.

Обработка произвольных allocation/IO отказов, animated loading progress,
playback prefix, input/pause/menu после41c581 и путь к429730 остаются открытыми.
Ошибки WAV/UI имеют прежние отдельные bounded corpora, а не полный fault run
этого первого входа. Здесь также нет всей Windows CRT lifetime, пиксельного
вывода, микшера, AI/полного матча или проверки на чистой macOS. Practice0.4.0
не изменена. Windows W остаётся обязательной отдельной проверкой.

Следующий шаг — продолжить собственное загруженное состояние через41c581,
419a60 и дальнейшие input/pause/menu ветви до429730; параллельная по зависимости
задача — animated4242e0 и происхождение остальных меню/устройств. Не возвращать
44d05c вручную и не подменять новый каталог синтетическими Object headers.

S следующего участка:41c581..41c5c1 копирует21 байт4493c8..4493dc в
44d040..44d054 даже при локальной паузе. Только затем41c5c7 пропускает419a60
при paused!=0. Иначе передаёт phase450b90, mode451160 и local+434. В419a60
для места со status>0 копирование Actor+cd..d3→c6..cc выполняется в обеих
фазах; чтение нового локального ввода следует только в фазе0. Эти наблюдения
пока статические и не расширяют новый D-корпус за41c581.

Продолжение выполнено в [LOCAL_INPUT.md](LOCAL_INPUT.md):41c581..41c5e5
и419a60/ret12 теперь проверены на том же реально загруженном мире. Сам этот
исторический корпус по-прежнему заканчивается перед41c581.
