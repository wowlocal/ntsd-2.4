# Свежие ресурсы в экране персонажей

Продолжение [FRESH_LIBRARY_MENU](FRESH_LIBRARY_MENU.md) по конечному
[плану](FRESH_CHARACTER_MENU_PLAN.md). Общий `OriginalCharacterScreen` теперь
имеет библиотечный текстовый путь; `OriginalCharacterMenuContinuation` связывает
владельцев ресурсов, человеческий экран и вывод до фактического422ab8ret4.
28 контролируемых возвратов совпали. Две остановки перед записью через
NULL-SPARK отклоняются нативно с полным откатом и не являются совпавшими возвратами.

Эталон — те же pinned NTSD EXE, bundled lib.dll, VC80 и11 оригинальных embedded
DIBs; SHA приведены в плане и машинном свидетельстве. Unicorn2.1.4/CW023f
исполняет настоящий41bc90 пролог, затем объявленный4229cc хвост. Раннее тело
такта пропущено явно. Allocator/COM/GDI/IO остаются ответами стенда; это не
Windows, устройство или собственный полностью инициализированный такт.
Трассировка памяти, стека и возвратов нужна для проверки владения свежими
bitmap, порядка изменений400 Actor и сохранённого DC, а не для воспроизведения
частного ABI в приложении.

## Поведение

В отличие от входа menu10, текущие menu1/menu3 пропускают музыкальный дочерний
вызов: его условие — previous!=10 и current==10. Music allocations/calls здесь0;
оба варианта с указанным NULL-wide response оставляют его непрочитанным. Поэтому
они проверяют этот gate, а не отказ allocation. В исходном scope первого стенда
ожидалась свежая музыка; текст сохранён в сырых данных, фактическая граница
уточнена здесь. Ни graph.log sprintf, ни wide buffer в этой ветви не создаются.

Загрузка11 bitmap сбрасывает места в Random и снимает latch. Menu3 затем
повторно устанавливает latch1, поэтому удерживаемая кнопка не присоединяет
место в этом кадре. Проверены начальные modes0/1/2/4, Stage team1 первых20,
War команды1/2, очистка всех400 недопустимых team, один/восемь join, приоритет
attack перед jump, cancel, счётчик2147483647 и countdown−1/0/149/150. Cancel
действительно исполняет431c70..431d0d, очищает команды восьми мест и300 клавиш
через original CRT memset. Подключения конкретного Object в этой проверке нет.

Новый экран рисует собственные CHARMENU/CMA/CM1..5/RFACE прямо из
`OriginalMenuResourceLoading.bitmaps`. Native bitmap хранит смысловой surface
reference; только этот известный указатель связывается с ответом COM. Остальные
байты и маски полного8016-byte record сравниваются без нормализации. Whole-frame
рисование читает незаполненный+0c. При положительном ramp count оригинал также
проходит отрицательный frame−1 и читает+fac/+7dc/+177c. Все1032 таких чтения
сохранены с defined=false и исходным содержимым выделения. Это не доказательство
происхождения реальной Windows heap; прежний bitmap алгоритм не изменялся.

Установленный lib text сохраняет transparent background и retainedDC, продолжает
после отрицательного GetDC. 28 возвратов сравнивают10357 упорядоченных событий:
5852 startup,258 bitmap requests,1935 reads,387 clips/Blts,246 GetDC и228 полных
последовательностей текста,24 запроса звука/72 sound methods,28 fill и28 present.
308 свежих bitmap полностью совпадают. Сохранены2347 helper returns и
1421 EXE+51lib+33CRT instruction starts для этих возвратов.

## Проверка состояния и границы

Все30 исходных случаев прошли независимый replay83763 stores/376452 bytes,
65799 instruction reads/259758 bytes и1786 API reads/10656 bytes. Проверены
12840 конечных records/56176740 bytes и982 checkpoints,420296 records/
1838851956 bytes с полными масками,2427 helper returns,770 blobs/
35219864 decoded bytes. Всего1422EXE+51lib+33CRT starts. Ложные маски вне
bitmap относятся только к исходному EXE cookie; его неизменные PE-байты
проверяются отдельно.

В каждом возврате Native сравнивает полные World/400 Actor/globals на13 точках
экрана и в конце;1820 значащих caller counter words сверяются без импорта x86
scratch. Контролируемые начальные records заданы явно. Для контейнера состояния
тест нормально восстанавливает прежний самодостаточный interleaved catalog;
выбор Random не читает его Object, Frame или sound bytes. Это не собственное
продолжение нового полного каталога.

Шесть ошибок наблюдателя после создания ресурсов, третьего текста, четвёртого
Blt, конца экрана, present и перед возвратом проверяют общий откат World/Actor/
globals/ресурсов/DC/буфера событий. Ещё одна ошибка после музыкального gate
проверяет ранний выход до выделений. Две source NULL-SPARK границы проверяются
отдельно. Внешние события необходимо буферизовать до общего commit.

## Сохранённые исправления стенда

Capture1/2 завершились на отсутствовавших в observer allow-list4450a0 и431d0c;
сохранены ошибки, PID/UTC/session и по пять atomic cases. Дизассемблирование
подтвердило actual memset thunk и оставшиеся pop/ret. Capture3 завершил30 calls,
но маршрутизация не закрывала наблюдение reset-memset return, что также скрывало
три последующих обычных cookie-helper return records в каждой отмене. Capture4
добавил восемь наблюдений; все прежние states/read/write/event/instruction bytes
проверены неизменными. Исходных game faults или safety refusals здесь не было.

Три ошибки независимого verifier сохранены: слишком широкий диапазон исключал
проверку left-button вместе с roster loads; список неизвестных bitmap-чтений
сначала учитывал только A5 backing; затем ожидалось одно дополнительное helper
наблюдение вместо четырёх на cancel. Итоговый replay проверяет точные PC/offsets,
полные сырые данные и все предыдущие atomic части без изменения expected bytes.

Первый release build244.14s связал NTSDNative. Все6 прежних tests прошли, включая
обе34-frame собственные последовательности выбора; два новых остановились на
подготовке теста: menu-loading catalog требует предшествующий sound registry.
Тест переключён на прежний самодостаточный catalog fixture через его обычный
loader; Core и исходные expected не исправлялись. Повторные2 tests прошли8.982s,
build80.30s. Итоговые2 packaged tests прошли8.873s/build0.28s без raw override. Все651
package inputs и состав рекурсивных архивов проверены;254 прежних fixture
неизменны,255 текущих. Полные raw113499742 bytes и packed9864941 bytes
восстанавливаются побайтно с одинаковыми JSON и SHA. Source/SwiftPM jobs этого
этапа завершены; NTSDNative связан, окно и устройство не проверялись.

Полные журналы, версии producer/verifier/test, input archives, fixture pins и
результаты находятся в `build/research/fresh-character-menu-work.json`.

Открыты конкретный выбор из нового каталога, дальнейшие selection stages,
собственная библиотечная цепочка, внешний цикл, окно/input/audio, полный матч,
Windows, весь игровой объём и чистая macOS. Длинный guarded catalog продолжает
работать независимо; этот этап не заменяет его полного возврата.
