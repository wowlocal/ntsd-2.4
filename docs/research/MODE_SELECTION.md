# Общий ввод меню и выбор режима

R02.1/R04/R15. Эталонный EXE SHA-256:
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.

Перенесены весь431b70 и клавиатурная часть экрана4322ad..4328f8 с настоящими
401a30,423910/43ef50 и4019b0. Оба самостоятельных корпуса с явно заданными
входами совпали со Swift. Это проверка механизмов перед соединением с
[собственным startup](MENU_STARTUP.md), а не выполнение целого431d10 из429e5a.
Отрисовка, файловое воспроизведение и UI приложения ещё не подключены.

## Какой экран следует за startup

Статический разбор429e5a..429eb7 и431d10..432aaa, а также подписи исходного
`MENU_CLIP3` уточняют последовательность: **menu10 — выбор режима**, затем
в обычном VS/Mission/War пути menu3 начинает выбор персонажей. Названия
CHARMENU/CM* загруженных bitmap не означают, что следующий экран уже выбирает
персонажей.

Настоящий caller429eb2 передаёт `this=World` и четыре аргумента:
target, `&menu=44d020`, `&mode=451160`, `&selection=4512c8`.
Последний аргумент нельзя путать с mode. После собственного startup SP меню
равен1000df08; вход431d10 имеет SP1000def4, а его полный рабочий frame —1000d7dc.
В нём mode/menu/target/World/selection хранятся по смещениям10/14/18/1c/20.
Три исходных выхода используют ret16. Этот ABI всего экрана здесь пока S.

## Ввод431b70

Helper сначала обнуляет семь DWORD-флагов4513bc..4513a4, затем проходит
ровно восемь указателей World+194. Он не проверяет активность, controller
status, тип объекта или ID персонажа. Участники могут ссылаться на одну
Actor-запись: защёлки относятся к месту участника, а не к Actor.

| Приоритет | Actor byte | Флаг |
| --- | --- | --- |
| Вверх | cd |4513a4 |
| Вниз | ce |4513a8 |
| Вправо | d0 |4513b0 |
| Влево | cf |4513ac |
| Атака | d1 |4513b4 |
| Прыжок | d2 |4513b8 |
| Защита | d3 |4513bc |

Любой ненулевой byte означает нажатие. Для первой нажатой кнопки helper
ставит общий флаг1, только если DWORD-защёлка451320+4*seat равна0, затем
записывает в защёлку1. Остальные кнопки этого участника пропускаются.
Если все семь отпущены, защёлка становится0. Смена кнопки без полностью
отпущенного прохода не создаёт новую команду. Отрицательная защёлка также
блокирует срабатывание. Разные участники могут выставить разные общие флаги
за один вызов. Actor/World остаются неизменными.

## Навигация и подтверждение

4322b6..43231e последовательно обрабатывает вверх, затем вниз. Оба направления
могут прийти от разных участников за один проход. Вверх уменьшает mode с
32-битным переполнением, любой отрицательный результат заменяет на7. Вниз
вычисляет знаковый остаток `(mode+1)%8` после исходного переполнения. Каждый
из двух переходов сбрасывает таймер подсказки4513c0.

Network byte44f1af проверяется как **Int8>0**. При навигации вверх результат6
заменяется на5, вниз — на7. Прямое подтверждение уже выбранного mode6 отдельной
network-проверки не имеет. Это важно для точно заданных контрольных состояний.

При attack4513b4!=0 подсказка сбрасывается. Для любого signed mode<7, включая
отрицательные, вызывается401a30 с loop0. Затем идут исходные проверки mode:

| Mode / подпись | Изменение состояния перед423910 |
| --- | --- |
|0 VS Mode | selection=0, menu=3,44d024=100,44d028=1 |
|1 Mission Mode | то же |
|2 Tournament | menu=20,44d024=0,44d028=0 |
|3 Team Tournament | menu=120,44d024=0,44d028=0 |
|4 War | как mode0 |
|5 Demo | menu=2,450c2c=1;44d024/44d028/selection сохраняются |
|6 Playback Recording | остановка перед43249c, после звукового helper |
|7 Quit |4019b0; при458434==0 PostQuitMessage(0) |

Для0..5 также сбрасывается4513c0 и устанавливается44d780=-1. Общий423910
освобождает текущий4511ac через настоящий43ef50, обнуляет surface+0, вызывает
free и очищает глобальный указатель. Нетронутые bytes/masks и мёртвая запись
wrapper сохраняются в модели владения.

Quit вызывает только **4019b0**, который освобождает два списка звуков и
звуковое устройство. Music interfaces, replay pointers и replay allocations
здесь сохраняются. Ранний составной shutdown дополнительно вызывает другие
helpers и PostMessage(close); целиком переносить его в этот caller было бы
ошибкой. Из общего нативного shutdown выделен `releaseSoundDevice`; ранний
caller продолжает выполнять прежнюю полную последовательность.

## Реализация и сравнение

- `OriginalMenuInput.advance` — общий431b70; `OriginalMatchPreparation`
  предоставляет делегирующий метод для последующего меню.
- `OriginalModeSelection.advance` соединяет ввод, навигацию и подтверждение
  с общими sound/background/device helpers. Его выход — panel4328f8 или
  playback43249c. Изображение, подсказка, курсор и хвост относятся к caller.
- `OriginalMenuPresentation.releaseBackground` используется также прежним
  World1-переходом; общие правила не дублируются.
- `ModeSelectionReference` сохраняет собственное состояние между пробами.
  Ожидаемые после-снимки служат только сравнению. World-поля первых восьми
  ссылок нормализуются в ненулевые ordinals; ordinal0 не означает null.

Каждый корпус содержит1345 случаев:616 прямых431b70 и729 связанных keyboard
entries. Перебраны все128 комбинаций семи кнопок с четырьмя значениями latch,
каждое из восьми мест и кнопок, удержание/смена/отпускание, alias на первом и
девятом backing,16 mode-значений включая Int32-пределы, пять network bytes,
восемь комбинаций up/down/attack от отдельных мест, null/disabled sound и
background, реальные device releases и повторное подтверждение без отпускания.

Первый корпус использует A5 backing, второй — ramp и обратные физические
адреса Actor. Начальные bytes/masks и все последующие внешние записи/revive
объявлены явно: это входы самостоятельного стенда, не recovered startup.
Helper действительно исполняет исходные инструкции; результаты COM/free/
PostQuit supplied. Все Actor/World, globals, bitmap, два replay backing и
replay pointers сравниваются целиком, вместе с masks/liveness. Проверяются
упорядоченные события и helper return ABI. Трасса отдельных записей EXE
сохраняется дополнительно; native сравнивает состояние на выходе пробы,
а не утверждает совпадение после каждой машинной записи.

На каждом проходе совпали1813 events,2159 helper returns,20175 records и
88382640 bytes/masks. Итого2690 случаев,3626 events,4318 helpers,
40350 records и176765280 bytes/masks.46 остановок перед playback сохраняют
реальное частичное состояние; reset431c70 и файловый диалог ещё не выполняются.
Размеры и SHA зафиксированы в [основном отчёте](../evidence/mode-selection.json)
и [контроле](../evidence/mode-selection-control.json).
