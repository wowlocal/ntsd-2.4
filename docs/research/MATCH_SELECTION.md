Каждый новый кадр начинается целым4246b0→41bc90 и проходит существующий
local/control/received/replay/round/music/resources. Только acquired keyboard
100/117 задаются через собственные control.txt bindings. Одна клавишная грань
занимает четыре кадра: press acquired phase1, press applied phase0, release
acquired phase1, release applied phase0. Последний Start заканчивается на
применении press, до42cf8a; его match prelude/подготовка здесь не исполняются.

   После четвёртой грани остаётся11. Пятый press applied даёт−21 и selection1.

## Число компьютеров,42b296..42b959

Перед popup выполняются все прежние human-seat handlers. CMC рисуется в218,215;
451220 обнуляется. Просматриваются все восемь activity bytes и Actor team:
каждый независимый team0 увеличивает число групп, ненулевой team учитывается
один раз. Пять счётчиков находятся на исходном stack+814. Inactive count — число
нулевых activity, а не число отрицательных selected.

Если групп меньше2 и mode!=1, нижняя граница1; иначе0. Верхняя граница — inactive
count. Sentinel−100 и значения вне границ заменяются нижней. При отсутствии
свободных мест selection становится3, но оставшаяся часть popup ещё выполняется.

У активных мест приоритет right,left,attack. Грань требует latch0 **и** исходную
selection на входе кадра1 (stack+3c). Навигация оборачивается между min/max.
Отсутствие этих команд очищает latch; jump на этом экране не подтверждает выбор.
Mode2/3 имеют отдельную принудительную ветвь, не покрытую новым VS-путём.

Подтверждение пишет selection2, а при count0 — option44d06c2, selection3 и восемь
флагов451228+4*seat, равных результату signed selected<0. Для каждого ненулевого
флага строится список ordinal1..<count, type0, signed source ID<30, исключая
**все восемь** текущих selected. RNG417170 имеет tagd7. Выбранный ordinal и
Object binding базового Actor меняются сразу, до списка следующего места.
Правило общее с [MATCH_CONTINUATION.md](MATCH_CONTINUATION.md), без обработчиков
по именам персонажей. Неактивность места не отменяет этот расход RNG.

Числа0..7 форматируются настоящим VC80 sprintf `%d` и выводятся через401290.
X=286+30*число, Y286, фон9f472f, цветffffff внутри границ/c06850 снаружи.
Выбранное число обводится четырьмя настоящими415160: верх/лево/низ/право,
белые полосы21×1 и1×21, внешние координаты280+30*число,283..303.
Backings/маски100-byte FX сохраняются отдельно для каждой заливки.

Новый D путь проверяет min0/max6, отсутствие навигации по числу и подтверждение0.
Right/left, min1, отсутствие свободных мест и числовые границы пока имеют S
правила. Подтверждение положительного числа компьютеров явно останавливает
native runner перед неподключённым продолжением выбора их персонажей/команд.

## Музыкальная настройка,402130..4025a5

Left/right меняют **музыку**, независимо от выбранной строки. Ненулевой right
увеличивает choice44f18c, затем >8 заменяется−1; ненулевой left уменьшает choice,
затем <−1 заменяется8. Проверки границ выполняются и при отсутствии направления.
Stage mode1 вместо этого переключает ON/OFF при любом из двух направлений.

Для обычного mode choice0 выводит Random и **каждый вызов** расходует RNG417170
с tag1/range8, даже без ввода. Результат+1 задаёт44eed0: main, stage1..5,
boss1/boss2 `.wma` в `bgm\`. Choice1..8 выбирают те же пути без RNG. Никаких
отдельных генераторов для музыки и персонажей нет: table/index/counter общие.

Строки копируются только до NUL, хвосты сохраняются. Choice−1 в обычном mode
обнуляет первый байт пути; Stage OFF перескакивает это обнуление и сохраняет путь.
OFF пишет44d0100 и вызывает общий402100 (stop/seek); прочие choices пишут1.
Stage ON сохраняет путь без RNG. S-ветви OFF/Stage/ручной музыки ещё требуют D.

следующему этапу. Windows DirectShow/слышимый вывод этим не проверяются.

## Проверка и открытые границы

Новый native runner составляет прежний OriginalCharacterScreen, общий bitmap/
text/fill/sound/RNG и продолжение меню. Callback получает собственные состояние
и локальные счётчики после human handlers; ожидаемые снимки не используются как
вход. CharacterScreenReference выделяет общий compareCases и onLast, сохраняя
полную проверку всех34 прежних кадров и их родителей.

Первые исходные проходы A5/control остановились на19-м новом экране: старый
наблюдатель415160 допускал только полноэкранную заливку. Сохранены18 завершённых
диагностических кадров. Новый default-preserving параметр наблюдателя принимает
только четыре восстановленных popup rectangles, проверенные по caller/ESI.
Оба прохода после этого повторены с начала, включая все закреплённые родители;
восстановление snapshot для принятой непрерывной цепочки не используется.
До этого оба18-frame диагностических префикса также совпали нативно:
по199782 records/266689908 bytes+masks. Core и ожидаемые snapshots не менялись
для обхода ошибки наблюдателя. Signed locals теперь декодируются из исходных
сырых UInt32, включая−1 в+28 после смены selection.

Суммарно два новых корпуса: **100 целых внешних входов,98 полных вложенных
возвратов,2 границы42cf8a,3026 checkpoints,16840 событий,3516 helpers,
1203502 records/1589446344 bytes+masks**. Метрики относятся к новым50+50 кадрам
после собственных родителей; прежние34+34 human screens не считаются повторно.

catalog bitmap и CRT RNG state, события и пять caller counters+20/+28/+34/+38/+3c.
Полное содержимое x86 стека за пределами объявленных данных не сравнивается
