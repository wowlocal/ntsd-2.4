# Полная готовность нативной NTSD 2.4

Активная цель пользователя от 2026-09-12: довести текущий прототип до полностью
работоспособной нативной macOS-версии NTSD 2.4, сохранив содержимое, управление,
боевую механику и ощущение закреплённого Windows-оригинала. Самостоятельный `.app`
должен обеспечивать полный игровой цикл без браузера, Wine, CrossOver и средств
разработки. Исходный текст цели сохранён в
`build/l2df-prototype/presentation-20260912/0-pasted-text-1.txt` и закреплён
`plan-inputs.json`; исходное приложение — commit4778284.

Работа ведётся в `codex/l2df-native-prototype`, с коммитами законченных этапов.
Оригинальные ресурсы, эталоны, маски, предыдущие приложения и ошибки сохраняются.
Используются готовые исследования; новые следуют AGENTS/WORKFLOW. Полный матч
Naruto/Sasuke остаётся промежуточной вехой. Ниже статус каждого требования,
а не изменённое определение готовности.

| Требование пользователя | Доказательство завершения | Текущее состояние |
| --- | --- | --- |
| 1. Полный цикл: запуск, ресурсы, меню/настройки, выбор, бой, исход, следующий раунд, повтор, выход | Сквозные проверенные последовательности в поставляемом приложении и сравнение исходного поведения | Открыто: запускается только контролируемая Practice |
| 2. Все персонажи, арены, режимы, техники, превращения, призывы, оружие/предметы; действия не останавливают игру | Полный исходный каталог загружен собственными обработчиками, игровые зависимости доступны, сквозные сценарии содержимого | Открыто: пять Object ID, District, ограниченные исполняемые состояния |
| 3. Совместимые движение/комбо/HP/MP/collision/damage/guard/grabs/projectiles/AI/update order/timer/camera | Неизменяемые эталоны соответствующих общих handlers плюс целые игровые проходы | Частично: ActorInput14624, bounded World575/16685; общие более полные Swift handlers ещё не подключены к L2DF |
| 4. Локальная игра, настройка клавиш, одновременные нажатия, пауза/фокус, музыка/эффекты на устройстве | Проверки физической клавиатуры и звука, настройки и lifecycle в приложении | Частично: два local controller, synthetic callbacks и audio isPlaying; физическое подтверждение и музыка открыты |
| 5. Сетевая игра двух клиентов, синхронизация, connect/disconnect | Два реально работающих клиента, записанные штатные и отказные сценарии | Открыто: network manager Practice отключён |
| 6. Эталонные и сквозные проверки, устранённые расхождения без подмены expected | Проверенные comparator scope, неизменённые expected/masks и проверки текущей поставки | Частично: конечные корпуса приняты; полный матч/весь каталог не проверены |
| 7. `.app`, архив релиза, инструкция, чистая macOS/поддерживаемые архитектуры, отсутствие блокирующих дефектов | Самодостаточный пакет и реальные установки/запуски, требуемые регрессии и device acceptance | Частично: самостоятельный текущий `.app`; clean Mac/Intel/полная игра открыты |

Приняты в конечном объёме [исходный таймер и отображение камеры](L2DF_PRESENTATION.md)
и [основание C ABI к Swift](L2DF_NATIVE_BRIDGE.md). В следующем принятом этапе
[собственная сессия](L2DF_LOADED_SESSION.md) загрузила начальные ресурсы и настройки
в двух сохранённых профилях, с269 ABI checks и полным rollback.
[Первый возврат меню](L2DF_FRONT_SCREEN_SESSION.md) продолжил того же владельца
до FIRST_MENU_RETURN:336 ABI checks с прежними регрессиями, полные шесть фаз,
состояние и rollback в обоих профилях. Эта сессия ещё не подключена к
Practice-приложению и не предоставляет игровой tick.

Следующий шаг — собственный application startup и первый возврат внешнего цикла
меню с восстановленным поведением bundled library по уже сохранённым47 полным
случаям и одной отдельной NULL-cursor boundary. Затем — ввод/загрузка и каталог
в том же владельце. Сохранённые16 нейтральных и48 активных gameplay-вызовов
проверяют pristine EXE; для полной NTSD нужен отдельный library-aware join.
Существующие Swift правила с явной extended precision переиспользуются без
упрощения до прежнего Practice Double. Далее — полный игровой проход и lifecycle,
каталог/содержимое, меню/режимы,
настройки/устройства, два сетевых клиента и проверка поставки. Порядок конкретных
шагов уточняется по готовности зависимостей, ни один критерий не удаляется.

Открытые safety incidents основной ветки не разрешены новой целью. Отдельная
ветка и перенос по готовым данным не закрывают их. Полная цель остаётся активной
до отдельной проверки всех семи требований на фактической поставке.
