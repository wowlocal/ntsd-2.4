# R02.1/R14 — включённая музыка перед ресурсами меню

Эталон: исходный NTSD 2.4.exe, SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Для sprintf исполняется исходный MSVCR80 8.0.50727.6195, SHA-256
`c3ac989c8489a23bb96400b1856f5325ffc67e844f04651ea5d61bc20a991c6d`.

## Граница

После [контроля раунда](MATCH_ROUND.md) основной первый путь приходит в4229cc
с menu44d020=10, previous4512cc=0 и **music44d010=1**. Путь4229cc вызывает
429730 с прежними World/surface и указателями menu44d020/mode451160.
Настоящий пролог/SEH подготавливает локальные ссылки; в4297a6 вызывается402020
с исходным `bgm\main.wma`. Музыку нельзя выключать ради обхода этого вызова.

Изучен402020 с настоящими401d30/401c90/401da0/401f30 и возвратами.
Остановка4297ae находится **до** записи previous4512cc, инициализации11
menu bitmap и дальнейшего вызова431d10. Сама429730 ещё не вернулась.
Контрольная загрузка приходит в паузный вывод41d73b: контрольный вход4229cc
предоставлен явно. Это не выполненный паузный render и не непрерывный путь
его обхода. Основной вход продолжает тот же CPU/stack без замены состояния.

Возвращаемые значения message, notify, log-handle assignment, conversion,
CloseHandle и Run не управляют этой ветвью. Результат volume тоже игнорируется
вызывающим402020. Результаты COM и записи через выходные указатели являются
разными входами: отрицательный HRESULT не означает автоматически нулевой output.

У текущего имени нет восстановленного ограничения52байта: с44ef38 начинается
каталог, который длинное имя может перезаписать. В корпусе есть длины51/52/99,
пустые, нечётные, регистрозависимые и не-ASCII имена. Исходные байты не приводятся
к UTF-8 и не очищаются. Пересечения с неизвестной памятью остаются за границей.

У401da0 нет освобождения wide-path allocation ни при успехе, ни при ошибке.
Native сохраняет все выделения, backing и маски, включая частичную или отсутствующую
запись conversion. Это факт о данном пути; полный процессный lifetime ещё открыт.
Исходный new и Windows-преобразование кодировки остаются предоставленными границами.
Проверка с null allocator output не доказывает поведение настоящего new при OOM.

## Реализация и проверка

Позднейший [GRAPH_EVENTS](GRAPH_EVENTS.md) сравнивает371 полный callback400 и
четыре отдельных401c90. `OriginalMusicPlayback.initializeGraph` теперь общий
для этого производителя и прежнего play; `seekToStart` общий для stop и event1.
Пять уведомлений используют собственные результаты создания графа с четырьмя
исходно нулевыми слотами. Сохранены точный E_ABORT, live local outputs и порядок
освобождения параметров. Прежние музыкальные тесты проходят без изменения
эталонов. Это ещё не проверка слышимого зацикливания на настоящем устройстве.

`OriginalMusicPlayback` реализует общий запрос трека и условие menu prefix.
`OriginalMusicMemory` сохраняет выделения. Shared release401d30 и volume401f30
используются также прежним `OriginalMenuPresentation`; правила не дублируются.
Старые match music selection4025b0/4025d0 ещё не соединены с новым обработчиком.

`oracle_music_playback.py` воспроизводит и сверяет прежние loading/local/control/
replay/round родители, затем продолжает основной4229cc. Новые пробы изменяют
только объявленные globals/API-входы. Во всех пробах неизменность целых World/
400Actor, saved settings, replay pointers и двух буферов проверяется против
первого round snapshot. Проверяются реальные helper returns, ESP и nonvolatile
registers. Native получает собственный ранее проверенный parent state; сравнение
не загружает expected after-state в движок. После callback прежние2074 round,
1134 replay,2993 control,303 local и полный loading всё ещё проверяются.

Для каждой новой операции сравниваются все globals, весь список retained
allocations, каждый байт/маска буферов и полный порядок запросов. CRT format
сверяется с исполнением DLL. COM/Win32/allocator ответы являются воспроизводимыми
входами; отсутствующий output сохраняет прежнее слово, а не подменяется нулём.

Оба свежих полных захвата совпали со Swift до принятия fixtures:
374 случая на проход, всего748; 2 450 настоящих helper returns,11 912 событий,
438 allocation requests (436 ненулевых выделений),24 сообщения,438 CRT formats.
Каждый проход сравнивает32 575 записей и18 155 382 байта/маски; повторное
сравнение накопленных выделений не является процентом игрового покрытия.
20 последовательных запросов на проход сохраняют состояние между переключениями
и повторным запуском треков. Полные прежние native parents тоже сравниваются.
Отчёты: [основной](../evidence/music-playback.json) и
[контроль](../evidence/music-playback-control.json); в них SHA исходных и packed
корпусов,14 неизменных parent fixtures и вывод независимого сравнения.

Предварительно выполнены373 исходные пробы на каждом варианте backing с явно
предоставленным входом. Они выявили недостающий разрешённый format в CRT adapter,
остановку до return hook и запись API без маски; исправлен стенд, не after-state.
Ранние полные запуски остановлены; принятые оба захвата выполнены заново после
исправлений. Whole-instruction guard подключается только после проверки родителей,
сохраняя полную проверку нового участка без лишних callbacks во время загрузки.
Прежний MenuPresentation XCTest прошёл за138.633s. Оба новых XCTest прошли
за290.588s (145.694+144.894), включая полные семь native parents на проход.
Финальная release-сборка NTSDNative прошла за19.69s; окно приложения и
реальный музыкальный вывод этим запуском сборки не проверялись.

Воспроизведение после принятия корпуса:

```sh
uv run tools/oracle_music_playback.py
uv run tools/oracle_music_playback.py --control
uv run tools/oracle_music_playback.py --accept
swift test --package-path native --filter OriginalMusicPlaybackTests
swift test --package-path native --filter OriginalMenuPresentationTests
swift build --package-path native -c release --product NTSDNative
```

Нельзя одновременно запускать SwiftPM-команды с общим native/.build.
Старые fixtures и исходные ресурсы не обновляются этим этапом.

## Осталось

Полный DirectShow/codec/file API, настоящее музыкальное воспроизведение и его
задержка на Windows/macOS не проверены. Нулевые обязательные COM-интерфейсы,
переполнение260-byte log buffer, недопустимые указатели и произвольные пересечения
памяти не заменяются удачным возвратом: native сообщает неподдержанную границу.

Следом —11 bitmap и таблицы menu4297ae..429e5a, затем настоящее тело431d10;
паузные render helpers41d73b и gameplay41e339 остаются отдельными продолжениями.
Этот этап ещё не подключён к Practice и не доказывает полный матч, музыкальный
вывод, воспроизводимый запуск Windows или проверку на чистой macOS.

Статические ориентиры следующего участка: CHARMENU705×487; CM1..5 по51×58;
CMA/CMA2 по120×66; CMC365×103; RFACE120×120; SPARK612×256. Это встроенные DIB
исходного PE, не новые изображения и не пути в файловой системе. Guard44d07c
проверяет любое ненулевое значение; все11 allocations имеют размер1f50.
Последний SPARK сохраняется в44f8fc, после чего429b21 безусловно разыменовывает
его для записи+0c=20. Поэтому null allocation последнего ресурса нельзя считать
таким же безопасным продолжением, как null wrappers начальной загрузки.
Дальнейшие прямоугольники изменяют только часть существующих записей SPARK;
их перенос должен сохранить остальные байты конструктора. Эти ориентиры имеют
уровень S; динамическая проверка и нативный перенос menu resources ещё открыты.

Последующий [этап ресурсов меню](MENU_RESOURCES.md) теперь отдельно проверяет
этот участок против Swift после двух свежих loading/input/round/music цепочек:
374 случая,2098 настоящих43ee50, полные bitmap bytes/masks и null-SPARK boundary.
Исторический музыкальный корпус сохраняет остановку4297ae и прежние fixtures;
новый корпус заканчивается429e5a до dispatch/431d10 и не доказывает вывод звука
или изображения.
