and a per-attempt batch of resolved commands for the native renderer. The finite
Native comparison and independent contract reviews passed. Results and remaining
application boundaries are recorded below.

## Contract

Display resources originate in actual Native window API requests and declared
outputs. Primary, backbuffer and clipper associations retain their creating
requests, masks and generations. A Release result remains an observed request;
it neither proves destruction nor erases a retained global reference. A palette
token from a declared input remains opaque until its entries are recovered.
The resource's clipper, palette, color-key and format fields hold the last
requested metadata and its numeric reply, including failures. They do not
establish a successful device association or conversion.

Each graphics command keeps the actual request and reply, source/destination
ownership and available source-color snapshot. Existing bitmap clipping and
mirror calculations remain the producer of the rectangles. All 491 saved
downstream Blt and 18 NULL-source occurrences keep their exact boundaries.
The 109 recorded presentation requests contain an explicit destination rectangle
of 16 zero bytes and a NULL source rectangle. Neither becomes an inferred
backbuffer-sized rectangle.

Bitmap copying continues only for GetDC exactly zero. Library text continues
for every nonnegative GetDC and can pass a declared DC of zero to GDI. Each
nonnegative text acquisition gets its own generation. A failed ReleaseDC stays
attached to that generation when a later acquisition returns the same token;
the new acquisition does not repair the old failure. TextOut and cleanup replies
remain ignored by the recovered caller, but are retained in the command.
The later Session graphics effect must therefore carry its actual numeric reply,
as the startup graphics effect already does.

`OriginalApplicationGraphics` resolves the actual Bootstrap window calls and
terminal Session effects. Bitmap requests refer to their own image and display
creators and to the existing bitmap-input DC generations. The source-color
snapshot is a value owned at the drawing command's emission. This resolved
graphics batch is another view of the same terminal operations; a backend must
not deliver it in addition to the original effects as a second set of draws.
Bootstrap always constructs the owner. Legacy isolated test states can omit it;
the complete 48/50/12 comparisons require the Bootstrap-produced owner.

The owner and command batch are staged with their whole caller. A late observer
or handoff failure publishes neither. A pending loading boundary retains tentative
commands separately from the last committed session. Existing loading-prefix
tests compose the same consumer with their retained production loading helper;
that composition alone does not provide a full production loading session.

Successful text cleanup removes its acquisition from committed state. The
returned commands retain its generation, while the state keeps a monotonic
generation counter and unresolved leases. Each new text GetDC starts a fresh
command sequence: a negative result cannot authorize GDI through a previous
failed acquisition. That earlier lease and the library's retained DC still remain.

## Open pixel and application dependencies

Source RGB is not an indexed DirectDraw framebuffer. Fullscreen requests 8 bits
per pixel; windowed startup does not set a mode. The controlled primary format
query does not establish offscreen conversion. Palette entries, actual color-key
conversion, clipper/device effects and text font/glyph/codepage/DPI inputs remain
unresolved. The original 146,289 unknown DIB positions remain unknown.

No complete framebuffer, real presentation, AppKit input/audio, Windows run or
clean-Mac acceptance follows from a resolved command batch. Full loading/catalog,
War gameplay, the first complete match and the full game remain open. All three
safety incidents remain open; this independent work does not retry their paths.
