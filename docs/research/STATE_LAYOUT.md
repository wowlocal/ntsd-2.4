# R02.1 — состояние и инициализация

Эталон: EXE SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
**Частичный результат R02.1.** Конструкторы Actor/World проверены отдельно;
инициализация целого матча, каталог и полный словарь типов ещё не восстановлены.
Исходные байты неизвестных полей сохраняются, но это не раскрывает их назначение.
Следующий проверенный результат — [BOOTSTRAP.md](BOOTSTRAP.md): загрузочный пул
400 Actor с повторной инициализацией восьми слотов, нормализованные ссылки и
статические границы всей аллокации каталога. Это отдельно от появления игроков.
Затем проверен [родительский проход каталога](CATALOG_REGISTRY.md): разреженные
записи, порядок реестра и обращения к ещё не исполняемым дочерним загрузчикам.
Он также не является инициализацией выбранного матча.
Отдельный [Object loader](OBJECT_LOADER.md) теперь сохраняет настоящую загрузку
объявленных целых файлов и сравнивает её с native Core. Прежний сырой снимок
такта ниже по-прежнему использует синтетическую загрузку; его границы не изменены.
[BACKGROUND_LOADER.md](BACKGROUND_LOADER.md) добавляет точные записи/маски всех
17 BG и отдельный жизненный цикл слоёв. [STAGE_LOADER.md](STAGE_LOADER.md)
добавляет весь исходный Stage-файл и маски всех 60 записей таблицы. Эти отдельные
загрузчики ещё не соединены в полный каталог.

## Конструкторы: установленные записи

S: Actor `0x4061d0..0x4064cc`, World `0x419e40..0x419e5f`.
D: [oracle_state.py](../../tools/oracle_state.py) исполняет обе функции через
возврат на четырёх шаблонах памяти (`00`, `a5`, `ff`, последовательность байтов)
по двум адресам. Единственная подмена — `memset` в `0x4450a0`; её записи включены
в маску с адресом возврата вызывающего кода. Проверяются защитные байты до/после
области и сохранение каждого нетронутого байта.

[Отчёт](../evidence/state-constructors.json) хранит адреса и байты всех записей,
включая повторные, и SHA-256 полного корпуса. Swift
[OriginalStateRecord](../../native/Sources/NTSDCore/OriginalStateRecord.swift)
совпал во всех **16 случаях: 24 512 байт и столько же флагов инициализации**.
Это проверка конструкторов, не запуска матча или появления объекта.

### Actor

Аллокация — **0x420 / 1056 байт**: `0x41c070` передаёт размер в `operator new`
по `0x41c075`; конструктор вызывается в `0x41c091`. Шаг `0x500` между Actor
в стенде не является размером структуры оригинала.

Конструктор записывает **913 байт**, оставляет **143 байта** нетронутыми.
Все диапазоны далее полуоткрытые: последний адрес не включён.

| Область | Конечное значение конструктора / представление |
| --- | --- |
| `+0x28,30,38,40,48,50` | По 8 байт: binary64 `0x3fb999999999999a` (0.1), из `0x447920` через x87 |
| `+0x58,60,68` | По 8 байт: положительный binary64-ноль |
| `+0x2e8,2ec,2f0` | По 4 байта: 1000; `2e8` сначала получает 0, затем 1000 |
| `+0x2f4,2f8,324,328,32c,33c,360,3f8` | По 4 байта: `ffffffff`; знаковое представление -1 |
| `+0x2fc,300,304,308` | По 4 байта: 500 |
| `+0x354` | 4 байта: 99 |
| `+0x3fc,400` | По 4 байта: `fffffc18`; знаковое представление -1000 |
| `+0x24..<28`, `81..<84`, `bd..<be`, `dd..<e0`, `31c..<320`, `368..<36c`, `370..<3e8`, `41c..<420` | **Нет записей**. Нельзя считать все эти области padding или нулевыми полями |
| Остальные байты `+0..<420` | Записывается ноль; ширина и адрес каждой операции — в отчёте |

Конструктор возвращается с EAX=-1000; это остаток инструкции, не указатель
`this`. Swift переносит состояние памяти, а не регистровую оболочку вызова.
После конструктора исходный цикл `0x41c096..0x41c0c1` отдельно задаёт координаты,
Object* в `+0x368`, указатель слота World и активность 0. Это ещё не все пути
появления. Нейтральные позиции/нулевые скорости старого стенда и `FighterState()`
— условия практики, **не** значения исходного конструктора или нового матча.

### World

Статический адрес обычного World — `0x458b00`. Инициализатор `0x446300`
передаёт его в ECX и прыгает в конструктор через `0x446305` (S; полный CRT-startup
здесь не исполнялся). D проверяет сам конструктор на тестовых адресах.

| Смещение | Размер / назначение | Инициализация |
| --- | --- | --- |
| `+0` | 4 байта, селектор диспетчера | Конструктор пишет 0 в `0x419e4e` |
| `+4` | 400 байт активности слотов | `memset(...,0,400)` в `0x419e54` |
| `+0x194` | 400 указателей Actor, **4 байта** каждый | Конструктор не пишет; цикл матча заполняет отдельно |
| `+0x7d4` | 4-байтный указатель каталога | Конструктор не пишет; назначается при загрузке |

Известный префикс заканчивается на `+0x7d8` (2008 байт). Его размер **не доказывает
sizeof(World)**. Конструктор записывает только 404 байта. PE-загрузчик отдельно
задаёт содержимое статической памяти/BSS; BSS-ноль не является доказательством
окончательного значения при начале боя.

## Поля практики и их исходное хранение

Таблица сопоставляет **все поля FighterState и его подмножества MovementState**.
Смысл и числовые операции проверены только в областях
[движения](../MOVEMENT.md), [боя](../COMBAT.md), [снарядов](../PROJECTILES.md).
`Int32` ниже обозначает используемый знаковый вид 4 байт; это не доказательство,
что все ещё неизвестные читатели поля всегда применяют ту же знаковость.
Swift `Int` в практике шире исходного dword; общая реализация должна сохранять
конкретные исходные операции переполнения и преобразования.

| Swift / смысл | Исходное место и вид | Читающие/меняющие стадии; дальнейшая работа |
| --- | --- | --- |
| `phase, tap` | Actor `+0,+4`, Int32 | `413080`, движение/ввод R04/R05 |
| `ix, iy, iz` | `+10,+14,+18`, Int32 | `40e490`, преобразования координат и геометрия R05/R07 |
| `frame, previousFrame, collisionFrame` | `+70,+74,+7c`, Int32 | Управление, физика, контакты, `40d960`; не сливать разные кадры |
| `wait` | `+88`, Int32 | Планировщик `40d960` R05 |
| `hitVX, hitVY, hitVZ` | `+28,+30,+38`, binary64 | Разрешение попаданий `42e100`, применение `4196f0` после рисунка R08 |
| `vx, vy, vz` | `+40,+48,+50`, binary64 | Управление/физика R05 |
| `x, y, z` | `+58,+60,+68`, binary64 | Физика, ограничения, связанные объекты R05/R09 |
| `facing` | `+80`, 1 байт | Управление и отражение спрайта; не читать как dword с соседними нетронутыми байтами |
| `attackBuffer, jumpBuffer, defendBuffer, defendCooldown` | `+be,+bf,+c0,+c1`, по 1 байту | `413080` и приоритеты R04; хранить исходные байты, включая знаковые операции |
| `rightBuffer, leftBuffer, upBuffer, downBuffer` | `+c2,+c3,+c4,+c5`, по 1 байту | `413080`, двойное нажатие/комбо R04 |
| `combos[0..<9]` | `+d4..<dd`, 9 байт | Распознавание/переходы R04; старый JSON снимок не доказывает семантику всех значений |
| `fall, freeze, guardDamage` | `+b0,+b4,+b8`, Int32 | Бой, hitstop, восстановление R05/R08/R10 |
| `rest, vrest` | `+ec`, Int32; `+f0..<280`, 400 знаковых байтов | Контакты/сроки повторного попадания R07/R08. Два элемента старого melee — ограничение снимка |
| `superPunch` | `+ea`, 1 байт | Бой/приоритеты R04/R08 |
| `hp, redHP, mp` | `+2fc,+300,+308`, Int32 | Урон/стоимость/восстановление R08/R10; исходные стадии R01.1 шире практики |
| `hitCount, fallHurt, invulnerability` | `+20,+320,+8`, Int32 | Реакции/защита/время жизни R08/R10 |
| `damageDealt, damageReceived, kills` | `+348,+34c,+358`, Int32 | Статистика/урон/завершение R08/R10/R15 |
| `cameraX, cameraVelocity` | Globals `450bc4,450bc8`, 4 байта | `41b5d0`; общие для мира, копии в FighterState — формат старого снимка |
| `renderFrame, renderFacing, renderX, renderY, renderZ` | Снятые перед планировщиком `frame,facing,ix,iy,iz` | Производная поза вывода R13; отдельных Actor-полей для этих копий не установлено |
| `sounds` | Список событий стенда/нативного аудиовыхода | Производный вывод вызовов `416fb0/417090`; не полный DirectSound state R14 |

Прочее состояние нативного ядра:

- `OriginalFighter.previousInput/currentInput`, `OriginalMovement.previousInput`
  и `OriginalMelee.currentInputs` — упакованные маски стенда. У Actor есть две
  последовательности входных байтов `+c6..<cd` и `+cd..<d4`; исходные фазы и
  источники ввода ещё требуют R04. Это не перенос полного глобального ввода.
- `OriginalFighter.mpSpent` и `MeleeState.mpSpent` соответствуют Actor `+350`;
  `ProjectileState.owner/team` — `+354/+364`. `slot` — индекс World, `id` —
  Object `+6f4` через Actor `+368`, `motion` — тот же набор полей Actor.
- `MeleeState.actors/projectiles` и `OriginalMelee.fighters/objects` — разделённые
  контейнеры практики. Оригинал использует общий пул 400 Actor. `draws`,
  `projectileDraws`, `ProjectilePose` — производные снимки поз и порядка рисунка.
- `OriginalRandom.table/index/counter` — `44ff90` (3000 байт), `450bcc`, `450c34`
  (по 4 байта), функция `417170`. `source/sourceSHA256` — происхождение фикстуры,
  не поля игры. Копии RNG в MeleeState — формат сравнения.
- `localPlayer` — выбранный игрок практики; не прямой перенос всех восьми
  входных слотов `450b4c`. `enablesChidoriNeedles` — ограничитель прототипа,
  не поле оригинала. Их нельзя переносить в общий движок как правила персонажа.
- `frames`, `parameters`, `voices`, `projectileCatalog`, `ProjectileDefinition`
  и `OriginalBackgroundLayer.fields` — загруженные определения/частичные
  каталоги. `OriginalFrameRecord` сопоставлен отдельно в
  [FRAME_LOADER.md](../FRAME_LOADER.md); целые Object/Catalog — R03.1.
- `OriginalMovement.width/zMin/zMax` — параметры текущей арены, взятые из DAT.
  `OriginalBackgroundLayer.counter` — dword каталога
  `+4d465d4 + arena*990 + layer*4`: чтение/знаковый остаток/запись
  `41a34c..41a35a` (S, D результата District в прежнем корпусе). Инициализация
  всего массива ещё требует внешнего загрузчика R03/R13.
- `OriginalClock.baseline` — UInt32 времени, исходно сохраняемое в ESI внешнего
  цикла (`43d157`), не поле Actor. Optional/reset — оболочка нативного запуска.
- `OriginalStateRecord.bytes/defined` — новая схема хранения/происхождения,
  не дополнительные игровые поля. При чтении используются явные UInt8/Int8,
  UInt16/Int16, UInt32/Int32 или raw binary64; нет преобразования указателей
  оригинала в адреса Swift. Эта схема пока не подключена к игровому циклу.

## Object, каталог и globals

Object выделяется по `0x25360` байт в `0x412660..0x412695`, затем вызывается
`0x40ef70`. Известны ID/type `+6f4/+6f8`, параметры движения в начале записи,
400 кадров `+7a4 + n*178`, указатели/числа боксов и звук в кадрах. Снимок хранит
весь Object, включая заголовок, нетронутые поля и хвост после кадров. Полный
внешний загрузчик не исполняется стендом сырого такта. В отдельном
[oracle_objects.py](../../tools/oracle_objects.py) он теперь выполняется целиком
для Naruto/Sasuke/kunai и контроля; фактическое происхождение заголовков и bitmap
установлено для этих случаев. Состояние всего каталога/матча пока не получено.

Каталог выделяется по `0x4d823a8` (`41bfeb..41bff0`), конструктор/загрузка —
`4122f0`. Основные границы теперь восстановлены статически в
[BOOTSTRAP.md](BOOTSTRAP.md): таблица объектов, 60 областей стадий, 101 запись
фона и хвост. Это не раскрывает все поля/правила загрузки. В сыром снимке
сейчас сохранены таблица пяти загруженных объектов, известная
область арены и последующие отображённые поля; **огромный промежуток не отображён
в стенде**, явно перечислен в `catalogHoles`. Это основная открытая часть R02/R03.

В отдельном BG-стенде все 101 × 0x990 байт таблицы отображены с backing/масками.
Для всех 17 исходных арен и ordinal 98 контроля проверены чтение DAT `40c160`,
загрузка bitmap слоёв `40c030` и освобождение `40c0e0`. Поля и источники значений:
[BACKGROUND_LOADER.md](BACKGROUND_LOADER.md). Последний release оставляет старые
указатели во всех layer slots, кроме первого; это не null и не живые объекты.
Shadow bitmap не освобождается этими функциями. Нетронутые поля и их маски
сохраняются при повторном parse. Нормализация строго index+1 с 0=null.

В [Stage-стенде](STAGE_LOADER.md) отображён весь участок `7d0..<4d45db0`:
60 × `149b08` = 81 024 480 байт. Все 60 конечных записей сравниваются с Swift,
как и выбранная стадия после каждого initializer/phase. При первом stage-level
ID определены 288 904 байта записи: 100 фаз / 6000 наборов полей. В отсутствующей
стадии записывается только count=-1 в +0; +4 остаётся нетронутым. Music +c,
entry fields +ec+n*e0 и phase goto +34c0 сохраняются как байты, без выдуманного
sizeof(entry) или нормализации чисел в указатели. Повторная загрузка сохраняет
нетронутое прежнее состояние/его маски. Этот результат не заменяет синтетическую
загрузку старого tick-trace автоматически.

## Снимок: что сохраняется и что пока неизвестно

[oracle_state_trace.py](../../tools/oracle_state_trace.py) повторяет шесть случаев
R01.1, снимает начальное состояние и состояние после каждого наблюдения:
**38 снимков**, по 409 областей / 1 538 892 байта. Сохраняются:

- все 400 выделенных Actor по 0x420, независимо от активности;
- пять загруженных Object по 0x25360, используемый префикс heap, доступные
  области каталога;
- вся PE `.data` по `0x44d000`, размер `0xc724`, включая World и неизвестные globals.

Байты хранятся hex-блоками по SHA-256, со ссылками из снимков; это устраняет
дублирование, **не** выбрасывает неизвестные поля. После записи корпуса проверяются
хеши и размеры всех блоков. Float не проходит через десятичный JSON: сохраняются
биты, включая signed zero, subnormal и payload NaN.

У подтверждённых pointer-полей отдельно указаны исходные биты и ссылка
`region + offset`: World → Actor/Catalog, Actor → Object, каталог → Object,
живые itr/bdy и звуковые пути кадров. Идентичность объекта — индекс записи
стенда, не уникальность ID. При нулевом count указатель боксов не интерпретируется.
Остальные байты остаются непрозрачными: произвольный dword не объявляется
указателем лишь из-за похожего адреса. **Это ещё не полная нормализация состояния
между разными размещениями памяти.**

У снимка после инициализации пока **нет полной маски происхождения**: исходные
конструкторы, ручные настройки стенда и BSS различаются в описании, но ещё не
прослежены побайтно на всём жизненном цикле. Отдельный корпус конструкторов такую
маску имеет. В наблюдавшихся Actor-чтениях единственная область, не записанная
конструктором, — Object* `+368`, назначенная стендом. Это не разрешение игнорировать
прочие нетронутые области в новых сценариях.

Снимок не включает stack/регистры, неизменяемые секции EXE, состояния устройств
и внешние структуры Python. Инвентарь обращений не видит host-записи CRT/платформенных
подмен. Новая аллокация за пределом объявленного heap останавливает стенд, чтобы
он не выдавал усечённый снимок за полный. Границы ОС, частичная загрузка DAT и
отключённый звук унаследованы из [R01.1](TICK_PIPELINE.md).

Конечные выбранные поля совпали с сохранённым отчётом R01.1. Побайтовый снимок
также сохраняет известное расхождение с прежним конвейером: через 12 тактов
RNG counter=12, HP=401, MP=107; старый конвейер даёт 0/400/100. Полный такт
с нативным движком пока не сравнивается, Windows W остаётся открытой.

## Воспроизведение и ближайшая работа

```bash
uv run tools/oracle_state.py
uv run tools/oracle_state_trace.py
swift test --package-path native
```

Для state-trace нужен прежний импорт `build/imported/game.json`; его создаёт
`python3 tools/import_ntsd.py`. Полные корпуса остаются в `build/original/`,
краткие доказательства — в `docs/evidence/`; конструкторный корпус также сохранён
для автономных Swift-тестов.

Загрузочный пул уже проверен отдельно в [BOOTSTRAP.md](BOOTSTRAP.md).
Следующее: R02.1 — исходная инициализация каталога, происхождение всех
прочитанных полей и оставшиеся связи/типы; R03.1 — загрузка целых объектов;
после них R01.2 — снимки по проходам и общий нативный такт. Новые конструкторы
не меняют доступный объём игровой практики и не закрывают R02 целиком.
