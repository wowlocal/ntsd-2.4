# Own application menu session

The production menu session is verified in its finite scope. It owns repeated
menu iterations and an explicit loading entry; app integration and the complete
game remain open.

The new production `OriginalApplicationMenuSession` composes the already
recovered message loop, delivered WindowInput callback, dispatcher, front menu,
main selection, presentation, RNG and resource release. Its finite evidence is
the saved APPLICATION_MENU_INPUT corpus: 50 chains, 47 idle repeats and three
activation chains, 62 completed iterations and three pending loading entries.
All parents are rebuilt through Native, not imported from expected after-state.
The work advances the own application loop toward its eventual AppKit join;
bootstrap and reference comparison adapters still live in the test target.

The pinned EXE remains 3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c.
Historical Unicorn2.1.4 observations use controlled COM/Win32 replies and the
installed library. Current work reads saved bytes and executes Native only.

## Owned state and aliases

The session's single full record preserves bytes AND defined masks throughout
0x44d000..0x4593a8. The outer prefix at0x458440 overlaps World at0x458b00;
local fields and World are not independent mutable copies. The allocator's
replay words at0x4588a8/0x4588ac must match their full-record aliases on entry,
including unknown masks. Updates merge them exactly. The loop owns counter
0x458580; a complete iteration merges its increment before publication.

The old bootstrap OwnContext is only a Native-parent/diagnostic bridge. Its
known extended region derives from independently initialized PE-backed parent
storage and Native dispatch writes. That selected provenance is now asserted
explicitly; source store masks keep their different meaning. Public Core never
supplies an all-true mask to imported bytes. A Native-only control retains an
unread unknown sentinel and unknown replay-pointer backing through a message
iteration.

Menu constructor records and raw CreateSurface tokens transfer once into the
current allocation registry. Constructor views remain historical. Missing or
dead current owners are rejected even if an old front/background snapshot is
present. An independent callback registry tracks same-call frees while the
presentation helper borrows its memory, avoiding overlapping Swift access.
The authoritative committed memory retains all dead bytes and masks.

## Transactions and loading

Reply callbacks inspect declared/staged input; observational callbacks never
perform host IO. The session returns a typed Committed batch only after the
whole loop iteration succeeds. A thrown observer, reply or beforeCommit error
returns no batch and preserves prior state, MSG, counter, timer, RNG, library DC,
bitmap owners and completed iterations.

The batch contains terminal operations: Blt/fill/clear, sound methods,
Release/presentation, GDI, free and Translate/Sleep as applicable. Helper
entries such as draw/text/soundRequest and reads/stores are observations only,
so a backend does not execute a helper and its terminal output twice. Sound
and Release keep their separately declared ignored HRESULTs, including -1;
GetDC records its declared result/output rather than silently dropping them.
This is a staged request contract, not hardware rendering/audio validation.

PendingLoading carries staged game state, own target and a separately named
uncommitted effects array. It leaves the committed session/loop unchanged.
The caller's tentative timer path has not returned, so this snapshot is neither
a completed loading result nor a general resume/commit token. The retained
loading-prefix comparator receives every semantic field through a Native-only
bridge. It continues the already accepted child while preserving the parent.

Network/worker/settings/resource and other missing operations remain named
boundaries. Unused zero input fields cannot authorize their execution: the
first unsupported request/continuation throws before a reply is consumed.
Missing queue replies are rejected except the two explicitly declared adapter
cases Translate and own DispatchMessage. Non-retrieval MSG writes are rejected
before the own callback overrides DispatchMessage's numeric response.
