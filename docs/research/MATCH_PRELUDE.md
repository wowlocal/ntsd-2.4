# R02.1 — пролог подтверждённого запуска матча

Эталон EXE SHA-256:
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
DLL MSVCR80 8.0.50727.6195 SHA-256:
`c3ac989c8489a23bb96400b1856f5325ffc67e844f04651ea5d61bc20a991c6d`.

Перенесён и сравнен с оригиналом участок **`42cf8a..42d1ff`**, который предшествует
[общей подготовке](MATCH_PREPARATION.md) и [созданию записи](REPLAY_INITIALIZATION.md).
Нативная реализация — [OriginalMatchPrelude](../../native/Sources/NTSDCore/OriginalMatchPrelude.swift).
Новый storage по-прежнему не подключён к Practice; это ещё не весь запуск матча.

## Граница и происхождение входов

В настоящем вызывающем коде `4229d0/4229d5/4229dd` функция меню `429730`
получает указатель режима **`451160`** третьим аргументом и указатель состояния
меню **`44d020`** вторым. В её прологе они сохраняются в локальных `esp+1c`
и `esp+40`; World — в `esp+14`. Это статически установленное связывание,
которое новый стенд использует вместо прежнего отдельного указателя режима.
`World+0` остаётся самостоятельным полем; подменять его значением `44d020` нельзя.

На входе `42cf8a` EDI равен нулю после `42cf67`, ESI указывает на режим.
Решение о входе в эту ветвь и более ранние действия UI пока заданы границей.
GetLocalTime получает явно заданные восемь UInt16 SYSTEMTIME. В corpus есть
обычная дата и числовые контроли с годом 7, нулевыми и максимальными полями;
последние не заявляются как допустимые даты Windows.

[oracle_match_prelude.py](../../tools/oracle_match_prelude.py) восстанавливает
проверенный полный каталог, исполняет World/bootstrap и далее 25 последовательных
цепочек **пролог → подготовка → запись до `42d704`**. Между сценариями сохраняется
реальный результат предыдущего запуска, включая сброс счётчика RNG. Два corpus
используют a5/ramp backing для World/Actor. Входы меню, RNG, metadata повтора,
аллокаторов и устройств остаются перечисленными стимулами.

[MatchPreludeReference](../../native/Sources/NTSDReferenceChecks/MatchPreludeReference.swift)
сначала проверяет полную нативную загрузку каталога и bootstrap. После записанных
входных стимулов выполняет нативный пролог, затем прежние общие проверки
подготовки/записи. Ожидаемые снимки не используются для инициализации следующего
состояния. Старые fixtures подготовки и записи сохраняют прежние границы.

## Подтверждённые инструкции

| Участок | Поведение |
| --- | --- |
| `42cf8a/42cf90` | Обнулить `450bb0/450bb4` для любого режима |
| `42cf96..42d042` | Только mode=1: `450b9c=70`; обнулить `450ba8/450bac/450ba4/44d028/450ba0/450bc8/450bc4`; записать -1 в `44fb6c/44f880` |
| `42cfc8..42d01f` | Только **точные** stage 0,10,20,30,40,50 выбирают BG 1,2,3,4,5,6; остальные сохраняют прежний BG |
| `42d048..42d056` | Обнулить поле по второму аргументу (`44d020`), запросить GetLocalTime |
| `42d0a5` | `sprintf("%4d%02d%02d_%02d%02d%02d", year,month,day,hour,minute,second)`; dayOfWeek/milliseconds не участвуют |
| `42d0b3..42d178` | Для mode=1: signed Int32 stage/10 с усечением к нулю; если результат <5, добавить `_Stage_` и результат+1, иначе `_Survival` |
| `42d17c..42d19f` | Для mode=0 добавить `_VS`; прочие режимы не добавляют этот суффикс |
| `42d1b3` | `sprintf(44fd98, "%s.lfr", name)`; записать строку и NUL, сохранить последующие байты |
| `42d1b8..42d1c6` | Обнулить `450b6c`; если `450be4!=0`, установить `450b70=1`, иначе сохранить его |
| `42d1d0..42d1ff` | Если `450b98!=0`, очистить прямоугольник и обнулить флаг; иначе вызвать `401a30(455610,0)` |

Формат `%4d` дополняет год **пробелами**, а не нулями. Все ширины минимальные:
UInt16 65535 сохраняет пять цифр. Для отрицательной стадии -11 получается
`_Stage_0`; -9 даёт `_Stage_1`. Это числовые проверки исходного кода, а не новые
пункты меню. Поддержка общая, без проверок имени персонажа.

## CRT и устройства

Все три формата исполняются через настоящий экспорт **sprintf `7817775d`**
из закреплённого MSVCR80 в отдельной исследовательской VM. У `CRT.format`
проверяются возвращённая длина, все записанные байты/маски до NUL и сохранность
оставшегося буфера/защитных областей. Используются прежние PTD/C-locale/lock
границы [исследования CRT](CRT_SCANNER.md). Это не реализация sprintf на Python
и не доказательство общего printf/locale. Фактический выбор DLL Windows пока
не наблюдался; происхождение и publisher policy описаны в исследовании CRT.

Звуковой helper **`401a30..401a6f`** исполняется целиком. При нулевом
`44eecc` или нулевом `[455610]` он не вызывает устройство. `44eecc` — указатель
аудиоустройства, а не пользовательский Boolean setting: статически `401970`
передаёт его адрес DSOUND ordinal 1 через `43f384`, затем `40198f..4019a1`
разыменовывает его vtable; `401a14..401a1c` освобождает и обнуляет. В прологе
проверяется только ненулевое значение. Иначе helper вызывает
методы vtable **+48, +34, +30**: аргументы после `this` соответственно `[]`,
`[0]`, `[0,0,0]`. Все три вызова происходят и при ошибочном HRESULT первого
или второго. Здесь проверен только передаваемый прологом loop=0.

Очистка исполняет **`415160..4151c2`** до vtable+14 поверхности `[455608]`:
прямоугольник `(0,0)..(794,550)`, нулевые source/sourceRect, flags `0x1000400`,
размер effects 100 и fill color 0. Остальные поля stack effects не инициализируются
helper; стенд не выдаёт их за нули и не использует как параметры заливки.
Возвращаемый HRESULT в этой ветви также не меняет дальнейшие сбросы.

В каждой последовательности устройства возвращают 0 либо `0x80004005`.
Идентификаторы `[455608]/[455610]` — явно заданные opaque handles; native никогда
не разыменовывает их как адреса macOS. В исследовательском EXE это адреса
предоставленных COM-объектов. Статически найден источник звука подтверждения:
`43d0c4/43d0c9/43d0ce` передают **`data\m_ok.wav`** (строка `44a11c`) в
`4014e0` с `this=455610`. Исполнение его загрузки, вывод пикселей и звука
остаются открытыми. `44eecc` и выключенный DirectShow `44d010` — разные
границы, смешивать звуковой helper с восстановлением музыки нельзя.

## Проверка и воспроизведение

Эталонные [a5](../evidence/match-prelude.json) и
[ramp](../evidence/match-prelude-ramp.json) содержат 50 сценариев: старт
Naruto/Sasuke на District, повторный старт, шесть точных Stage-переключений,
промежуточные/отрицательные/предельные стадии, mode 0/1/2/-1/Int32.min/Int32.max,
нулевые/ненулевые флаги и обе ветви устройства. В них 130 реальных вызовов CRT,
60 звуковых методов и 10 заливок.

Сравниваются все 46144 global bytes и маски до/после каждого пролога —
**4 614 400 байт/масок**, имя файла и порядок событий. Проверяется, что пролог
не изменил World/Actor/BG/RNG. Затем совпали полные состояния подготовки и
ресурсы — **77 300 записей / 115 871 104 байт/масок**, и 50 буферов записи —
ещё **324 583 600 байт/масок** только в буферах, 50 выделений и 50 освобождений.
Результат нативного сравнения и хеши принятых fixtures находятся в evidence.

Проверка release прошла до принятия обоих fixtures. Затем весь `swift test`:
**33 теста, 0 ошибок, 634.646 с**; новая проверка цепочек заняла 114.310 с.
Повторное исполнение прежних a5-стендов подготовки и записи после добавления
необязательного пролога воспроизвело все их 25+25 исторических случаев точно:
снимки/маски, вызовы, bootstrap/cleanup и инвентари обращений инструкций.

```sh
uv run tools/oracle_match_prelude.py
uv run tools/oracle_match_prelude.py --ramp
uv run tools/oracle_match_prelude.py --accept
swift test --package-path native
```

Нужен ранее полученный `build/original/loaded-catalog.json` с хешем из evidence
полного каталога. `--accept` сначала сравнивает обе новые упакованные записи
нативно и только при успехе сохраняет fixtures. SwiftPM выполнять последовательно.
