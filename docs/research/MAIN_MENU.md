# R02.1/R15 — мышь, пять пунктов меню и подготовка сервера

Эталон EXE: SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Этот этап восстанавливает происхождение mouse globals и решений раннего
меню, от которых зависит в том числе расход CRT RNG. Нативный результат
передаётся в уже проверенную подготовку матча и создание записи повтора.
Это ещё не полный поток экранов и не подключение нового запуска к Practice.

## Проверенные участки и границы

Позднейший [NETWORK_NOTIFICATION](NETWORK_NOTIFICATION.md) сравнивает415 целых
callbacks401/402ec0, серверный accept, три исходных пакета и обработку короткого
recv. Прежний menu/network-init корпус сохраняется неизменным. Прослушивающий
socket и names/RNG там объявлены на входе; полного menu→listen→accept соединения
и реального обмена двух экземпляров эти отдельные проверки ещё не доказывают.

Позднейший [NETWORK_CLIENT](NETWORK_CLIENT.md) добавляет392 полных действий
428420 и парный FIFO обмен собственными пакетами клиента и сервера. Настоящий
пролог даёт EBP19, но промежуточный экран ввода до подключения пока пропущен
в явно объявленном ABI. Полный возврат меню и Windows/TCP delivery открыты.

[NETWORK_EXIT](NETWORK_EXIT.md) теперь сравнивает56 полных возвратов402d70,
включая собственный client→exit и повторную очистку. Его cancel-caller427f6b
ещё требует полного соединения с экраном, звуком и освобождением фона.

[MENU_CHARACTER](MENU_CHARACTER.md) добавляет10492 целых вызова422f60: AL и
порядок Shift/GetKeyState совпали. Caller428371 sign-extends AL; API-dependent
high EAX не является native контрактом. Полный300-key hostname scan, его
собственная строка и menu1/2/3 остаются в [NETWORK_MENU_PLAN](NETWORK_MENU_PLAN.md).
Существующий World prefix0x7d8 не доказывает инициализацию hostname за ним.

| Участок оригинала | Исполнение и граница |
| --- | --- |
| WndProc `43b3d0`, сообщения `200..205` | Настоящие dispatch/jump table, записи globals, вызов DefWindowProcA и `ret16`; результат ОС задан явно |
| Меню `427915..427ca7` | Все пять пунктов, отсутствие выбора, границы и подтверждение; до общих входов `42873e` или `4287de` |
| Генератор `422ac0..422af7` | Настоящие вызовы из меню, настоящий CRT rand и сохранение общего PTD state |
| Звук `401a30..401a6f` | Настоящий helper до COM, включая нулевые ресурсы и ошибочный HRESULT |
| Сетевой init `402b60..402d63` | Целая функция, helpers `402ad0/402a60`, настоящий sprintf `%s`; результаты WSOCK32/API предоставлены |
| Панель `423b00` | Реальные null/empty пути до `4242b2`; непустая панель остаётся за границей |
| Bitmap `43f010` | Только упорядоченный запрос с this и всеми шестью аргументами; helper/пиксели здесь не исполняются |

Границы WSOCK32 фиксируются по IAT и исходным trampoline; это не исполнение
сетевой DLL или реальное соединение. UI/device/allocator и metadata boundaries
предыдущих звеньев сохраняются. MSVCR80 .6195 и её происхождение описаны в
[CRT_SCANNER.md](CRT_SCANNER.md); Windows assembly binding остаётся открытым.
Ни EXE, ни DLL, ни Unicorn не входят в runtime нативного приложения.

## Ввод мыши

WndProc читает message из stack+8, wParam из+0c, lParam из+10. Его ветви:

| Сообщение | Изменение |
| --- | --- |
| `200` | `4546f0 = UInt16(lParam)`; `453cdc = lParam >>16` |
| `201` | `457580 = 1` |
| `202` | `457580 = 0` |
| `203` | Игровые globals не меняются |
| `204` | `4527e4 = 1` |
| `205` | `4527e4 = 0` |

Обе координаты **беззнаковые**: packed `ffffffff` становится65535/65535.
Нажатия/отпускания не извлекают координаты из своих lParam. Jump table
`43bc9c` содержит `43b8f7/43b8e8/43bc24/43b915/43b906`.
После этих ветвей вызывается DefWindowProcA с исходными четырьмя аргументами,
его EAX возвращается без изменения. Проверены ненулевые wParam, старший бит
lParam, сохранение EBX/EBP/ESI/EDI и ESP после настоящего `ret16`.
Нативный `receiveMenuMouse` принимает только этот объявленный набор сообщений.
Поведение других сообщений и настоящей оконной системы этим не доказывается.

## Пять пунктов

`base = Int32(453da4 + 202)` с переполнением. Сначала запрашивается bitmap
из `45117c`: позиция263/base, кадр0, аргументы прозрачности/отражения1/0.
Всегда обнуляется `4511e0`. Выбор допускается при **276 ≤ x ≤ 520**.
Вертикальные сравнения знаковые; каждое прибавление к base оборачивается
отдельно, поэтому заменять их сравнением `y-base` нельзя.

| Пункт | Включённый диапазон y относительно base | Подсветка: global bitmap / x / y / frame |
| --- | --- | --- |
| 1 | 15..39 | `4511a0` /277 /base+13 /7 |
| 2 | 45..70 | `4511a0` /277 /base+45 /8 |
| 3 | 77..102 | `4511a0` /277 /base+76 /9 |
| 4 | 107..132 | `45117c` /279 /base+107 /1 |
| 5 | 137..162 | `45117c` /279 /base+139 /2 |

Пункт2 вызывает генератор таблицы **до подсветки и проверки подтверждения**.
Он делает это и при `457580=0/2/-1`, и при ненулевом `44d060`.
Пункт1 пересоздаёт таблицу только после подтверждения. Поэтому наведение
на пункт2 может многократно продвигать CRT state до запуска локальной игры.

Подтверждение требует точно `44d060==0` и `457580==1`. Для любого другого
значения эти действия не выполняются, но подсветка и генерация пункта2 остаются.
При подтверждении все пункты запрашивают звук из `455610` с loop=0:

- Пункт1 сначала очищает `457580`, затем после звука пишет `4553bf=75`,
  `44d064=0`, **World+0=1**, пересоздаёт таблицу, задаёт `450b4c..450b58 =1,2,3,4`.
- Пункт2 также очищает `457580` до звука; затем `44d064=1` и сетевой init.
- Пункт3 задаёт `44d064=6`, пункт4 — `44d064=7`. Они **не очищают457580**.
- Пункт5 после звука вызывает Sleep(300), затем ShellExecuteA с `open`,
  `http://littlefighter.com`, show=1 и нулевыми остальными аргументами.
  Возврат ShellExecuteA не проверяется; это запрос открытия сайта, не выход из игры.

Нормальные пути после этого вызывают `423b00(44d060,targetSurface)` и переходят
к `42873e`. Нулевой `458420` и ненулевой указатель на нулевой первый dword
проверены реальными инструкциями. Непустая панель отклоняется нативным методом
с откатом World/globals/CRT state; её поведение не заменено пустым.

## Подготовка сетевого сервера

Сохраняются исходные проверки и порядок `402b60`:

1. Startup запрашивает версию0101. Его код возврата **игнорируется**;
   проверяется первый UInt16 выходной структуры. Несовпадение показывает `WSAStartup()`.
2. Запрашивается hostname в буфер256. Только -1 считается ошибкой.
   Затем host lookup сохраняет указатель результата в `44f2d4`; ноль — ошибка.
3. `402ad0` проходит список адресов. Для каждого вызывает htons(0), игнорирует
   его результат, получает текст адреса, копирует через настоящий sprintf `%s`
   и проверяет `402a60`. Выбирается первый неотклонённый адрес; если все
   отклонены, используется **первый**. Пустой успешный список остаётся вне домена.
4. Предикат отвергает byte prefixes `10.`, `192.168`, `169.254`, `127`.
   Дополнительной точки для последних трёх нет. `172.16.0.1` не отвергается.
   Это исходные сравнения байтов, а не новая классификация IP.
5. В `44f260` записывается family=2, в `44f264` — выбранный raw UInt32 адрес,
   в `44f262` — htons(5000). Затем обнуляются `44f1b4/44f1b0` и создаётся
   socket(2,1,6). Полученный token сохраняется в `44f1b4`, ошибкой считается толькоffffffff.
6. AsyncSelect получает socket, window из `4546f4`, message401 и mask38.
   Любой ненулевой результат — ошибка. **Socket при этой ошибке не закрывается**.
7. При успехе `44f58c/44f590/44f58e` получают family2, тот же адрес,
   htons(12345); `44f1ae=0`. Остальные байты sockaddr сохраняются.

При отказе init функция показывает соответствующую ошибку; меню дополнительно
показывает `InitWinSock()` и переходит к `4287de`, минуя панель и общий вывод.
При успехе меню обнуляет200 байт `44f340`, копирует туда текст выбранного
адреса через NUL и вызывает bind(socket,44f58c,16), затем listen(socket,5).
Bind=-1 закрывает socket без дополнительного сообщения; listen=-1 сначала
показывает `Listening() error`, затем закрывает socket. Оба пути идут к4287de.
Код closesocket игнорируется и сохранённый socket token **не обнуляется**.
Ненулевые коды bind/listen, отличные от-1, проходят дальше.

Native network input — явно предоставленные результаты платформенных вызовов,
буферы и непрозрачные32-bit pointers/handles. Это ещё не транспорт macOS.
Действительные IPv4-контроли имеют согласованные raw bytes и dotted text.
Отдельные намеренно не-OS строки `192.1689/169.254x/1278/1` проверяют
именно предикат EXE; их нельзя выдавать за реальные результаты inet_ntoa.

## Сравнение и связь с матчем

[oracle_main_menu.py](../../tools/oracle_main_menu.py) расширяет
[RNG initialization](RANDOM_INITIALIZATION.md) после вычисления таблицы.
Два корпуса с Actor/World backing a5/ramp содержат по25 цепочек. Каждая:
контролируемый seed/table участок → последовательность menu probes с общим
CRT state → настоящий mouse move/left down → пункт1 → пролог → подготовка
из полного исходного каталога → полный буфер начальной записи повтора.

Интервал между функциями4246b0 и429730 ещё не исполнен: регистры/stack context
для следующей функции устанавливаются явно. Данные выбранных бойцов, mode,
арены, времени/устройств и replay metadata сохраняют прежние границы. Перед
каждым probe явно задаются позиция/смещение/flags и World+0; mouse probes
затем меняют их исходным WndProc. Контроли состояния с отрицательными/крайними
Int32 не объявляются достижимыми физическим перемещением мыши.
В этом корпусе World+0 после пункта1 остаётся1 до записи повтора. В настоящем
диспетчере следующая ветвь `424701..424736` вызывает `423910`, запрашивает
рисование, пишет World+0=2 в `42471d`, затем вызывает `4028a0/43e940`.
Она пока не исполнена: конечный снимок нового корпуса **нельзя считать
готовым начальным состоянием такта матча**. Здесь проверено сопряжение
объявленных функций с явно установленным stack context.

Позднейшее [MENU_PRESENTATION.md](MENU_PRESENTATION.md) исполняет этот tail
и весь вызов диспетчера World=1 через настоящий ret4. В его **новых** корпусах
World=2 получается из восстановленных инструкций и передаётся в подготовку.
Исторические fixtures этого документа не изменяются и сохраняют World=1.

[OriginalMainMenu.swift](../../native/Sources/NTSDCore/OriginalMainMenu.swift)
воспроизводит решения общими методами и сохраняет CRT state между вызовами.
[MainMenuReference.swift](../../native/Sources/NTSDReferenceChecks/MainMenuReference.swift)
сравнивает все globals/World bytes и masks до/после каждого probe и сообщения,
порядок и все аргументы запросов, результат WndProc, выходы menu body, CRT state.
Нативные данные передаются в существующие сравнения пролога/подготовки/записи;
ожидаемые post-state и таблицы не становятся входами Swift.

Release-сравнение двух корпусов до принятия fixtures:

- **1020 probes, 450 сообщений мыши**, 139759680 байт/масок.
- **4150 событий**, 250 генераций таблицы из меню,46 вызовов настоящего sprintf,
  14 выходов через сетевые ошибки. Дополнительно сохраняются50 исходных
  генераций родительского RNG-корпуса.
- После меню —50 цепочек подготовки и **324583600 байт/масок** полных
  буферов повтора. Весь загруженный каталог и прежние проверки продолжаются.

Источники, SHA-256 и полные упорядоченные события закреплены в
[a5](../evidence/main-menu.json), [ramp](../evidence/main-menu-ramp.json)
и packed fixtures. Raw captures дополнительно сохраняют instruction access
inventories; внутренние3000 CRT draws каждой menu-генерации проверяются
исполнением DLL и сохраняются как digest/count, сама таблица — побайтно.
Подробное сравнение каждого rand/state уже находится в родительском корпусе.

Два выбранных Swift-теста прошли без ошибок за230.344s: новый menu corpus
за116.782s и прежний RNG initialization corpus за113.562s. Оба включают
загрузку каталога, пролог, подготовку и полные буферы записи. Это проверка
затронутых цепочек, не повтор всего Swift-набора. Старые fixtures не изменены.
Release-сборка `NTSDNative` также прошла (2.31s).

```sh
uv run tools/oracle_main_menu.py
uv run tools/oracle_main_menu.py --ramp
uv run tools/oracle_main_menu.py --accept
swift test --package-path native --filter '(OriginalMainMenuTests|OriginalRandomInitializationTests)'
```
