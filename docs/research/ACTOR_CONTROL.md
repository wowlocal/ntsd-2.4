# R02.1 / R04 / R05 — целая функция управления Actor

Эталон: NTSD 2.4 EXE SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.

[OriginalActorControl](../../native/Sources/NTSDCore/OriginalActorControl.swift)
переносит всё тело `413080..4143cb` до`ret8`. Оно вызывает ранее проверенный
[OriginalActorInput](ACTOR_INPUT.md), затем обрабатывает движение, атаки,
рывки/перекаты и назначение скорости из DAT. Сохраняются полный Actor,
global state и маски инициализации. Отдельных обработчиков персонажей нет.
Значение `Actor+98` выбирает исходные ветви удерживаемого оружия; оно не является
ID персонажа. Исключение ID6 остаётся в подтверждённом общем распознавателе.

Это функция одного Actor. Окружающий caller по400 слотам, физика, контакты,
рисунок, планировщик и завершение такта остаются отдельной работой. Новая
функция ещё не заменяет ограниченную Practice и не закрывает полный матч.

## Восстановленные участки

| Адреса | Поведение |
| --- | --- |

| `4132ef..4133b1` | Разворот кадра110; движение по z в состояниях19/301 |
| `4133b1..413a09` | Обычная ходьба и отдельные кадры/скорости при `Actor+98==2`; двойные нажатия; атака, прыжок, защита |
| `413a09..413b13` | Разворот и атака в воздухе при состоянии4/y<0 |
| `413b13..413e75` | Обычный/weapon2 бег, остановка, атака, защита и рывок |
| `413e75..413f8d` | Продолжение из кадра215: защита, два последовательных направления рывка, управление z |
| `413f8d..414080` | Восстановление из182/188 при живом Actor, разрешённом fallHurt и buffered jump |
| `414080..414247` | Разворот в состоянии5 без разворота импульса; атака в направлении движения |
| `414247..4143cb` | Общие `dvx/dvy/dvz`, facing и знаковые буферы направлений |
| `417090..417162` | Накопление громкости встроенного звука по двум каналам |
| `417170..4171bc` | Настоящий общий RNG; Native использует прежний OriginalRandom |

Оба аргумента caller сохранены в публичном API. Первый в теле не читается;
второй передаётся412f40, где также не используется. Их нельзя превращать
в произвольный множитель скорости или пропуск управления через такт.

Блоки последовательны. Двойное нажатие может выбрать бег и выполнить его
движение в том же вызове. Атака при ходьбе обрабатывается до прыжка и защиты;
её стоимость может списаться, даже если последующий блок заменит кадр.
При удерживаемом оружии2 используются кадры12–18 и скорости заголовка30/38/40/48.
Нативный код сохраняет32-битное переполнение фазы и знаковый остаток деления;
исходная ошибка `idiv` остаётся явной неподдерживаемой границей с откатом.

Обычные standing/air атаки используют весь `Frame.mp`, без упаковки HP-стоимости
комбо: отрицательный после вычитания результат зажимается в0 и не увеличивает
счётчик расхода. Беговая/рывковая атака сначала требует достаточного MP.
Сильная атака по положительному `Actor+ea` выбирает70 без этой оплаты.
Правила не заменены единым предполагаемым «списанием стоимости».

Из кадра215 правый рывок без удерживаемого направления требует **vx>0.001**,
левый — **vx<−0.001**. При обоих направлениях возможны два вызова звука и
второе назначение импульса. В состоянии5 атака требует строго положительной
скорости при facing0 или строго отрицательной при facing1; ноль не подходит.
Эти границы отличаются от прежних приближений в ограниченной Practice.

Перекат из182/188 выбирает100 или108 по facing и знаку vx, ограничивает vy
значением `Object+80`, затем задаёт скорость из`Object+88`. Внутри интервала
−1<vx<1 направление зависит от facing; снаружи — от знака vx. Направление
переката и направление кадра затем не пересчитываются по правилам другой игры.

## Звук и RNG

`OriginalGameplaySound.queueBuiltin` переносит настоящую417090. Координата x
относительна `450bc4`. Каналы имеют центры200/600, полку радиуса200 и линейное
затухание до400. При нулевом флаге в453e10 оба накопителя сначала очищаются;
иначе складываются с сохранением32-битного переполнения. Флаг становится1.
Сами WAV/device calls в этом helper отсутствуют: воспроизведение происходит
позже. Проверки здесь включают index7, повторное накопление и границы координат,
включая Int32 min/max. Звуковой микс/вывод на устройстве ещё не подтверждён.

RNG417170 исполняется в EXE, а Native продолжает переданный ему table/index/
counter через общий OriginalRandom. Никакой host RNG не используется. Теги
130/131/132 обозначают места вызовов и не создают независимые генераторы.
Новый вызов управления откатывает Actor и globals при ошибке, в том числе
если RNG уже был израсходован. События observer должны буферизоваться внешним
транзакционным caller до принятия всего такта.

## Проверки и границы доказательства

[oracle_actor_control.py](../../tools/oracle_actor_control.py) выполняет полную
функцию и реальные helpers на **25 795 синтетических случаях**:23 040 комбинаций
состояния/оружия/facing/128 held inputs,700 фаз/двойных нажатий,840 воздушных
границ,288 стоимостей,756 dv,126 звуковых границ и45 RNG wrap/типов оружия.
Выполнено1999 уникальных инструкций,900 RNG и2772 sound requests; это счётчики
наблюдений, не процент завершённости функции или игры.

[oracle_actor_control_catalog.py](../../tools/oracle_actor_control_catalog.py)
добавляет **5376 случаев на всех42 исходных Object type0**: кадр0 каждого и
128 комбинаций held input. Сырой Object восстанавливается из закреплённого
полного LOADED_CATALOG; хеши исходных DAT и каждого Object blob проверяются.
Данные Object не изменяются. Actor, globals/RNG и caller остаются объявленными
тестовыми входами. На Native заново строится и проверяется весь137-object
каталог, после чего используются его собственные header/frameStorage,
а не ожидаемое состояние объектов. Исходные байты/маски контролируют чтения;
неинициализированных чтений Actor/Object в этом корпусе не обнаружено.
Выполнено1343 уникальных инструкций и1487 RNG; звуковых запросов из этих
стимулов кадра0 нет. Исходные экземпляры по ordinal не объединяются по ID.

Все **31 171** случая сравнивают1056 байт Actor и1056 элементов маски:
**65 833 152 байта/маски**. Дополнительно совпали хеши полных46 144байт globals
на каждом случае (1 438 354 624байта) и порядок RNG/sound events. Helpers
проходят реальные возвраты с проверкой стека/сохранённых регистров. Game-code,
RNG и sound helpers не заменяются заглушками. Constructor memset сохраняет
прежнюю явно объявленную границу.

Оба первых нативных сравнения прошли:25 795 за10.336с/build89.69с,
5376 с полным родителем за7.866с/build5.11с. После выделения метода доступа
к Object синтетический producer заново воспроизвёл тот же полный raw SHA.
Сохранённые оба корпуса, откат после RNG и прежний ACTOR_INPUT прошли:
5 XCTest/22.845с. NTSDNative собран за33.48с.


`--accept` проверяет хеш/размер нового raw capture и сравнивает его с Native
перед публикацией fixture. Отчёты: [synthetic](../evidence/actor-control.json),

ACTOR_INPUT сохранены отдельно; они не включены в31 171 ещё раз.

Не доказаны все кадры/непрерывные последовательности каждого персонажа,
произвольные некорректные указатели, нечисловые/бесконечные скорости и все
случаи промежуточного округления x87. Исходные Object типов, отличных от0,
в новом корпусе не исполняются. Следующий шаг — подключить функцию
к собственному MATCH_LAUNCH41e339 и перенести окружающий caller400/401/500/501,

Начальные скорости0.1 и первый frame219 сохранять. App UI, законченный матч,
Windows, чистая macOS и общая цель остаются открытыми.
