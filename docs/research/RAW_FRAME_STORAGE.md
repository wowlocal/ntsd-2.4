# R02.1 / R03.1 — полные Frame и весь Object-реестр

Эталон EXE SHA-256:
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Чтение DAT выполняет MSVCR80 .6195 из [проверенного пакета](CRT_SCANNER.md).
Теперь все **137 исходных Object**, в исходном порядке и с общим кэшем звуков,
сравнены с нативным загрузчиком. Исключений по персонажам в реализации нет.

## Сырое хранилище и выделения

[OriginalFrameStorage.swift](../../native/Sources/NTSDCore/OriginalFrameStorage.swift)
добавляет конструктор `OriginalStateRecord.frame(over:)`, нативные аллокации и
32-битные ссылки. [OriginalFrameLoader](../../native/Sources/NTSDCore/OriginalFrameLoader.swift)
пишет непосредственно в эти записи; прежние `words/name/sound/boxes` — проекция
того же хранилища. Второго набора правил числовых defaults нет.

Конструктор `40bbf0..40bd83` определяет **325 из 376 байт**. Presence в `+0`
занимает один байт, `+1..3` сохраняются. `+c4..d7`, указатели массивов `+130/+134`
и имя `+15c..16f` не инициализируются. Sound pointer `+170` получает 0,
sound index `+174` — -1. Маски нетронутых байтов не превращаются в true.

| Запрос выделения / адрес возврата | Размер | Поведение |
| --- | ---: | --- |
| Первый itr, `4114a0..4114b8`, return `4114ab` | 400 | `+130` получает новую ссылку; каждый используемый элемент по 80 байт обнуляется и заполняется |
| Первый bdy, `411b7a..411b92`, return `411b85` | 200 | `+134` получает новую ссылку; элементы по 40 байт |
| sound, `41092e..41093f`, return `410935` | Длина пути + NUL | Всегда новая строка, даже при попадании в общий звуковой кэш |

Повторное определение кадра обнуляет **только счётчики** массивов, а их указатели
сохраняет. Первый новый блок выделяет новый массив. Если новых блоков нет,
остаются старые ссылки и bounds при нулевых counts. Старые массивы/строки
загрузчик не освобождает; они включены в нативное хранилище и сравнение.
Неиспользованные элементы malloc сохраняют исходные байты и false-маски.

Адрес аллокации — **вход внешней границы**, а не восстановленное игровое правило.
При сравнении адаптер предоставляет адрес каждого настоящего запроса malloc;
нативный загрузчик независимо проверяет порядок, вид и размер запроса, пишет
байты и затем сравнивается с результатом EXE. В обычном нативном использовании
ссылки назначает собственная последовательная арена. Это числа внутри модели
данных, не адреса памяти Swift; разыменований host pointer и исполнения x86 нет.
Подстановка адресов необходима: частичная запись в указатель зависит от остальных
его байтов, а иногда эти байты становятся частью читаемого имени.

Нативный Object принимает `frameBacking` и адаптер `frameAllocation`, возвращает
все 400 `frameStorage`, предоставляет `onFrameStorage` после определения кадра.
`frameAllocations` сохраняет выделения между Object. Ошибка не публикует изменения
кадров, кэша, bitmap или аллокаций; это дополнительно проверено прежними тестами
отката. Callback остаётся диагностическим и может наблюдать промежуточную работу.

## Имя перекрывает указатель и индекс звука

`410421..410439` вычисляет адрес `Object + 7a4 + n*178 + 15c` и передаёт его
неограниченному `%s`. Поэтому 20-байтная область имени **не является лимитом
чтения**. Следом располагаются 4 байта указателя и 4 байта индекса звука.
Лишь после имени `41043b..41046e` сбрасывает counts и ставит presence=1.

В исходниках имена достигают 25 байт. Перенесённая запись включает NUL и
подтверждена также контролями до **27 байт**: последний NUL ещё находится внутри
записи Frame. Имена, переходящие в следующий Frame, остаются явной границей.
Они не нужны для исходного реестра; это не разрешение тихо обрезать строку.

38 конечных кадров содержат после имени непрозрачные значения вместо указателей:

- Kyubi 325: pointer `0x00747361`, index -1;
- Shikamaru 282: pointer `0x6e776f64`, index -256;
- criminal2 143: pointer `0x646f6c70`, index -65435.

Эти значения сохраняются как байты и как `opaqueSoundPointer` в проекции.
Нативная модель не выдаёт их за null или путь и не разыменовывает произвольную
память. Совпадение загрузки не доказывает все последующие игровые использования
таких полей; они остаются работой соответствующих обработчиков такта/звука.

Запись `sound:` после длинного имени снова меняет `+170/+174`
(`41093f`, `41097b`, регистрация до `410a99`). Поэтому даже **прочитанное имя**
может измениться после загрузки звука. Контроль получает, например,
`four_tails_chakra_bl` + байты адреса `e0 78 02 21`, затем NUL индекса 0.
Простое сохранение текстового имени и отдельного sound было бы неверным.
Короткое новое имя пишет только себя с NUL: предыдущие хвост, указатель и индекс
при этом не очищаются. Все промежуточные состояния проверены по сырым записям.

## Десятый лист

Исходный `4TK_ball.dat` использует 10 листов. Индекс начинается с 1; исходные
адреса вычисляются в `40f254..40f6a2` и `40fd28..410165` без нативного ограничения
девятью. Для слота 10 поля остаются в пределах заголовка:

| Поле | Смещение |
| --- | --- |
| filename | `+604`, до следующей области `+62c` |
| first sprite | `+650` |
| w / h / row / col | `+678 / +6a0 / +6c8 / +6f0` |
| normal / mirror bitmap | `+778 / +7a0` |

Последний указатель заканчивается ровно перед Frame 0 в `+7a4`.
«Нулевые элементы» соседних формальных массивов не используются как отдельные
параметры листов. Общий loader теперь допускает 10. Проверены настоящий
`4TK_ball` и контроль с десятью повторными путями и отдельными bitmap-обёртками.

## Сравнение

[object-loader-raw.json](../evidence/object-loader-raw.json) содержит хеши
исходников, дампов и принятой fixture. Корпусы:

| Вход | Object | Определения / конечные Frame | Bitmap | Frame malloc | Сравненные байты и маски |
| --- | ---: | ---: | ---: | ---: | ---: |
| Все исходные записи в порядке data.txt | 137 | 15388 / 54800 | 808 | 14586 | 36402627 |
| Контроль повторов/перекрытий, backing a5 | 1 | 9 / 400 | 20 | 6 | 316959 |
| Тот же контроль, backing 00 | 1 | 9 / 400 | 20 | 6 | 316959 |

Всего **71006 полных записей Frame** после появления/при EOF, **14598 Frame
аллокаций**, **37036545 байт и масок**, включая прежние заголовки/хвосты/bitmap.
Это повторные наблюдения памяти, не процент реализованной игры. Дополнительно
сопоставлены все числовые/строковые/box-проекции, decoded bytes, общий checksum
и звуковой кэш после каждого Object. Исходный проход заканчивается 400 звуками
и Object-only checksum **30847120**. Все пять незакрытых itr в weapon4/heart*
пройдены непрерывным сканером; искусственных границ или исправлений DAT нет.

Полные сырые дампы остаются в `build/original`. Fixture использует lossless
raw DEFLATE: 288508385 байт сравнительного JSON упакованы в ~8.7 MB.
Расшифровка контейнера с проверкой длины/SHA-256 находится только в development
target `NTSDReferenceChecks`; приложение от него не зависит.

```bash
uv run tools/oracle_objects.py --raw-suite
swift test --package-path native
```

`--raw-suite` сначала исполняет оригинал, затем сравнивает каждый корпус с Swift,
и только после успеха сохраняет fixture/evidence. Все SwiftPM-команды выполняются
последовательно. Старые fixtures и их 349 изолированных исключений не переписаны.
Обычный запуск прошёл **27 Swift-тестов**, включая распаковку нового корпуса;
отдельно повторно совпали все **15056 определений / 15025 групп** сохранённой
изолированной проверки. Хеш того корпуса остался прежним.
