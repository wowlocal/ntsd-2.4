# Provenance of the character menu's catalog operands

Prepare the next installed-library character-menu continuation from
[FRESH_CHARACTER_MENU](FRESH_CHARACTER_MENU.md). The consumer reads registry
count/order, Object+6f4/+6f8 ID/type, Object+6fc portrait owner and Object+25324
name. A selected Actor retains its Object binding when selection returns to

and native menu chain.

This first finite step is a read-only artifact comparison, not new EXE execution:
all137 original registry entries, their complete DAT decoded bytes, final name/
head tokens, and every available portrait BMP dimension and wrapper. Compare
independently derived values with immutable
`original-loaded-catalog.json`, whose complete original4122f0/Object children
and native loader are already accepted. Verify its full transport and all
referenced blobs, source files and masks; never use an expected after-state as
an input to Native. Numeric/frame/allocator/private ABI not consumed by the
character menu remains outside this operand projection.

Reference files are the pinned distribution NTSD EXE
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`, original
data/data.txt, all137 referenced DATs and their original portrait BMPs. The
retained catalog fixture records controlled Unicorn/VC80 execution with explicit
text-file and image-device boundaries. The comparison runs on the macOS host
without executing those instructions. The fresh installed-library own catalog
continues independently; its full return remains open.

Acceptance: derive count/order/ID/type and text decoding only from pinned raw
inputs; match every decoded byte and relevant original stored value/mask;
reconstruct each portrait's full8016-byte wrapper from the bitmap input and
declared allocation pattern, then match full original bytes/masks with only the
known surface binding. Preserve missing name/head operands as unknown and report
whether any selectable original entry requires them. Hash all input/output
artifacts, keep all255 current fixture pins and pending/foreign/frozen files
unchanged. Record mismatches without editing existing expected bytes.

The next actual source execution must use these recovered resource operands,
preserve their declared caller-entry status, execute selection/team/ready and
real installed-library text, and compare Native's normally loaded catalog and
owned menu state. This audit alone does not execute that screen, establish own
initialized application provenance, or prove Windows/device/app/full-match
behavior. No pointer/protection corruption or memory-fault continuation is
part of the operation.
