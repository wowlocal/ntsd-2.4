# R02.1 — состояние полного такта

**Текущий приоритет: [FPU_PRECISION](FPU_PRECISION.md).** Стартовый445a31
через настоящую MSVCR80 задаёт53-битную точность; прежняя native arithmetic
проверялась при объявленном CW037f/64 бита. Собственный harness наследует CW0.
32 различающихся stores подтверждены исходными инструкциями. Нужны численная
коррекция и новые цепочки с восстановленной FPU initialization до расширения такта.

[Первая коррекция](ARITHMETIC_PRECISION.md) добавила24/53/64-битную арифметику:
54 201 исходная последовательность операций,55 433 целых вызова физики при53
битах и3 090 пулов импульсов при трёх точностях совпали с Swift. Старые fixtures
сохранены. Следом нужна новая собственная цепочка с выполнением445a31/CRT;
передача precision в hits/links пока подтверждена только прежней64-битной
регрессией. Остальная численная модель и Windows FPU provenance ещё открыты.

Следующий [этап инициализации](INITIALIZED_GAMEPLAY.md) теперь исполняет445a31
и CRT перед World на общем CPU, затем продолжает оба собственных пути до41f550
при CW023f. World physics/links/hits перепроверены отдельными53-битными корпусами;
три контрольных попадания меняют ветвь42f1e7. Прямая арифметика ActorControl и
прочие преобразования требуют дальнейшего аудита. Полный такт остаётся открыт.

**Статус:** в работе; конструкторы, загрузочный пул и родительский проход каталога
перенесены в Swift; весь исходный каталог с Object/BG/Stage и общими ресурсами
теперь также загружен совместно и сравнён; общая подготовка матча с этим каталогом
совпала в 50 случаях; создание буфера повтора через настоящий вызов меню
также перенесено полностью. Сырой снимок проверен исполнением оригинала.
Полная инициализация и словарь типов не завершены.
**Родитель:** R02 в [карте](../RESEARCH_MAP.md).
**Зависимость:** результаты [R01.1](R01.1.md).
**Эталон:** SHA-256 `3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
**После неё:** R03.1 — внешний загрузчик; затем R01.2 и общие игровые механизмы.

## Вопрос и объём

Какое состояние читает и меняет обычный путь `43e9a0 → 4246b0 → 41bc90`,
какие у полей размеры/знаковость, кто задаёт начальные значения и владеет памятью?
Начать с двух исходных бойцов, их текущих зависимостей и найденных в R01.1
пропусков. Остальные типы/режимы явно учитывать как расширения словаря.

## Опоры

- Actor выделяется по `0x420` байт: `0x41c070..0x41c091`. Конструктор —
  `0x4061d0`. Шаг `0x500` в Python остаётся размещением стенда.
- Вызов матча использует World по исходному статическому адресу `0x458b00`;
  `+0` — селектор диспетчера, `+4` — 400 байт активности, `+0x194` — 400 указателей,
  `+0x7d4` — каталог. Полный жизненный цикл и все поля World ещё не закрыты.
- Каталог выделяется размером `0x4d823a8` в `0x41bff0` и заполняется через
  `0x4122f0`. Не выводить layout каталога из одной аллокации.
- Frame stride `0x178`, 400 записей, Object `+0x7a4`; смещения проверенного
  загрузчика — [FRAME_LOADER.md](../FRAME_LOADER.md).
- Фазы, пауза, периодические счётчики и ресурсные поля —
  [TICK_PIPELINE.md](TICK_PIPELINE.md). `globalWrites` в полном `tick-trace.json`
  даёт адрес инструкции, адрес записи и размер для шести исследованных случаев.
  Это не полный список достижимых записей.
