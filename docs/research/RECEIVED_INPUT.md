# R02.1 / R04 / R16 — применение сетевых команд и команд повтора

Эталон EXE SHA-256:
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Исходные функции —4198f0/ret12 и4197a0/ret8; caller —41d469..41d4b7
при playback либо до41d5db без playback/при паузе. Продолжение после этих
точек не входит в этот участок.

## Происхождение состояния

[oracle_received_input.py](../../tools/oracle_received_input.py) заново исполняет
всю [первую загрузку](INITIAL_LOADING.md), сравнивает все три raw transport
побайтно с закреплёнными прежними захватами и затем выполняет естественный
[локальный ввод](LOCAL_INPUT.md). Его первый случай, включая все используемые
blobs, также сверяется с прежним корпусом. Ни World, ни Actor, ни загруженный
каталог не восстанавливаются из ожидаемого после-состояния.

В основном проходе фаза после загрузки равна1, пауза0. Тот же CPU/стек
продолжает41c5e5: настоящий переход41c5ec ведёт к41d469, затем4198f0 и41d5db.
Это непрерывное продолжение первой загрузки; статусы первой восьмёрки пока0.

В контрольном проходе после загрузки фаза0/пауза1. Следующим должен выполняться
ещё не перенесённый сетевой/hotkey путь41c5e5..41d469. Поэтому первый новый
контроль явно начинает с41d469 на собственном загруженном состоянии и с
сохранёнными входами паузы/команд. Это **предоставленная граница caller**, а не
непрерывное исполнение пропущенного пути. Остальные пробы обоих проходов также
явно задают входы и вызывают нужную функцию/caller на сохраняющемся мире.

Native повторяет полную загрузку и весь старый local-input corpus через
[LocalInputReference.onNatural](../../native/Sources/NTSDReferenceChecks/LocalInputReference.swift).
Новый callback получает собственное проверенное состояние сразу после
естественного локального ввода. Новые пробы работают с его копией; после callback
проверка старого корпуса продолжается независимо. Все восемь родительских
fixtures закреплены прежними SHA; данные каталога/аудио не дублируются.

## Общие правила и различия

Обе функции обходят ровно восемь мест в порядке0..7 через World+194+seat*4.
Activity bytes World+4..b не проверяются. Остальные392 записи Actor не входят
в цикл. Сам индекс места не обязан совпадать с индексом Actor.

| Действие |4198f0: remote|4197a0: playback|
| --- | --- | --- |
| Выбор места | Только signed status450b4c+seat*4 **ровно−1** | Все восемь; status не читается |
| Сохранение previous | Сырые current+cd..d3 → previous+c6..cc | То же |
| Фаза!=0 | После копирования перейти к следующему месту | То же |
| Фаза0 | Очистить current+d3..cd, затем применить семь масок | То же |
| Запись команд | При450b80!=0 заменить весь output[seat] входным байтом | Выходного буфера нет |
| Playback flag450b84 | Самой функцией не проверяется | Самой функцией не проверяется |

Маски up/down/left/right/attack/jump/defend:80/40/20/10/08/04/02.
Установленный бит создаёт current=1, снятый —0. Bit0 не является кнопкой,
но4198f0 сохраняет его при записи полного байта команды. Это **присваивание**,
в отличие от OR локального419a60: старая команда может потерять свои биты.
В phase!=0 и для пропущенного статуса выходной байт не изменяется.
Команды мест8/9 остаются нетронутыми у обоих обработчиков.

Копирование previous не приводит исходные байты к Boolean. Если два места
ссылаются на одного Actor, второе видит current, уже записанный первым местом.
Поэтому previous после phase0 может содержать кнопки предыдущего места,
а current — последующего. Стенд проверяет эти ссылки и порядок на реальных
Actor allocations, включая399 и контроль с обратным физическим размещением.
Это структурные пробы механизма, не утверждение, что меню создаёт такие ссылки.

## Caller и нативная реализация

41d469 читает menu-state44d020. Ненулевой локальный pause поstack+38 сразу
ведёт к41d5db, пропуская обе функции. Проверяется именно локальный аргумент
этого участка, а не новое чтение глобальной очереди паузы.

При отсутствии паузы4198f0 всегда получает input44f198, phase450b90,
output stack+434. Затем только при450b84!=0 вызывается4197a0 с packet stack+440
и phase450b90. Поэтому даже при playback сначала выполняется сетевой обработчик.
Он может изменить previous/current и буфер записи, после чего playback ещё раз
копирует current в previous и заменяет current в phase0. Промежуточный снимок
между этими функциями проверяется отдельно от конечного.

[OriginalReceivedInput](../../native/Sources/NTSDCore/OriginalReceivedInput.swift)
добавляет remoteInput/playbackInput/receiveInput к существующему
OriginalMatchPreparation. Публичные операции сохраняют транзакционность
World/Actor/globals и буфера commands при ошибке. Ссылки — известные ненулевые
ordinal, включая0; Windows-адреса не становятся указателями процесса macOS.
Нативный общий helper не зависит от имён/ID персонажей или полей их DAT.

receiveInput возвращает явную следующую стадию: playbackChecksum либо recording.
Возврат не означает, что контроль суммы или запись уже выполнены. Прямые API
получают десятибайтные значения пакетов с отдельным выходным массивом; произвольное
перекрытие адресов source/output/Actor в исходном адресном пространстве не
эмулируется. Настоящий caller использует отдельные44f198, stack+434 иstack+440.
Повторные ссылки самой таблицы World→Actor поддержаны и проверяются.

## Проверяемый объём

[ReceivedInputReference](../../native/Sources/NTSDReferenceChecks/ReceivedInputReference.swift)
сравнивает весь World, все400 Actor, globals и маски происхождения, после
каждого настоящего возврата и на конечной границе. Сравнение сохраняет padding,
остальные поля и неактивные объекты. Проверяются оба десятибайтных буфера и
восемь окружающих stack bytes; нормализуются только установленные указатели.
Python контролирует настоящие ret12/ret8, возвратные адреса, стек и все четыре
nonvolatile registers. Swift дополнительно проверяет свидетельства вызовов.

На каждый из двух проходов предусмотрено726 случаев:

- Один первый caller после воспроизведённых загрузки и локального ввода.
- По256 значений байта remote иplayback: каждый из восьми входных байтов проходит
  все значения0..255, включая различия bit0 и одновременные противоположные кнопки.
- 135 сочетаний трёх entry kinds, пяти фаз0/1/2/−1/Int32.min, recording0/1/−1
  иplayback0/1/−1; статусыInt32.min/−2/−1/0/1/4/5/Int32.max вращаются по местам.
- 24 дополнительных поворота статусов и24 перестановки/повторные ссылки Actor
  в фазах0/1; активность включает0/1/2/127/128/255.
- 30 caller controls с pause1/−1, всеми пятью фазами иplayback0/1/−1.

В прямых вызовах global phase специально может отличаться от аргумента.
Playback/recording flags не ограничены Boolean0/1. Входные записи описаны отдельно
от ожидаемых снимков; новые значения после выполнения не подставляются в native.
