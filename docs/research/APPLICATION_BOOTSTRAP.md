# Production startup and first menu owner

The production bootstrap is verified in its finite declared-input scope.
The frozen plan and candidates are retained in
`build/research/application-bootstrap-native-20260912/`.

`OriginalApplicationBootstrap` moves the declared WinMain startup and first
menu caller into Core. It retains the complete `OriginalWinMainStartup` owner
beside a live `OriginalApplicationMenuSession`. The first committed resize and
the following resource/settings/background/body/menu/timer iteration are driven
by Core. XCTest adapters supply declared inputs and compare observations.

This advances the own application startup required by the native game. It does
not yet replace the Practice app entry or establish actual window, input, raster,
audio, Windows or clean-Mac behavior. The full game goal remains unchanged.

## Ownership, inputs and transactions

Startup receives the declared full PE-backed record and masks, instance/show,
clock/calendar/TZ/critical-section responses and original file/resource inputs.
It invokes the existing continuous `OriginalWinMainStartup`, retaining panel
generations, calendar/music storage, formatted dates and all five WAV results,
including their temporary/first/second records and masks. Globals, startup RNG
and the initial loop counter come from their own producers.

`OriginalApplicationStartupPlatform.stagedCopy` requires an independent copy of
every mutable reply position, allocator identity and file/effect cursor. Core
rejects a same-instance copy; adapter tests must additionally prove mutable-state
independence. The startup owner and adapter publish together only after the final
handoff observer succeeds. A thrown startup attempt publishes neither. Shared
immutable source-byte caches are distinct from mutable platform state.

Each following loop iteration is a separate transaction. Its queue, lifecycle,
surface and first-menu resource replies are immutable value packets. Core owns
their attempted positions; observers cannot choose or execute a continuation.
The selected WM_SIZE callback uses `OriginalWindowLifecycle`. A late first-menu
failure preserves that already committed callback and the complete startup.

The session's canonical full record preserves the real outer/local/World/replay/
counter aliases and all masks. Native constructs the 24 front resources, parses
the declared translated control bytes, allocates and constructs its background,
then executes panel/body/alternate/main/presentation and dispatcher/timer return.
Created surface bindings enter the live registry exactly once within the pending
iteration. Test Graphics dictionaries remain diagnostics; no expected wrapper or
after-state becomes a Native owner. Private settings/body bytes stay unknown.

Whole World returns its presentation HRESULT; the enclosing dispatcher retains
its independently produced result 1. Negative HRESULT cases must preserve both
observations. Missing or dead bitmap owners remain typed Core errors. The
NULL-cursor source boundary is a Native rejection with rollback, never a matched
completed source iteration. Pending loading remains uncommitted and does not
invent the later 41bc90 return or held-state clear.

## Operations and validation gates

The startup operation log explicitly distinguishes immutable input acquisition,
Core-owned memory work and platform requests. Fetching WAV input bytes is not a
second mmioOpen, and a PCM copy is not a second backend write. Music helper and
format summaries do not duplicate child operations; GetVolume remains an actual
COM request with its declared response. This typed log is not an implemented
AppKit command buffer.

First-menu batches record actual allocator/image/surface/settings/thread/graphics
requests while excluding helper summaries and scalar observations. Startup and
first-menu projections are independently assembled from saved source streams;
their exact order, arguments, replies and declared field masks must compare.
Opaque request bytes normalize only under their false source masks.

The frozen regression selection contains the new bootstrap tests plus retained
WinMain, BitmapSurfaceLoading, Settings, FrontScreen, ScreenBody, MenuReturn,
MenuInput/Session, MessageLoop and LoadingPrefix families. Whole final wrapper
bytes/masks, raw surfaces, RNG, startup resource lifetimes and late rollback
remain required. Test success, independent review, fixture transport integrity,
Native package identity, archive identity and Git publication are separate gates.

Candidate1 built and then failed at the new background `timer` observation,
which its initial Session dispatcher omitted. Its 24 test executions, failures,
complete source inputs and frozen code remain preserved. Candidate2 includes the
missing first-background observation routes and independently reviewed stronger
operation/lifetime checks. All 24 selected release methods passed in 149.107s; the build took 293.60s.
No raw overrides were set. Candidate1 took 299.67s to build and 72.823s to run,
reporting 20 XCTest failures (two unexpected), not 20 distinct source cases.

## Verified composition and preservation

The one nested original-entry startup yields 144 typed operations: seven input
acquisitions, 20 owned-memory operations and 117 modeled platform requests.
Repeating it for the 48 primary attempts compares 6,912 operations; it does not
add distinct WinMain configurations. Early WM_SIZE iterations separately commit
49 operations (48 translations and one invalidation). The 47 completed first
menus compare 22,623 operations: 1,175 owned-memory and 21,448 platform. The
NULL-cursor attempt retains 464 uncommitted operations separately.

First-menu request masks cover 320,048 bytes: 136,976 defined and 183,072 unknown.
Fill backing adds 4,700 bytes: 376 defined and 4,324 unknown. All 19,921 Bitmap
replies retain 3,511 writes / 182,460 bytes. The independent saved-data projection
pins source order and payloads; the Native tests compare exact operation batches.
The new startup six late controls and first-menu 17 late controls pass, together
with the retained nine MenuReturn late controls and all selected parent/input/
loading regressions. These controlled observer errors establish Native rollback,
not original API-failure behavior.

Five additional raw/fixture pairs preserve 205,795,824 raw bytes in 46,327,408
fixture bytes. Each envelope omits exactly one terminal LF: payload plus that LF
reproduces all original raw bytes/SHA, full JSON and 5,443 blob entries /
185,692,160 decoded bytes (2,386 distinct blobs). Four earlier pairs reuse their
pinned full transport verification after rechecking its report and all eight
raw/fixture pins. The two new Python projection-verifier mistakes (optional kind
and Window-versus-Bitmap schema) remain beside the corrected third report.
No failed source outcome or expected byte changed.

All 370 fixtures remain regular and unchanged. The full tested Native archive
contains 822 members / 4,015,554,451 payload bytes; the evidence archive contains
120 members / 485,121,265 payload bytes, including both frozen changed candidates,
all 69 original plan pins, the additional five raw corpora and prior verification.
Every member's mode, bytes and SHA matches. Both Native jobs are terminal and
their PIDs absent. These archive checks precede the separate Git tree check.

[Machine-readable acceptance](../evidence/application-bootstrap.json) pins the
plan, candidates, jobs, independent code/fixture/projection reports and archives.

a Native file/translated-text adapter, and AppKit queue/clock/raster/audio delivery.
No research JSON or Windows executable may become shipping runtime infrastructure.

execution/reentrancy and unsupported dispatcher branches remain open. Full own
loading/catalog return, War43a860, the complete match/game, Windows and clean-Mac
acceptance also remain open. The three recorded safety incidents are unchanged;
this independent Native work does not clear or retry their affected operations.
