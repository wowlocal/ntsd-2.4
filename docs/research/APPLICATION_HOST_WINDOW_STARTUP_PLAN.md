## Contract frozen before edits

- Bootstrap gains an optional preparation callback after its existing independent
  staged copy and before any Core startup work. It can mutate only that copy.
  Preparation failure reports the attempted copy once and commits nothing. Default
  callers keep their existing number/order of copies and recovered operations.
- Host passes preparation to Bootstrap and gains a final validation callback after
  its delivery-context copy, immediately before nonthrowing state/batch publication.
  A failure at either hook preserves the committed Host and publication sequence.
  Both hooks prohibit physical IO and mutation of shared/captured provider state.
- A new Core coordinator owns a private Host, one private window exchange, fixed
  instance/show/initial data, and a recursive lock/reentry guard. It never replaces
  the Host between attempts. A small provider protocol exposes an optional value
  cursor copied by stagedCopy; all nonwindow observations remain prepared inputs.
- Resume installs a fresh immutable cursor only into the attempted platform. At
  an unanswered request the whole Host attempt unwinds, then the coordinator
  claims the exact ticket and returns its permit. Serving the physical operation
  and submitting its response occur outside Core. Resume with an active permit
  rejects; stored answers are replayed as values, not served again.
- The final Host validation finishes the exchange only after whole Bootstrap and
  the independent delivery-context copy succeed. Missing, foreign, stale,
  suspended or unconsumed cursors reject before publication. The private exchange
  and Host cannot be mutated externally during this boundary. No throwing work
  remains after exchange completion before Host publication. Failed earlier
  preparation, whole caller or context copy leaves the answered exchange open.
- Completion returns the same Host for its existing menu/input consumers. Prior
  receipts survive late failures/cancellation; issued permits accept one eventual
  response or indeterminate failure after cancellation. No automatic physical
  retry, invented HRESULT, rollback of device work or duplicated batch delivery.
- Reentrant resume/answer/fail/cancel/inspection mutation rejects. Read-only value
  snapshots may observe committed state. Immutable snapshots and committed platform
  cursors retain response resources through coordinator destruction.
