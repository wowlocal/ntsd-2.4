## Native reader and consumer

`OriginalApplicationCatalogInputs` checks the compiled manifest digest, exact
file and directory composition, regular-file boundaries, lengths and SHA values
before publishing an immutable value. It rejects symlink roots/members, missing,
corrupt, extra or nonregular content. Duplicate/conflicting manifest entries
cannot satisfy its fixed manifest identity. Existing BMP/DIB initializers own
headers, metadata, source colors and defined masks; no new image decoder or
palette behavior is introduced. Data is acquired before a Core attempt, with no
later filesystem lookup in the catalog callbacks.

The reader exposes521 files,669 bitmaps and8 music byte arrays. Its finite file
lookup rejects unknown spelling; an optional overlay makes an independent value
and keeps missing distinct from empty. Music packaging does not choose an audio
codec or successful device result. App lookup requires Contents/Resources/
OriginalCatalog and does not fall back to developer module data when an app's
package is missing. SwiftPM clients use the same ordinary module resource.
