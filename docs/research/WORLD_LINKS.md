# R02.1 / R05 / R09 / R11 — глубина и удерживаемые объекты

Эталон: NTSD 2.4 EXE SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.

[OriginalWorldLinks](../../native/Sources/NTSDCore/OriginalWorldLinks.swift)
переносит всю функцию `417f80..4187a3`, включая поздние ветви после её обычного
ret418222. Она делает два отдельных прохода по400 слотам: границы глубины,
затем размещение/использование/броски удерживаемых объектов. Прежнее название
«ограничение Z» описывало только первый проход. Оригинальный такт вызывает
функцию дважды; новый собственный путь пока дошёл через первый вызов41eed3.

## Исходные правила

| Адреса | Перенесённая стадия |
| --- | --- |
| `417f80..418022` | Активные type0: нижняя/верхняя Z-границы выбранного BG, затем4450d0 и integer z |
| `418022..4180ac`, `418798..4187a3` | Второй400-slot проход, отрицательный98, unsigned A0<=399, активность владельца и обратная ссылка9c |
| `4180ac..418223` | State17 владельца, использование sourceID122, восстановление HP/MP и завершение |
| `418223..418310` | State17/sourceID123, расход HP предмета и восстановление/назначение MP владельца |
| `418310..4184b2` | wpoint/weaponact, facing/freeze и координаты через центры кадров обоих участников |
| `4184b2..41857b` | Выпадение при state12/10 владельца, исходные hit/velocity поля и RNG138 |
| `41857b..41870c` | Ненулевой wpoint.dvx: type1/4/6 бросок40, type2 случайный кадр через RNG139 |
| `41870c..418798` | wpoint.kind3: четыре последовательных RNG140..143, окончательные frame/скорости |

Оба прохода считают активным любой ненулевой byte World+4+slot. Первый
обрабатывает только Object.type0: `z=max(z,BG+4)` и затем `z=min(z,BG+8)`
как два последовательных строгих сравнения. При перевёрнутых границах это
заканчивается верхним значением. Integer z обновляется даже без ограничения;
integer x/y, binary x/y и скорости не меняются. BG ordinal берётся из44d024,
поля находятся в каталоге по4d45db0+ordinal*990. Native использует собственные
загруженные background records, не параметры Practice.

Второй проход обрабатывает Actor с98<0 независимо от Object type. A0 содержит
номер слота владельца. Он должен быть unsigned<=399, activity!=0, а его9c
должен равняться номеру текущего слота. При любой неудаче очищается **только98**
текущего Actor; A0/9c, кадр и скорости остаются прежними. World-таблица допускает
alias нескольких слотов одной аллокации; все чтения/записи учитывают эту связь
и возрастающий порядок. Проверка относится к номеру слота, не к равенству Actor.

## Использование предметов

В state17 владельца sourceID122 с положительным HP предмета уменьшает его на1.
При новом HP%5==0 владельцу добавляются redHP+2 и HP+4, затем redHP ограничивается
maxHP, HP — redHP. При текущем HP предмета%6==0 владельцу добавляются5MP с
верхним пределом500. Значение HP предмета перечитывается между ветвями: alias
и предшествующее лечение могут его изменить. Все суммы сохраняют Int32 overflow.

SourceID123 с HP>0 уменьшает его на2 и прибавляет владельцу3MP с верхним
пределом500. Затем если owner2f4 **предмета**>-1 и MP **предмета**>150,
MP владельца присваивается150. Это не min(MP владельца,150) и не проверка
его текущего MP. ID122/123 — прямые исключения EXE, не код по имени DAT.
В исходном каталоге оба имеют type6; общий механизм также сохраняет исходное
отсутствие type-фильтра у этой ветви.

Когда использованный предмет исчерпан,98 обоих Actor,9c владельца иA0 предмета
становятся0. Предмет получает frame0/vy−8, затем vx=RNG(136 либо137,7)−3.
Владелец получает frame0, durability31c предмета=0; размещение/броски для этого
слота пропускаются. Состояние RNG полностью сохраняется в собственных globals.

## Размещение и бросок

Входной wpoint владельца сохраняется как ссылка на конкретный Frame. Его
weaponact назначает кадр предмету; facing/freeze копируются из владельца.
Последующие centerx/centery читаются уже из текущих кадров обоих Actor.
При alias это может отличаться от кадра сохранённого wpoint.

Опорная x при facing0: owner.ix−owner.centerx+owner.wpoint.x, иначе
owner.centerx−owner.wpoint.x+owner.ix. Опорная y:
owner.iy−owner.centery+owner.wpoint.y. Позиция предмета добавляет его
centerx−wpoint.x для facing0, обратную разность иначе; по y всегда
centery−wpoint.y. Integer z копируется от владельца. При owner.wpoint.cover==0
добавляются z+1/y−1, иначе z−1/y+1. Все операции32-битные с переполнением;
три binary координаты затем получаются из этих integer значений.

State12/10 владельца после размещения очищает98 обоих и назначает предмету
frame=RNG(138,16). Если owner.hitCount20==1, vy берётся из30, vx из28/3;
иначе vy из48, vx из40/3. Binary y ограничивается сверху−2, **integer y не
пересчитывается**. Этот блок не пропускает дальнейший явный/случайный бросок.

При ненулевом wpoint.dvx type1/4/6 сохраняет номер владельца в2f8 и получает
frame40; type2 получает RNG(139,6). Vx задаётся signed dvx с разворотом по
нулевому/ненулевому facing владельца, vy=dvy. Если только current up/CD ненулевой,
vz=−dvz; если только down/CE —vz=dvz; при обоих или ни одном прежняя vz остаётся.
98 обоих очищаются; reciprocal9c/A0 здесь не очищаются. Остальные типы
пропускают эти два блока, но всё ещё могут пройти следующий kind3.

Wpoint.kind3 выполняется последним и ещё раз очищает98 обоих. Затем строго
по порядку: frame=RNG(140,6), vx=RNG(141,7)−3, vy=−RNG(142,4),
vz=(RNG(143,5)−2)/5. Предыдущие расходы RNG/назначения не отменяются, даже
если итоговые frame/скорости перезаписаны. Теги не означают отдельные генераторы.

Деления на3/5 используют общий [OriginalExtended](ACTOR_PHYSICS.md) с исходной
64-битной мантиссой/CW037f и явной binary64-записью.4450d0 теперь выделен в
общий OriginalCoordinateConversion; правила обоих ранее проверенных CPU-путей
не изменены. Нефинитные входы и иные CW остаются вне объявленного домена.
Весь pool/globals откатывается при неподдержанном пути или ошибке наблюдателя;
события нужно буферизовать до принятия такта. Это политика порта, не правило EXE.

## Корпуса и границы доказательства

[oracle_world_links.py](../../tools/oracle_world_links.py) исполняет настоящую
417f80 и все RNG/ftol2 helpers. Только прежний constructor memset остаётся
внешней границей. Declared input:400 Actor над a5/ramp, четыре Object/Frame,
BG limits и globals.31c=20 задан явно, поскольку конструктор сам его не пишет.
Стек, сохраняемые регистры, пустой FPU stack/CW, границы pool, маски чтений,
неизменность World/Object/BG проверяются после каждого случая.

3018 случаев:616 depth,252 invalid/valid link gates,576 placement,
1200 throw,324 consumption,48 alias/order,400-slot pass и пустой World.
588 уникальных инструкций,6922 helper returns,3878 RNG requests.
Сравниваются хеши всех424408 pool bytes/масок,46144 globals и порядок RNG.
Native совпал с первого raw сравнения:2 XCTest/2.413с, release build103.40с.
Acceptance после подключения reference API:2 XCTest/2.423с, build67.36с.
Отдельный rollback тест требует ошибку после Z clamp, размещения и первого
реального расхода RNG. [Принятый отчёт](../evidence/world-links.json).

[Survey исходных DAT](../../tools/survey_world_links.py) отдельно проверяет
неизменность загруженного каталога и SHA всех исходных Object файлов. У42 type0
Object найдено10041 присутствующих Frame и688 различных wpoint наборов.
В41 кадре weaponact равен−888/1000/9998, то есть вне400-frame массива.
[Отчёт](../evidence/world-links-dat.json) сохраняет каждый ordinal/ID/путь/кадр
и все девять полей. Это инвентаризация данных, **не доказательство достижимости
таких связок в игре**. Native не исправляет значения, не заменяет их0 и явно
отказывает при выходе ссылки за восстановленную область Frame. Исследовать
предшествующие state/link переходы и Windows-поведение нужно отдельно.
Синтетический корпус не выдаётся за все DAT/все непрерывные техники.

## Собственный матч

[oracle_gameplay_links.py](../../tools/oracle_gameplay_links.py) заново
воспроизводит оба полных MATCH_LAUNCH и GAMEPLAY_ENTRY до физики, сверяя их
закреплённые raw SHA/размер/JSON. На том же CPU/стеке, без сброса состояния и
новых игровых стимулов, выполняются caller41eed1/41eed3 и вся417f80 до41eed8.
Оба source запуска завершились:по3 helpers,2 depth checkpoints,100 уникальных
инструкций и0 catalog reads-before-writes. Здесь нет удерживаемых предметов;
сложные ветви проверены отдельно на объявленных3018 сценариях.

Native compare получает собственный World после control/physics. Полностью
сравниваются pool/globals/маски, CRT/ранние ресурсы,101 BG,854 bitmap, музыка и
весь replay630e18, плюс оба Actor после обновления integer z. Родительские
записи и ресурсы не становятся expected-state входами. Первый вызов сохраняет
послефизическое состояние Naruto/Sasuke целиком:frame219,HP500/MP200,RNG39/0,
phase1/tick1, музыка boss2.wma. EndSP1000e9bc, тот же ещё не вернувшийся4246b0.

Оба own сравнения прошли за36.621с, release build102.31с. Вместе с сохранёнными
launch/control/physics секциями:61898 записей /569493556 байт с масками,
912 helpers и62 checkpoints. Собственно новый участок добавляет6 helper
returns и4 Actor depth checkpoints; весь родитель не считается новым запуском.
Отчёты [a5](../evidence/gameplay-links.json) и
[ramp/reverse addresses](../evidence/gameplay-links-control.json).

После публикации новые packed corpora, прежние Actor/World physics,
GAMEPLAY_CONTROL/GAMEPLAY_PHYSICS/MATCH_LAUNCH и оба rollback checks прошли
вместе:14 release XCTest/178.394с, build103.59с. Сборка также скомпилировала

завершены.117 прежних fixtures сохранили SHA; три новых проверены по raw/packed
