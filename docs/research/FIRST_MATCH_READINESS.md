## Why active48 does not yet test damage

The current application composes all19 stages, but a stage being called does not
mean its damaging branch ran. [Preparation](MATCH_PREPARATION.md) sets Actor+8
to75; [scheduler](../../native/Sources/NTSDCore/OriginalActorScheduler.swift:79)
moves it toward zero after contacts/hits in the actual body order. The retained
first+16 neutral calls leave58. A new saved-data reader verifies both immutable
pristine active48 files and five available boundaries per call: before, contacts,
hits, lifecycle and whole return. At each of the96 contact endpoints both live
Actors have positive Actor+8 and zero contacts. HP is500 throughout those selected
boundaries. Each lifecycle reduces protection by one, leaving10 at both final
returns. The exact per-call values, frames and hashes are retained in the evidence.

Positive protection is a sufficient rejection for ordinary kind0 under the
recovered collection rules. Earlier effect/category gates can also reject an
ITR; this finding does not claim every pair reaches the protection test. It
explains why these schedules cannot establish an ordinary damaging hit. No
missing snapshot was reconstructed from a later return.

The current independent application projection explicitly requires every broad
pair's ITR to reject before narrow geometry and each hit count to equal zero
([projection](../../native/Tests/NTSDCoreTests/OriginalApplicationActiveContactsProjection.swift:145),
[hit gate](../../native/Tests/NTSDCoreTests/OriginalApplicationActiveContactsProjection.swift:181)).
Its negative tests reject a real contact rather than treating it as a no-op.
Those are comparison-domain boundaries, not gameplay restrictions in Core.

## First permissible next task and its stopping condition

**Prioritize a bounded first-damage diagnostic from current application state.**
Task → expose the first actually reached unprotected combat dependency → enable
an accepted damaging whole call, then a full match in the native application.
The active48 protection finding makes this a specific obstacle; another longer
comparison inside the same protected interval would not remove it.

Before execution, freeze a Native-only plan and actual code/resources. Reuse the
existing own first+16 neutral application producer, then retain one Bootstrap,
current catalog/Frame allocations, installed library, replay, graphics and sound
owners. Define at most two input scenarios (ordinary attack by each human slot),
at most160 additional whole calls per scenario, including waiting for protection
through ordinary neutral input and approaching through acquired directions.
Any positional threshold or input feedback is a declared test-controller choice,
not a recovered game rule. Read actual state to generate input; never assign the
state to make the scenario work. Resolve virtual keys from the current bindings
and preserve keydown/keyup, phase and replay sampling.

Protection reaching zero is an intermediate marker: the next contact pass reads
the updated value. Retain the actual current contact predicates (kind/effect,
category, teams, geometry and protection) as well as endpoint state.
Observe input, contacts, hit-stage HP changes, remaining19-stage flow, queued
effects and the enclosing return. The diagnostic ends at its first complete
returned call with actual hit-stage damage, first precise unsupported dependency,
or the declared call limit. A thrown or partial call is not successful damage.
Preserve the attempted input and first failing stage; check whole-call rollback
and the already committed acquisition. It must not relax the existing projection
or run new inputs through a comparator whose domain rejects them.

A successful Native trajectory is **a prediction and implementation diagnostic**,
not new original equivalence. Its concrete reached branches determine the next
independent comparison, using retained controlled contracts where applicable and
explicitly declaring any missing same-input source evidence. No expected after-state,
old Practice spawn or research ABI may initialize the owned application. Do not
execute a new source experiment without a separate need/contract/plan; a refused
path stays open. Do not publish diagnostic output as an accepted source fixture.

The independent app branch is a production session/input/commit adapter for the
live window. Its first implementation must pin actual startup/allocation/file/
platform inputs and preserve the same outer ticket through retries; commands
become deliverable once after finishLoadedMenu, never from PendingReturn before
that enclosing commit. This can proceed when its dependencies are ready; real
raster/audio and Windows observations must remain separate acceptance gates.
A first hit alone does not complete a round, match, native integration or the game.
