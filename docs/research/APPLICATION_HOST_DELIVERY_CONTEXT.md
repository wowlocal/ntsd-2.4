## Contract and implementation

`OriginalApplicationHostSession.Batch.context` retains the computed Application
value of that commit and a private independent Platform copy. Application owns
the actual startup state, five startup WAV results, music allocations, current
Session and loaded child/resource chain. The public platform inspection method
creates another staged copy; it never exposes the retained mutable object or
consults the latest Host state. Application inspection keeps existing value
semantics. Shared immutable inputs remain permitted by the existing platform
contract; mutable queues, allocators and reservations must be independent.

Startup, ordinary iteration and the final loaded tail construct this context
before publishing state, platform, sequence or batch. A throwing or same-object
copy therefore leaves the previous committed owner and queue intact. Startup
reports its additional late preparation failure through `failedAttempt` exactly
once; Bootstrap's existing failure callback path is preserved. A loaded-tail
failure keeps the actual pending/prepared child and platform for the existing
tail-only retry. Copy preparation stays inside the Host transaction lock.

The authoritative ordered `Batch.contents` streams and their overlapping graphics
metadata are unchanged. Nothing is flattened, reordered, duplicated or sent to a
device here. A retained context is neither a device lease nor a delivery receipt.
Failed releases, original numeric replies, source masks and unknown bytes keep
their established meaning. Future prepared observations, reservations/cancellation
and post-commit delivery failures still need their own contract.

Only three Native paths change: the Host class, the WinMain test Adapter's two-line
copy-failure switch, and the new delivery-context test file. All old test methods,
fixtures, runtime inputs, package manifest, game handlers and operation producers
remain unchanged. The [reviewable patch](../evidence/application-host-delivery-context.patch)
is relative to the pinned base candidate, not root Native.

## Comparison design and evidence boundaries

Six new methods are selected before the unchanged76 prior methods:

1. Leave startup and key-down/key-up iterations queued, then compare their FIFO
   order, complete state, startup PCM/music, exact effects and independent platform
   sentinels against the existing direct Bootstrap/source adapter and key caller.
2. Fail startup's publication copy by throwing and returning the same object;
   require one callback, no publication, unchanged owners and a successful retry.
3. Fail an ordinary key iteration both ways; retain startup/key batches and
   committed state/platform, then retry the same key packet without skipping a
   reply or advancing the publication sequence.
4. On both existing allocation backings, retain the fresh loaded return and three
   cached cycles, including an interleaved key and the known bitmap release.
   Compare complete ordered child operations plus the explicit outer time tail,
   state/masks, match/resource owners,400 registered WAVs,18 common WAVs and five
   startup WAVs. The earlier allocation must remain live in the earlier context.
5. Fail the final loaded publication copy both ways on both backings; retain the
   same pending/prepared tickets, platform and earlier queued iteration, then
   finish the same prepared child once.
6. Mutate independently returned Application/platform copies and release the Host;
   retained startup and actual loaded contexts must remain usable and unchanged.

The delayed loaded comparisons reuse the existing `checkFinished`, which computes
the final counter and entire outer tail from the actual source-compared child.
