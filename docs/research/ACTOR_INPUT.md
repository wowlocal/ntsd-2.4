# R02.1 / R04 — общий ввод Actor и переходы из DAT

Эталон — оригинальный NTSD 2.4 EXE, SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.

Этот компонент переносит `413080..4132ef` и настоящие дочерние helpers:
буферы и историю ввода, девять распознавателей комбо, переходы `hit_*`,
проверку и списание стоимости. Продолжение управления `4132ef..4143cb`,
окружающий проход по400 слотам и весь игровой такт сюда не входят.
Исходный EXE выполняется только в исследовательском Python-стенде.

## Общая нативная реализация

[OriginalActorInput](../../native/Sources/NTSDCore/OriginalActorInput.swift)
работает с полным `OriginalStateRecord` и `OriginalLoadedObject.frameStorage`.
Она сохраняет нетронутые байты и признаки инициализации, использует исходные
32-битные поля и знаковые байты. Внешний вызов атомарен при неподдерживаемом
обращении к кадру: изменения уже обработанных буферов и истории откатываются.

Имени персонажа, списка разрешённых техник или специального обработчика Sasuke
в компоненте нет. Общая функция читает переходы и стоимость из текущего Object.
Это основа для полного игрового пути; прежний ограниченный `OriginalFighter`
пока сохраняет свои старые проверки и не заменён этим компонентом.
Распознавание и оплата приёма не означает, что весь последующий приём перенесён.

## Правила оригинала

| Участок | Правило |
| --- | --- |
| `413080..413119` | В порядке `c2,c3,c4,c5,bf,be,c0,c1` уменьшаются только положительные Int8. Нулевые и отрицательные значения сохраняются. |
| `413119..413208` | Фронт требует ровно previous=0/current=1. Порядок: вправо, влево, вверх, вниз, защита, прыжок, атака. Буфер становится5. |
| `40e450..40e48a` | Каждый фронт сдвигает пять Int32 в `Actor+408..418`; добавляемые коды соответственно6,4,8,2,9,0,5. Несколько фронтов одного такта записываются последовательно. |
| `412800..413077` | Девять независимых прогрессов в `d4..dc`: D→R/L/U/D→A, D→R/L/U/D→J, D→J→A. Стадии могут пройти несколько переходов за один вызов. |
| `40e170..40e2c8` | Фронт5 сбрасывает незавершённый маршрут. Если маршрут продвинулся в этом вызове, разрешён фронт только что принятой кнопки. Флаги, отличные от0/1, возвращают false. |
| `40e2d0..40e445` | Общий переход в кадр, проверка его присутствия и стоимости. |
| `41324c..4132ef` | `hit_a`, затем `hit_d`, затем `hit_j`; буфер должен быть строго больше обоих конкурентов при знаковом сравнении. Равенство не выбирает переход. |

Распознаватели выполняются в исходном порядке. Следующий видит текущий кадр
и буферы после действий предыдущего. `Actor+98==2` запрещает combo transfer.
Для направленных R/L-комбо facing записывается после попытки, даже когда
целевой кадр отсутствует или стоимость не оплачена; прогресс тоже сбрасывается.

Стоимость `Frame+4c` делится со знаком к нулю: HP cost=`(mp/1000)*10`,
chakra cost=`mp%1000`. При включённом `44d034` нужны `MP>=chakraCost` и
`HP>healthCost`. Изменяются HP, MP, статистика `Actor+34c/+350` и кадр;
семь буферов очищаются. Счётчики сохраняют переполнение32бит. Отрицательные
стоимости не исправляются на ноль. При выключенном флаге стоимость не читается.

Отрицательный target сначала меняет знак;999 после этого означает кадр0.
Разворот `facing=1-facing` происходит только в успешной ветви с включённым
учётом ресурсов. При выключенном `44d034` отрицательный переход не разворачивает.
После попытки через `hit_a/d/j` выбранный буфер очищается и при неудаче.
Положительность буфера здесь не требуется:0 может победить два отрицательных.

Единственное исключение по source ID в этих helpers подтверждено
`412fdd..41300f`: при ID6, `hit_ja==300`, HP>177 и `458428==0` последний
распознаватель сохраняет стадию3 без перехода и сброса. Его общая ветвь также
требует `Actor+324==-1`; при невозможном переходе и `Actor+328==1` обнуляет
`Actor+338`, сохраняя прогресс. Назначение этих полей за пределами данных
читателей остаётся предметом исследования.

## Воспроизводимая проверка

[oracle_actor_input.py](../../tools/oracle_actor_input.py) выполняет реальные
инструкции EXE на объявленных синтетических Actor/Frame/global-входах.
Это отдельные проверки механизма, а не захват исходных DAT или полного матча.
Конструктор Actor выполняется в EXE; его memset — прежняя явная граница.
Игровые helpers не заменяются заглушками. Проверяются возвраты целых helpers,
callee-saved registers, ret cleanup, границы Actor, отсутствие записей в Object
и globals и чтения неинициализированных Actor bytes. У interior actions probe
явно заданы ESI/EBP и глубина стека; он не объявляется целым вызовом413080.

14 624 случая:

| Проверки | Количество |
| --- | ---: |
| Знаковое затухание, точные фронты и история |112|
| Все128 масок фронтов, семь ключей/неизвестные ключи и флаги инвалидатора |4608|
| Отрицательные/999 переходы, absent frame, стоимость и границы HP/MP |384|
| Девять маршрутов, все128 масок, стадии0/1/2/3/4/255, ограничения и исключение ID6 |7484|
| Приоритеты трёх DAT-действий, отрицательные буферы и равенства |500|
| Непрерывный префикс413080..4132ef со всеми128 наборами held input |1536|

Чередуются backing a5 и ramp, а также адрес Actor. Каждый случай сравнивает
все1056 байт Actor и1056 элементов маски, включая нетронутые поля:
всего30 885 888 байт/масок. Дополнительно проверяется откат при неподдерживаемом
переходе. Корпус не доказывает значения всех возможных Int32/Int8 и произвольные
невалидные указатели; обращения вне400 Frame нативная сторона отклоняет.

```sh
uv run tools/oracle_actor_input.py             # новый исходный захват в build/
uv run tools/oracle_actor_input.py --accept    # новый захват, Swift, затем fixture
swift test --package-path native -c release --filter OriginalActorInputTests
```

`--accept` публикует fixture и [отчёт](../evidence/actor-input.json) только после
успешного сравнения нового исходного корпуса с нативным кодом. Ожидаемое
состояние используется исключительно для сравнения; Native самостоятельно
строит конструктор, применяет объявленные входы и исполняет общий механизм.

Первое нативное сравнение прошло5.493с после release build94.47с; первоначальная
сборка до этого остановилась на расстановке Swift `try` у short-circuit operators.
Ожидаемые игровые состояния не менялись. Повторный свежий исходный захват дал
тот же SHA/66 104 342байта; acceptance прошёл5.470с/build33.93с после уточнения
порядка чтения HP за проверкой MP. Сохранённый packed corpus и rollback test
прошли5.336с; приложение NTSDNative собрано за34.14с. Все106 прежних fixtures
неизменны, полный unpack/SHA/JSON нового fixture проверен отдельно.

## Следующее продолжение

[oracle_gameplay_entry.py](../../tools/oracle_gameplay_entry.py) отдельно
продолжает собственный [MATCH_LAUNCH](MATCH_LAUNCH.md) на том же CPU/стеке,
World/400 Actor, каталоге, ресурсах, музыке и буфере записи. Перед продолжением
заново исполняется и сверяется весь закреплённый родитель. После Start нет
новых игровых стимулов. Целевые границы: весь контрольный caller
`41e339..41e634`, затем физический caller до`41eed1` перед Z/contact passes.
Оба свежих исходных прохода завершились: по20 возвратов helpers управления,
двум возвратам физики и12 промежуточным снимкам Actor. Stack остаётся
`1000e9bc`, World — прежний. Вызовы413080 получают собственные phase1/mode0.
Нативное сравнение этой цепочки остаётся открытым и не входит в14 624 probes.

Без новых нажатий первый контрольный проход не изменяет состояние. Физика
сохраняет происхождение скоростей конструктора0.1: x/z становятся
442.1/504.1 и289.1/519.1; целые координаты остаются прежними, y и скорости
становятся0, оба кадра —219. Это реальное начальное приземление, которого нет
при искусственном обнулении скоростей Practice. HP500/MP200 сохраняются.
Остановка —`41eed1`, до начального Z-pass, контактов, рисунка и планировщика;
внешний игровой вызов ещё не вернулся. Отчёты исходных проходов:
[a5](../evidence/gameplay-entry.json), [control](../evidence/gameplay-entry-control.json).

Для полного управления дальше нужны `4132ef..4143cb`: состояния19/301,
обычная и weapon2 ходьба/бег, воздушные атаки, прыжки/рывки/перекаты,
назначение скорости из DAT; затем caller400/401/500/501, физика и остальной
порядок такта. Старую выборку Practice с подставленными RNG/позицией/нулевыми
скоростями использовать вместо собственного состояния запрещено.
Полный матч, приложение, Windows-сравнение и чистая macOS остаются открытыми.
