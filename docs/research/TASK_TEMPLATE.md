## Спецификация

Порядок операций, размеры/знаковость, округление, переполнения, значения
конструктора, побочные эффекты, RNG, звуковые/графические события, условия отказа.
Имена персонажей использовать в примерах; общую семантику формулировать через
исходные данные и состояния. Если EXE сам проверяет конкретный ID — сохранить это.

## Исполняемый эталон

Команда; исходные DAT/повтор/входы и хеши; начальное состояние; выполняемые VA;
все заглушки и их договор; сравниваемые/исключённые поля; место снимка в такте.
Если исходный код ещё не выполнен, не заполнять результат как успешный.

Среда и версии; FPU/ABI; источник значений стековых/глобальных полей;
синтетические mappings/API-ответы и отличие от реальной Windows. Для каждого
низкоуровневого действия назвать игровую цель, реальные операции и причину их
необходимости, сравнение и терминальную границу. При чтении готового захвата
указать, что нового исполнения оригинала нет.

**Job:** команда, PID и время старта, cwd, input pins, output path, состояние,
терминальный exit/time. До действий с процессом перепроверить идентичность.
**Результат источника:** returned / source fault / declared boundary / harness
error / не выполнен. Exit 0 и отсутствие нового текста не заменяют результат.
**Публикация и аудит:** все части готовы; SHA/маски/события/зависимости проверены;
неизвестные значения не заполнены из Native или expected.

## Нативный перенос

Файлы/обработчики; как новый механизм используется другими объектами из DAT;
какие ограничения прототипа сняты; что остаётся неподдержанным и как диагностируется.

Собственные владельцы и aliases; сохранённое состояние между вызовами; потребитель
эффекта в вызывающем коде; порядок RNG/численных stores; граница staging/rollback.
Кандидат не меняет исходные expected. Если нужен новый контракт/компаратор,
сохранить прежний отказ и отдельно проверить изменение основания приёмки.

## Независимая проверка

Reviewer проверяет исходные доказательства, достижимость, пропущенные случаи,
маски/исключения, Native-код и фактическое участие кандидата в тесте. Записать
замечания, их разрешение и идентичность проверенных файлов. Самопроверка автора
не является независимым review. Структурное сходство и LLM PASS не доказывают
совпадение поведения. По возможности часть случаев оставить для независимой
приёмки без выдачи ожидаемого after-state исполнителю; старые корпуса не менять.

## Границы и остановка

При исходной memory fault сохранить точные доступ/адрес/инструкцию/состояние и
не продолжать faulted VM. Native rejection/rollback учитывать отдельно от match.
Отсутствие provenance, ошибка стенда, лимит хранилища и несовпадение имеют
собственные записи и дальнейшие зависимости.

**Область блокировки:** конкретное действие / приёмка карточки / вся цель;
зависимость и доказательство. Для всей цели обосновать отсутствие независимого
разрешённого продолжения по WORKFLOW; остановка одного запуска этого не доказывает.
**Ожидается от пользователя, если необходимо:** точные данные/решение/проверка
и почему их нет в задании; следующая независимая задача на время ожидания.

При safety refusal сохранить точную ошибку, время/зону, session/turn/request ID,
модель, операцию и лог; неизвестный триггер оставить неизвестным. Прекратить
автоматические повторы затронутого действия, включая смену модели/сессии/команды
для обхода. Проверить реальные процессы. Продолжать независимую разрешённую
работу, не считать её разрешением заблокированного пути. Действовать по WORKFLOW.
