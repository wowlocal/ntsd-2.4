## Behavior, reference and environment

`OriginalApplicationCatalogSession` continues the actual owned `PendingCatalog`
from bootstrap, menu and common loading. One synchronous call invokes the shared
registry, DAT/Object/bitmap/file/WAV and animated loading handlers. It retains
five startup and eighteen common WAV owners, menu state, graphics resources,
logical allocation identities and tentative effects. It creates `PendingPool`
only after a real full Native catalog return; the enclosing timer iteration still
requires its pool/UI/loading/outer-loop continuation before delivery to a backend.
There is no twenty-object limit or captured after-state in the runtime API.

The reference is the pinned original NTSD EXE
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`, lib.dll and
VC80 in the previously declared controlled Unicorn environment. This study reads
three saved twenty-Object checkpoints, original resource bytes and saved traces
as data. No original game code, emulator, historical producer or auditor was
executed. Logical pointers, clocks and API responses are controlled test inputs;
they do not establish real Windows heap, COM or device behavior.

The source files are candidate4-guarded (parent 0), candidate2-nominal (parent 1)
and candidate3-nominal (parent 2), each `.object-000020.json` under
`build/research/`. Their exact 437,967,602 bytes, eighteen record-table parts and
six global-store parts are carried losslessly by four test-only fixtures.
The index and packets verify raw bytes, JSON, SHA-256 and original part paths.
No reference execution is required to use the bundled tests.

## Contract and comparison

Each of three Native runs starts from its own application bootstrap/menu/common
result. Original files, image origins and declared platform controls are inputs;
expected records, masks, bitmap response writes and graphics relations are
comparison-only data. Allocation counts come from the shared Native loaders,
not the captured allocation journal. The reference helper resolves 105 file
inputs and 139 catalog images; old startup inputs remain separate.

At every one of sixty child boundaries the comparator checks full Object records,
frames, bitmap storage and masks, owned file state and events, WAV results and
PCM ownership, globals, allocations, ordered platform effects and graphics.
Each parent reaches 20 child returns, 194 bitmap constructors, 4,995 malloc
observations, 94 registered WAV returns and 51,510 saved events. These are three
repeated parent chains, not sixty unique assets or three complete catalogs.

All source-observed global masks compare against a separately reconstructed
union of CPU stores and the Native journal of actual semantic writes. The six
saved store parts contain 29,094 rows. Native knowledge remains distinct from
source observation: the harness resets its catalog observation mask at entry,
while the Native state retains known bytes from its own preceding calls. No
unknown source backing is imported to make those masks agree. The final source
mask has 2,003 known bytes per parent. Native does not claim source instruction
widths, store counts, private stack layout or CPU ABI.

At PC 41269a the twentieth child has returned before its parent slot/count store.
The comparison requires exactly four parent regions and 188 known bytes: count
19, nineteen initialized slots and an unknown twentieth slot with A5 backing.
This caller phase is preserved. The declared 81,273,768-byte catalog allocation
at logical token 70000020 cannot overlap retained PCM; a separate test rejects
the legacy 60000020 overlap with full rollback.

The graphics checker derives new image/surface/DC owners, generations, selections,
deletions, releases, command associations and source RGB/masks from saved events
and the separately pinned image golden data. Its plain row-copy comparison covers
the declared 1:1 SRCCOPY operations. Every appended command is compared, including
bindings, resource references, dependencies, rectangles, colors and sequence.
This is a source-color/command contract, not a measured Windows raster result.

Eighty close events per parent omit their result. Read-only AST inspection of the
saved harness inheritance chain proves the default `ret(value=0)` used for these
controls; the missing expected field stays missing. Each ignored volume result
of -1 is retained in the observed operation stream. Sound path writes include

All 582 bitmap API response writes per parent remain expected-only; the Native
bitmap input owner computes them from original image metadata.
