# R02.1 / R04 / R16 — горячие клавиши и обмен командами

Эталон EXE SHA-256:
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.
Участок `41c5e5..41d46f`, настоящие helpers `416c70..416fad`, затем уже
перенесённые `4198f0/4197a0` через caller до `41d4b7` либо `41d5db`.
**Статус: объявленный участок перенесён; два свежих исходных корпуса совпали
с нативной реализацией. R02.1 и полный игровой такт остаются открытыми.**

## Состояние и границы

[oracle_input_control.py](../../tools/oracle_input_control.py) заново исполняет
всю [первую загрузку](INITIAL_LOADING.md). Три полных raw transport сравниваются
побайтно с прежними закреплёнными захватами. После этого на том же CPU/стеке
выполняется естественный [локальный ввод](LOCAL_INPUT.md), его первый случай
и все используемые blobs также должны совпасть с прежним корпусом.

Первый новый случай продолжает `41c5e5` без замены World, Actor, каталога,
регистров или буферов команд. В основном проходе фаза равна 1, пауза — 0;
в контрольном фаза 0, пауза 1. Таким образом, контроль теперь проходит ранее
пропущенные четыре сетевых вызова даже без включённой сети. Остальные случаи
задают явные входы на сохраняющемся загруженном мире, включая клавиши,
сетевые ответы, статусы, ссылки Actor, HP и параметры повтора.

Нативный [InputControlReference](../../native/Sources/NTSDReferenceChecks/InputControlReference.swift)
получает собственный загруженный мир через `LocalInputReference.onNatural`.
Он не подставляет ожидаемое после-состояние в движок. После нового callback
продолжается сравнение всего прежнего local-input corpus. Все четыре родителя
каждого прохода закрепляются SHA, их fixtures не изменяются.

Winsock, COM, MessageBox, free и PostMessage — явные границы платформы.
Возвращаемые значения и полученные байты заданы во входах случая. Унаследованная
граница `memset` выполняет также вызов `431d04` с аргументами
`455378, 75, 300`; тело `431c70` действительно исполняется. Два буфера по
`630e18` байт и сохранённая область `458588..4588a7` предоставлены явно.
Это не доказательство их происхождения из playback startup или файлового IO.
Для включённых звуковых проб `455618/45561c` явно связываются с двумя уже
загруженными registry buffers. Настоящее назначение этих слотов при startup
здесь не выполняется; звук сравнивается до COM-вызовов, без аудиовыхода.

## Правила оригинала

При `450b90 != 0` происходит переход к `41d469`. При фазе 0 сначала идут
два `WSAAsyncSelect` с нулевыми message/events, затем два `ioctlsocket` с
`FIONBIO`. Первый получает NULL argp; второй — адрес обнулённого stack word.
Возвращаемые ошибки не прерывают путь. Записанный ОС scratch word дальше
на этом участке не читается.

Байт `44f1af` выбирает ветвь: 0 — локальные команды; ровно 1/2 — два порядка
сетевого обмена; остальные значения пропускают обе ветви. Это отличается
от signed `> 0` в упаковке обычного [локального ввода](LOCAL_INPUT.md).
Клавиша нажата только при значении 100; потребление записывает 117.

| Helper | Общий эффект |
| --- | --- |
| `416c70`, `416ca0` | OR битов 1/2 в command[9], `458428/45842c = 1 - old`, запрос звука через `455618/45561c` |
| `416cd0` | При menu 0 сброс очередей паузы и переход к завершению/меню; отдельный выход из повтора |
| `416dd0` | При menu 0 обе очереди паузы получают `1 - 450bfc` |
| `416df0` | При menu 0 очередь шага получает 1, очередь паузы — 0 |
| `416e10` | При menu 0 command[8] OR 4 и `450c28 = 2` |
| `416e30` | При menu 0 переключение `44d02c`, клавиша `4553ec = 117` |
| `416e60`, `416eb0`, `416f10`, `416f60` | Общие команды с битами 10/20/40/80, исходными условиями mode/menu/450c28, счётчиками и запросами ресурсов |

Последние четыре требуют signed `450c28 < 2`, menu 0 и либо mode 0,
либо `45842c == 1`. Последние три ставят свой бит **до** проверки таймера
`450bdc == 0`. Сложение счётчиков и вычитание флагов сохраняют 32-битное
переполнение. Последующие игровые последствия этих запросов ещё не перенесены.

При локальном управлении сначала обрабатываются два переключателя, затем выход,
пауза, шаг, команды и оставшиеся клавиши. Часть проверок использует сохранённый
menu в ESI. Во время повтора команда `4553eb` вызывает `416cd0`, затем `431c70`, даже если
helper отказался из-за menu != 0. Поэтому последующие клавиатурные команды
могут исчезнуть при сбросе, тогда как биты уже прочитанного пакета повтора
продолжают обрабатываться. `431c70` обходит восемь ссылок из таблицы World,
а не первые восемь аллокаций Actor; повторные ссылки сохраняют исходный порядок.

## Сеть и ошибки

Обе сетевые ветви упаковывают те же клавиши в outgoing bytes 10/12.
За исключением двух переключателей, клавиши требуют menu 0.
Контрольная сумма состояния — сумма signed HP `Actor+2fc` первых 20 мест,
причём activity должна быть **ровно 1**. Сложение 32-битное; результат
`sum % 100 + 1`. Последовательность — `(450bf0 + 1) % 50` с переполнением
до знакового деления. Каталожная сумма `44f620` не является состоянием RNG.

Пакет имеет 22 байта: [9] — последовательность, [11] — младший байт `44d03c`,
[13] — сумма HP, [14/15] — исходные остатки/частное суммы каталога по 256.
Обычный caller копирует только 21 байт шаблона, поэтому последний байт пакета
не следует автоматически обнулять.

При network 1 оригинал сначала вызывает send, затем receive; при network 2 —
наоборот. Результат send игнорируется. Положительные фрагменты receive
накапливаются до 22 байт; ноль/ошибка завершает цикл. Суммарное количество
проверяется как unsigned, последний результат — как signed. Неполученные
байты входного пакета остаются прежними и тоже участвуют в последующих проверках.

Первые три поля сравниваются после знакового расширения входного байта.
Сумма каталога сравнивается по байтам. Каждое несовпадение вызывает сообщение,
общие `4019b0/401d30/43d2a0` и PostMessage(close), **после чего путь продолжается**.
Возможны несколько сообщений и запросов закрытия за один вызов. Первый shutdown
освобождает звук, музыку и оба буфера, очищая указатели устройств/буферов;
звуковые массивы и их счётчики остаются прежними. Повторный shutdown видит
уже очищенные указатели. Это общий механизм из
[MENU_PRESENTATION.md](MENU_PRESENTATION.md).

После проверок OR входного и выходного пакетов запускает helpers в порядке:
пауза, шаг, выход, отображение, command[8] bit4, два переключателя, затем четыре
дополнительные команды. Порядок отличается от локального и влияет на результат.

## Восстановление после повтора

Ветка `416cd0` при `450b88 != 0` устанавливает mode 6. Если playback pointer
ненулевой, настоящий `43df00` восстанавливает signed byte `45877c` в dword
`450c30`, восемь имён с шагом 11 и три строки. Копируется строка через NUL;
шаг имени не является ограничением длины. Затем caller берёт сохранённые
`458428/45842c` из playback buffer `+630bb8/+630bbc`. Он очищает
`450b88/450b84/450bdc` и ставит menu 10.

Нативный `OriginalInputControlContext` владеет сохранённой областью и использует
тот же реестр буферов, что завершение меню. Поддержаны строки, заканчивающиеся
внутри предоставленных `320` байт. Чтение за этой областью, произвольное
перекрытие буферов, полное сохранение настроек при запуске повтора и файловый
жизненный цикл остаются открытыми.

## Проверка и продолжение

В каждом проходе предусмотрены 2 993 случая: первый естественный caller,
2 048 сочетаний клавиш, 128 сочетаний семи команд повтора, 408 сетевых сочетаний
источников/битов, 20 вариантов receive, 12 повреждений заголовка, 32 числовых
сетевых контроля, 35 phase/network сочетаний, 246 граничных условий helpers,
12 выходов из повтора, 3 случая повторных Actor-ссылок при reset, 24 суммы HP
с различной activity/переполнением, 8 точных keyboard bytes, 12 переполнений
переключателей и 4 переполнения счётчиков.

Сравниваются все World/400 Actor bytes и маски, globals, сохранённая область,
указатели и **оба полных буфера**, включая освобождённые. Также проверяются
10 + 10 командных байт, восемь окружающих stack bytes, scratch word, порядок
платформенных событий и настоящие helper/received-input возвраты с аргументами,
ESP и сохранностью nonvolatile registers. Снимки не отбрасывают padding.

Стенд явно останавливается code hook на каждой конечной инструкции. Одного
`emu_start(..., until=...)` оказалось недостаточно при повторном использовании
переведённых блоков: следующий запуск мог пересечь границу, уже исполненную
предыдущим continuation. Hook останавливает CPU без изменения состояния игры.
Диагностическое восстановление старых снимков использовалось только для поиска
ошибки стенда; принимаемые корпуса должны заново исполнить всю загрузку.

Оба свежих захвата выполнили эти требования и прошли release-сравнение до
принятия новых fixtures:

этим запуском не проверены.

Профилирование debug XCTest выявило стоимость generic Array equality при
повторном сравнении полных буферов. Только новый reference checker ускорен:
сравнивает все байты представления, а для различающихся Bool-представлений
сохраняет семантическое сравнение масок. Это не выборка, не сравнение одних
хешей и не предположение об ABI Bool. Оба release-сравнения после изменения
снова прошли; хеши всех десяти новых и родительских fixtures не изменились.
