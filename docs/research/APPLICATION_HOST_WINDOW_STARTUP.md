## Analysis and implementation

Bootstrap now invokes an optional preparation callback on its existing independent
platform copy before any startup work. Default callers retain their original copy
count and operation order. Preparation failure goes through the existing attempted
platform failure hook and commits nothing. Host forwards that preparation and
invokes a final ownership validator after creating its independent delivery context,
immediately before nonthrowing state/sequence/batch publication. Failure at this
last boundary reports once and leaves the previous Host state intact.

`OriginalApplicationWindowStartup` retains one private Host, one private exchange,
initial record and instance/show arguments. A provider protocol exposes the value
cursor used by its existing window consumer; stagedCopy must copy that cursor and
all mutable nonwindow state independently. Each resume installs a new immutable
cursor only into the attempted provider. A missing reply unwinds the entire Host
attempt before the coordinator issues a request permit. The caller answers or
records an indeterminate outcome outside Core. Previously answered requests read
the same values on retry and are never issued as new device work.

The coordinator finishes receipt consumption inside Host's last validator, after
whole Bootstrap and the fallible publication-context copy. No throwing work remains
before Host publication. Private ownership plus serialized actions prevents another
answer or cancellation from racing this boundary; recursive actions reject. Late
copy failure therefore leaves the exchange open with all answers retained. Missing,
foreign, stale, suspended and unconsumed cursors reject before any batch escapes.
Successful completion returns that same Host to its ordinary menu/input consumers.

Cancellation preserves receipts and accepts one eventual answer/failure for an
already issued permit. Opaque resource retention does not invent device success,
undo actual IO or guarantee physical exactly-once recovery. Callbacks and stagedCopy
remain forbidden from host IO or shared queue/allocator mutation; nonwindow inputs
must stay fixed across retries. The test provider is not a production provider.

Changes are limited to Bootstrap, Host, the new coordinator, one new test file and
the existing test Adapter's failure-selector declaration. Its selector is now a
value copied into each attempted provider, so tests can inject a late failure and
retry from the unchanged retained provider. All old test method bodies, comparators,
fixtures, resources and recovered window/WinMain algorithms remain unchanged.
