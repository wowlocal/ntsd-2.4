## Actual ownership chain

Host LoadingContext carries the current Bootstrap PendingLoading, startup and
optional current loaded cycle. LoadedCycleSession starts from this pending
state and the retained loaded match, music and resources. Its bindings still
refer to the historical pool entry. After one acquisition/local/replay/round
sequence, Input.PendingContinuation carries both identities: `loading` is the
current suspension, while `entry` is the historical Pool.PendingInput owner.
It also retains state, match, inputContext, music, commands, playback commands,
paused flag, round outcome, operation journal, graphics and menu resources and
backgrounds. The current loading's staged effects/graphics form the prefix.
Using the historical pool ticket as current identity would reject valid later
cycles or admit the wrong owner.

PendingLoading's actual candidate contract includes owner ID, revision and a
private attempt UUID; `isSameAttempt` compares all three. This UUID is host
identity, not game RNG, time or a source resource ID. MenuSession's constructor
accepts a menu continuation. GameplaySession's constructor accepts gameplay or
pausedRendering, validates aliases and requires installed library commands.
The latter adopts the actual Ready through Menu.Attempt and does not reacquire
input or rerun the round decision. Normal gameplay calls OriginalGameplayBody;
paused rendering calls OriginalPausedGameplay without normal simulation/camera
bounds. Installed text/DC, hits, transforms, live surfaces/bitmaps/WAVs, music,
replay, masks and caller-owned unknown storage retain their existing contracts.
Menu local 0x704, result-format storage and opaque 372-byte storage are distinct;
none becomes known zero or a private source ABI.

GameplaySession produces Menu.PendingReturn with the same Ready, its owned
snapshot, returned exit, actual dispatcher result and graphics. Its local
commit is not the host publication. Bootstrap's finishLoadedMenu validates
owner/revision, returned result and aliases, resumes the current outer loop's
time/Sleep tail, merges the counter aliases and installs state, loop and loaded
owners. The host must additionally keep exact-attempt validation. Its corrected
tail clones the prepared platform and assigns `self.platform` only at final
commit, publishing one complete loaded batch. The old compiler failure remains
preserved; this preflight does not alter that correction.

## Proposed host boundary — not implemented

Extend the common preparation result to distinguish returned menu, Start and
gameplay input Ready. A provider receives the current LoadingContext and an
independent staged platform, acquires input once and selects the resulting
branch. Illustrative API names are `prepareLoadedUntilBoundary`, a common
LoadedOutcome and `resumeGameplay`; final names belong to the candidate plan.
Preserve the existing return-only and Menu.Outcome APIs through deterministic
adapters. A gameplay-only preparation API that requires callers to predict the
branch before acquisition would not satisfy this contract.

The private prepared state gains mutually exclusive Ready/platform retention.
Validate Ready.loading against the current exact attempt and preserve the
existing alias, branch and installed-library checks before the final host
preparation observer. Do not invent new cold-loading or game restrictions.
Expose read-only inspection with independently copied platform storage; old
returned/Start accessors are nil at this new stage. Same-class stagedCopy
identity remains invalid under the existing host platform contract.

Resume uses only privately retained Ready and a fresh platform copy, without a
replacement Ready argument. Existing GameplaySession executes the selected body.
Before replacing Ready with returned-child/platform, validate current identity,
returned result and aliases and pass the final host observer. Successful body
retention publishes no batch. The existing final outer tail is the sole host
publication. The transitions and retries must preserve these boundaries:

| Failure boundary | Retained state after rejection | Retry starts at |
| --- | --- | --- |
| Input/provider/local/replay/round/preparation observer | Current loading and earlier committed acquisitions/batches | Input preparation |
| Gameplay/paused body, graphics/sound/dispatcher/child commit or host observer | Exact Ready and its prepared platform; committed host unchanged | Body, without reacquiring input |
| Outer time/Sleep/commit observer | Returned body and prepared platform; committed host unchanged | Outer tail, without rerunning input/body |

Wrong stage, over-preparation, absent, foreign, same-revision sibling, stale or
consumed tickets and callback reentry must reject before provider IO. Public
inspection cannot replace private children. Failures preserve complete earlier
batches and every retained state/resource owner, not just scalar counters.
