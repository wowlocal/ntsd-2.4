# R02.1 / R05 / R14 — полная физика Actor

Эталон: NTSD 2.4 EXE SHA-256
`3f7ac67c5890ef979ee24a6dae5528056e7f631725c292cf9cb0a928ebeff71c`.

[OriginalActorPhysics](../../native/Sources/NTSDCore/OriginalActorPhysics.swift)
переносит всю `40e490..40ef6a` на полных Actor/Frame/Object и globals.
Публичный вход использует собственный загруженный Object. Правила общие для
каталога; исключения по source ID сохранены только из инструкций EXE.
Окружающий проход, смерть и возрождение описаны в [WORLD_PHYSICS](WORLD_PHYSICS.md).

## Порядок и границы

| Участок EXE | Перенесённое поведение |
| --- | --- |
| `40e490..40e4f0` | Ненулевой freeze приближается к0 и завершает вызов; carried-kind<0 или текущий cpoint.kind2 также возвращают сразу |
| `40e4f0..40e5d0` | x/z, четыре флага блокировки, дополнительные смещения type4/ID120/101, type3 hit_j |
| `40e5d0..40e677` | Трение vx/vz при прежнем integer iy>=0 |
| `40e677..40e6c2` | type4/6 state1000 выбирает frame40 при скорости вне[-9,9] |
| `40e6c2..40e794` | y+=vy и гравитация с исходными константами/порядком округления |
| `40e794..40e8d1` | Воздушные кадры type0/state12/18, fallHurt и счётчик450bd0 |
| `40e8d1..40ec53` | Приземление бойца, урон от падения, отскок и landing frames |
| `40ec53..40ef22` | Приземление/отскок type1/2/4/6 и отдельная ветвь ID999 |
| `40ef22..40ef6a` | Три преобразования4450d0, очистка320 вне итогового state12 и возврат |
| `416fb0..417082`, `417090..417162` | Настоящие накопители громкости каталожных и встроенных звуков |

Ранний возврат оставляет остальные байты, включая320, прежними. Обычное x
блокируется только при соответствующем флаге ровно1: положительный vx/3f4,
отрицательный vx/3f0. У z аналогичны3ec/3e8. Дополнительные x+=vx*0.2 для
type4 или ID120 и x-=vx*0.2 для ID101 выполняются даже после блокировки;
type4/ID101 последовательно проходит обе дополнительные операции. Затем
обнуляются все четыре флага. Для type3 положительный hit_j добавляет к z
знаковое32-битное hit_j−50.

Трение использует старый integer iy. При v>0.0001 вычитается1; результат
ниже0.0001 становится+0. Затем отдельно при v<−0.0001 прибавляется1;
результат **выше положительного0.0001** становится+0. Сравнение после записи
использует ещё расширенный промежуточный результат. Нельзя заменять это
симметричной функцией приближения к нулю.

После y+=vy воздух выбирается при расширенном y<−0.0001. Type3 не получает
гравитацию. Type6 прибавляет1.1333333333333333, type4 —0.85. Для остальных
state1002 использует ID124:0.16999999999999998, ID120:0.425,
ID101:1.1333333333333333, иначе0.5666666666666667. Прочие состояния:1.7.
Это загруженные binary64-константы EXE, а не заново вычисленные дроби.

Type0/state12 с кадром<185 выбирает180/181/182/183 при итоговом
vy<−8 / <1 / <8 / иначе. Кадры186..<191 аналогично выбирают186..189;
185 исключён. Отрицательный320 в первой группе заменяет результат на182
только при **vy<12 и450bd0>=6**, иначе181. Состояние перечитывается после
изменения кадра: state18 при frame<205 и vy>1 выбирает205.

## Приземление

Проверка cpoint.kind2 повторяется после возможной смены кадра40. Для type0
state13 при y>epsilon и vy>epsilon скорость vy>17 либо vx вне[-9,9]
снимает10HP при340==0, иначе добавляет−1000/340; y=0, vy=−3.5,
vx зажимается в[-7,7], frame185, wait сохраняется. Медленный вариант
обнуляет y/vy и делит vx на3 без смены кадра. Последующие проверки продолжаются.

Обычное приземление требует сохранённые y>epsilon и vy>epsilon, кроме
state12/18. Отдельный путь frame212 требует **y>0 и vy==0**. Он обнуляет
y/vy/wait, делит vx на3 и выбирает94 для state100, иначе215 для frame212
или state6, иначе219. Исходный frame212 с y<=0 не считается приземлившимся.

Приземление state12/18 сначала накапливает builtin sound6 по **прежнему
integer x**. Ненулевой320 получает исходный abs с32-битным переполнением;
при положительном340 урон=(hurt*100 с переполнением)/340, иначе hurt.
Он вычитается из HP/redHP, затем320 очищается. При vy<=11, vx в[-9,9]
и state!=18: y/vy/wait=0, vx/3, frame230 либо231 для старого frame>=186.
Иначе y=0, vy=−3.5, vx в[-7,7], frame191 при frame>=186/state!=18,
иначе185; wait не очищается.

Объекты type1/4/6 требуют y>epsilon и vy>epsilon; type2 требует только y.
Durability31c уменьшается на Object94, а у type2 сначала на1. Type1/state1002
при vy>9.9: frame7, vy−8, facing=1−facing как байт, vx*0.5 и звук ObjectA8,
если index>-1. Иначе frame70 для1002 или60, vy/wait=0, vx*0.5.
Type2 при vy>9 сначала вызывает звук, затем vy−5/facing/vx*0.5, сохраняя
frame/wait. Иначе ещё снимает Object94 с зажимом durability>=0, ставит20,
vy/wait=0 и vx*0.5.

Type4/6 при vy>8.5 либо vx вне[-10,10] и state1000/1002 выбирает frame0,
vy=max(−10,vy*−0.7), vx*0.7, звук; wait сохраняется. Иначе frame70 для1002
или60, vy/wait=0, vx*0.7. У type6 HP<=0 принудительно ставит durability−1.
Среди остальных типов ID999 при y>−epsilon обнуляет y/vy/vx/wait и выбирает101,
не требуя положительной vy. В конце integer координаты обновляются,320
очищается только вне итогового state12.

## Числа и звук

[OriginalExtended](../../native/Sources/NTSDCore/OriginalExtended.swift) — конечная
двоичная арифметика, в этих исторических корпусах с64-битной мантиссой и nearest/ties-even, отдельным
округлением при каждой binary64-записи. Сложение, вычитание, умножение, деление
и сравнение реализованы целочисленными операциями Swift. Интерпретатора команд,
CPU/EXE или совместимого Windows runtime в приложении нет. Обычный Double
не сохраняет исходное промежуточное округление x87.

Объявленный CPU-контракт этих корпусов — CW037f. Новая
[коррекция точности](ARITHMETIC_PRECISION.md) отдельно добавляет24/53/64 бита
и повторяет оба корпуса физики при53 битах, сохраняя старые fixtures.
Nonfinite операнды и переполнение экспоненты80-битного формата вне этого конечного домена.
Доказательство реальной установки CW при Windows startup остаётся открытым.
4450d0 имеет два пути по глобальному флагу45971c, расположенному вне основного
снимка globals44d000..458440. Поэтому Actor API принимает явный sse2Conversion,
по умолчанию false. Legacy путь возвращает младшие32 бита усечённого Int64;
вне Int64 результат0. SSE2 путь усечённого Int32 возвращает Int32.min при
недопустимом преобразовании. Это граница CPU-контракта, не игровая настройка.

Общий sound helper теперь обслуживает две исходные таблицы. У catalog416fb0
флаг457588 и каналы457bc8/452170, у builtin417090 —453e10 и4527e8/4554c8.
Правило расстояния/накопления прежнее из ACTOR_CONTROL. Здесь проверены
очередь/полные globals и порядок событий, но не WAV output или слышимая задержка.
Actor/globals фиксируются после успешного вызова; внешний caller буферизует
события до принятия всей стадии/такта.

## Проверки

[Синтетический producer](../../tools/oracle_actor_physics.py) выполняет9344
целых вызова40e490 и реальные sound/ftol2 helpers. Покрыты типы0..6, знаковые
границы, блокировки, hitstop/cpoint, состояния/кадры/урон, оружие, оба
преобразования координат и3000 детерминированных varied finite numeric inputs.
Выполнено914 уникальных инструкций,804 sound requests. Durability31c=20
явно задаётся стендом: конструктор сам не доказывает инициализацию этого поля.

[Каталожный producer](../../tools/oracle_actor_physics_catalog.py) берёт
неизменённый закреплённый LOADED_CATALOG и проверяет SHA всех исходных DAT.
Для каждого из15363 присутствующих кадров всех137 Object выполняются три
объявленных состояния движения:46089 случаев,790 уникальных инструкций,
1707 sound requests. Actor/globals/caller синтетические; исходные Object
bytes/masks не меняются и не читаются до инициализации. Native заново строит
и сравнивает весь каталог, затем использует собственные загруженные Object.
Все кадры покрыты этими входами; непрерывные техники/полный матч этим не доказаны.

Оба корпуса сравнивают все1056 Actor bytes/masks, SHA всех46144 globals и
упорядоченные звуки. Первые успешные сравнения:9344 за3.766с, каталожные46089
за23.339с. Диагностика уточнила строгую границу vy<12 и положительный y для
frame212; ожидаемые захваты для исправления Native не менялись. Инструкции,
стек helper returns, CW и пустой FPU stack после вызова проверяет producer.
Отчёты: [synthetic](../evidence/actor-physics.json),
[исходные кадры](../evidence/actor-physics-catalog.json).

```sh
uv run tools/oracle_actor_physics.py
uv run tools/oracle_actor_physics_catalog.py

```

Последняя команда сравнивает все новые физические корпуса одним последовательным
SwiftPM-процессом и только после успеха публикует fixtures/evidence. Старые
fixtures сохраняют свой объём. Общая физика соединена с собственным матчем
в WORLD_PHYSICS; контакты, оставшийся такт, приложение, Windows и чистая macOS
остаются открытыми.
